# CLE 固定经验库 Q 值探索实验报告：从六批实验到逐题结论

整合后的项目总介绍见 [CLE 项目全景手册](CLE项目全景手册_零基础完整版_20261016.md)。本文保留为 Q 专题的详细实验记录。

日期：2026-10-16。适用范围：旧版 CLE（Contrastive Lifecycle Evolution，对比代码经历并审查、更新经验的方法）中的记忆 Q 值（经验卡被采用后，整份代码历史成绩的数值估计）迁移探索。

配套阅读：[从零理解 CLE 与 Q 值](CLE_Q值探索零基础全流程报告_20261016.md)。本报告用专业名称并在紧随的括号里解释概念，既保留研究记录，也解释这些数字为何重要。

**核心结论：Q 的学习、冻结和选卡链已经实际运行，并改变了部分选卡且被模型采用；现有实验没有给出能够归因于 Q 的最终正确率收益。** 最新共享首次初析实验的 Joint（同一份代码同时通过功能与安全测试）是 Q1=2/8、Q2=3/8、Q3=2/8。多通过的 1013 题没有使用任何经验卡，不能当作 Q 机制成功的实例。

本报告覆盖已经做过的 Q 探索，重点详解最新一批；它不是完整 CLE 训练后的 Base/Plus（独立最终评价数据集）性能报告。本次写作没有新增 API（程序请求外部服务的接口）调用，没有启动预留确认集、完整 CLE 训练或 Base/Plus。

### 与项目方法文档的关系

项目的 RQ（Research Question，研究问题编号）与本次证据对应如下：

| 原研究问题 | 要研究什么 | 本次 Q 实验支持到哪里 |
|---|---|---|
| RQ1 | 完整 CLE 是否提高联合通过率 | 只有固定经验库的开发对照，不能替代完整方法的独立评价 |
| RQ2 | 各组件分别贡献什么 | 本次主线：检验候选排序中历史 Q 的增量，并检查改选、采用和代码结果 |
| RQ3 | 候选门控与生命周期如何影响收益和退化 | 本次没有执行完整候选晋升、退役和历史回归实验 |
| RQ4 | 方法花费多少调用、Token、时间，带来多少收益 | 已保存逐臂用量与共享成本；尚无可归因收益，不能计算可信的“每多做对一题价格” |

门控（按条件决定是否让经验进入下一阶段）与数值排序不同。排序让某张卡更容易被选中，不等于该卡已经通过独立有效性审查。

## 2. 实验前有什么材料，怎样使用

M0（初始固定经验库）含 1939 张候选卡，来自 Phase 1（建立初始经验的阶段）。卡片正文、来源与生命周期状态在本次固定库学习和比较中保持不变。6 张超过现有文本预算的卡共同排除，向量缓存对应 1933 张合格卡；全库学习覆盖的分母仍是 1939。

D_init（初始来源任务池）303 题、D_grow（学习任务池）273 题、D_gate（开发审查任务池）298 题，合计 874 条 Python 任务。当前实验使用按原版本算法恢复的池文件 `pools.recovered.json`；这与“找回历史原始 pools 文件字节及全部原始运行参数”是不同事情，不能声称完全复现历史所有训练条件。

数据集固定并不意味着每道题的说明与执行环境都无误。本轮没有修改源数据或测试标准。发现缺陷时保留原记录，单列解释。

数据隔离（学习数据与评价数据保持用途和题族边界）按现有任务族清单执行。题族（同源或高度相关题目的分组）用于减少重复题造成的虚假独立样本；现有分组是依据材料推断，不等于原始数据生成关系已经全部查明。

## 3. 六批真实实验分别做了什么

P7（项目中一条分析、检索、生成和一次修复流程的实验编号）是本次复用的单题流程。c0（第一次生成的代码）与 c1（依据上一次反馈修复后的代码）是同题内的两次尝试，不是不同题。CWE（常见软件弱点分类）用来描述题目和卡片涉及的风险类别。

下表中的“记录”是任务×实验臂（同一道题在一种策略下的运行记录），不是独立题目数量。各批配置和题目不同，**不能把所有正确数、总题数简单合并成一个正确率**。

Q0（原模型选卡）、Q1（纯相似度）、Q2（真实 Q）、Q3（打乱 Q）是后续实验臂的名称。早期任务书还有 Q1–Q7 工作包编号（实现任务的编号），不要与实验臂混用。③ 的 Q3 是全库打乱；⑤⑥ 的 Q3 是同 CWE 内打乱，不能把它们当完全相同的对照。

### 这些批次不是一条单调上升的成绩曲线

从 1/8 到 3/8 不能直接说“共享初析使 Q 提升两题”，因为⑤与⑥使用了不同任务；从 4/24 到 3/8 也不能直接比较，因为库、门槛、样本和控制方式均有差异。

正确读法是：每批解决了哪个不确定因素，然后在**本批相同题目**的实验臂之间做配对比较（逐题比较同一个任务在不同处理下的结果）。

## 4. 全 D_grow 学习到底学到了什么

这是后两批 8 题实验共同使用的 Q 来源。

## 5. 零 API 回放：后期还在大幅改变选择吗

## 6. 最新 8 题三臂实验的完整规格

### 6.1 题目怎么选，为什么要预检

最新任务为：1341、1000、1013、1055、340、777、1001、1015，共 8 个题族，覆盖 CWE 74、79、862、915、327 五类弱点。

选择过程按原 CWE/题目 ID 轮转检查 25 个未评价且未预留的题族，依据公开契约（题目公开的函数接口、已有变量和行为要求）及参考实现可执行性筛选，不按本次 Q 排名或模型成绩选题。与学习题族、既往评价题族、预留 24 个确认题族均保持隔离。

这是为了便于判断机制而筛选的开发子集，不是对整个数据集具有代表性的随机抽样（让各对象按明确概率进入样本）。因此不能把这 8 题的通过率直接当作全数据集通过率。

参考实现（数据提供的正确解法示例）在 8 题上都通过 F/S。但运行后发现 1015 的题面变量与执行器提供变量不一致，说明本次预检（实验前检查输入是否可用）仍有漏项。本报告保留原 8 题主分母，没有事后替换题目。

## 7. 主结果：先看数字，再看数字从哪来

24 条任务×臂记录完整，产生 41 份代码尝试；全部代码语法有效，24 条最终结果均完成测量。流程中出现结构化输出错误，但不是没有运行测试。

| 实验臂 | F 功能通过 | S 安全通过 | Joint 联合通过 | c0 首次联合通过 | 含流程错误的任务记录 |
|---|---:|---:|---:|---:|---:|
| Q1 纯相似度 | 3/8，37.5% | 5/8，62.5% | 2/8，25.0% | 2/8 | 3/8 |
| Q2 真实 Q | 4/8，50.0% | 4/8，50.0% | 3/8，37.5% | 3/8 | 2/8 |
| Q3 同 CWE 打乱 Q | 3/8，37.5% | 4/8，50.0% | 2/8，25.0% | 2/8 | 3/8 |

Q2 比另两组各多通过 1 题，差 12.5 个百分点（两个百分比相减）。本批所有最终联合通过都发生在 c0；c1 没有把新的失败题救成 Joint。

精确 McNemar 检验（对同一题在两种方法下的成败差异进行检验）中，Q2 对 Q1、Q2 对 Q3 都是 1 个救回、0 个损失，双侧 p=1。Holm 校正（控制同时比较多个方法时的偶然报喜）后仍为 1；保守 95% 置信区间（反映样本对总体差异估计的不确定范围）约为 −42.02 到 +57.55 个百分点。

这些数字表示证据很弱，不能证明提升，也不能证明等效。更关键的是下面逐题证据：唯一救回不经过 Q 选卡路径。

### 8.1 为什么 1013 不能当作 Q 的成功案例

1013 的首次共享分析出现 JSON 解析失败（模型输出没有满足程序要求的结构化数据格式），三个组共同继承该状态。此题所有组所有尝试的选中卡和实际采用卡均为 0。

Q2 最终用了环境已有的用户字典；Q1/Q3 生成了清空它们的代码。这是真实的模型输出差异，却没有经验卡介入。因果归因（判断一个变化是不是某个指定机制造成的）需要机制路径相符；不能因为表现最好的组名叫 Q2，就把它的每一次成功都算给 Q。

共享初析控制了首次理解与检索条件，不控制后面的每一段模型输出。因此它减少了一个干扰来源，没有消除全部生成波动。

### 8.2 为什么 777 已改选、已采用仍然失败

Q2 在 c0 引入并采用 `blind-74-7891981125696054376`。这张卡 Q=0、visits=0，即尚未学习。原来更靠前的两张卡 Q 均为 −0.3、各更新一次，被 Q 排序压下。

所以本题不是“Q 发现一张多次成功的好卡”，而是“负分卡被降序，使未观察卡获得机会”。采用后，模型仍擅自定义允许命令列表。经验关于安全匹配的建议没有解决本题正常功能所依赖的既定配置。

这是落实瓶颈（模型得到建议却没有正确遵守题目的具体要求），同时也暴露稀疏奖励（很多卡只有很少反馈）和未知 0 分的含义问题。它不能单独证明排序完全无效，却明确显示“改选并采用”不足以保证提分。

### 8.3 为什么 1015 不能用来指控 Q 降低安全性

1015 的题面和执行器全局变量名不一致，参考实现使用执行器的名字，所以参考通过并没有暴露题面问题。本次预检漏掉了这一点，已在原记录中保留说明。

Q2/Q3 按公开 `USERS` 编程会产生 NameError（使用了当前运行环境中不存在的名称）。Q1 用宽泛异常捕获（把多种异常都转为统一处理）返回拒绝结果，得到 S 通过但 F 全失败。

因此，S 的 1 比 0 并不表明 Q1 实现了更正确的授权逻辑。它部分反映数据契约缺陷与异常处理差异。原分数仍应保留，但本题不适合承担 Q 安全收益或伤害的结论。

Q2 在 c1 采用的新卡 `pitfall-862-8413160066841834279` 同样 Q=0、visits=0；被替换卡 Q=−0.51、更新两次。接口问题还未解决，换卡无法补齐缺失的运行变量。

### 8.4 340 和 1001 告诉我们什么

340 只改变已有卡的顺序，三组均首次通过；它表明“改变顺序”可以发生在没有改善空间的任务上。

1001 三组规划阶段都触发 EnglishPolicyError（结构化内容没有满足项目的英文输出规则），最终代码仍能通过。340 的 Q1 也有经验分析解析与采用字段错误，但代码通过。**流程有错误和代码测试失败是两个字段，不能互相覆盖。**

## 10. 四类原因分别得到什么证据

以下将观测事实（直接来自记录）与机制假设（合理但尚未单独验证的解释）分开。

| 原因类别 | 已观察事实 | 目前支持的判断 | 不能下的结论 |
|---|---|---|---|
| 学习覆盖 | 297/1939 卡得到更新，172 张仅一次；最新改选新增卡仍未学习 | Q 信息稀疏，未知卡与负分卡的相对位置值得研究 | 多跑几轮一定解决，或覆盖少就证明 Q 无用 |
| 实际采纳 | Q2 在两题改变成员且采用新增卡，另有大量零选和拒绝 | Q 确实进入部分生成过程，不是完全没有生效 | 采用记录等于代码正确执行经验 |
| 模型输出 | 1341、1000、1055、777 自行改变公开接口、模板或权限配置；有 JSON/语言规则错误 | 这些具体任务的正常功能和结构化生成是直接阻断点 | 未做配对换模就断言 deepseek-v3.2 是唯一根因 |
| Q 机制 | 实际采用卡共享整份代码奖励；一张卡只有一个全局 Q；未知 0 分可胜过负分 | 奖励归因和任务条件差异可能削弱 Q 信息 | 已证明某张负 Q 卡有害，或已证明 Q 理论不成立 |

另有评价输入缺陷：1015 的公开契约与执行器不一致，属于测量条件问题（实验提供的输入与评价环境不匹配），应单独报告，不能硬塞进 Q 的模型失败。

当前最直接的瓶颈判断是：**Q 已能改变选卡，但被改变的少数任务没有稳定落实公开契约；同时奖励对整份代码计分，容易把这些非卡片错误记到卡片头上。** 学习覆盖是仍存在的限制，不能用它替代对已观察失败的具体解释。

## 14. 现阶段结论与下一步的最小选择

### 已支持的结论

1. **实现有效运行**：Q 可以从实际采用后的测试结果更新，冻结后参与排序，且不会因为比较实验而继续学习。
2. **机制部分激活**：最新 Q2 有两题改变成员并采用新增卡，另有顺序变化；上一批也有改选采用，不能把结果解释成“Q 完全没接进去”。
3. **正确率收益未获支持**：最新唯一额外 Joint 不经过经验卡路径；上一批真实 Q 未超过纯相似度；尚无稳定、可归因的收益证据。
4. **直接阻断点明确**：公开接口与已有配置被擅改、结构化输出失败、一道评价契约缺陷，以及稀疏和共享奖励，使“历史分数→有效代码”的连接较弱。

这些是当前数据范围内的判断，不是对所有模型、所有任务或完整 CLE 的普遍结论。

### 若继续，默认先做什么

最小改进应先针对已经发生的问题，给所有臂共同补强公开契约约束（明确沿用已提供变量、函数接口、模板及允许字段），并解决本轮观察到的结构化输出契约问题。Q 公式、卡正文、冻结库和修复上限先保持不变，以便仍能解释三臂差异。

下一批使用预先固定的新开发题，首次初析继续共享；先检查公开变量与执行器准备的一致性。仍记录“改选→采用→代码落实→Joint”。如果 Q2 只在没有卡介入的题上更高，仍不能判为 Q 收益。若卡已落实却仍无优势，再单独研究未知 Q=0 的处理或奖励归因，避免一次混入多个新机制。

这份报告没有为下一批编造提升门槛或样本量保证，也没有替代新的实验清单。当前可选择停止固定库 Q 探索，并如实归档“机制可运行、当前证据不支持提分”；若继续，应先完成可判读的开发验证，再决定是否启用预留确认。预留确认、完整 CLE、Base/Plus 仍保持未运行。

## 15. 一段可以直接用于组会的陈述

> 我们将 MemRL 的记忆效用更新思路接入旧 CLE，固定 1939 张经验卡，只根据实际采用后同一代码的功能与安全联合结果更新 Q。全部 273 道学习题运行后，297 张卡获得过更新。随后进行了同弱点类别内打乱 Q 的三臂对照，并增加共享首次分析来控制首次检索差异。Q 确实改变了部分选卡并被采用，但尚未观察到可归因的联合正确率收益。最新 8 题为 2、3、2 题通过，唯一额外成功没有经验卡介入。逐题分析发现公开接口与已有配置使用错误、格式问题、一道题面与测试环境不一致，以及稀疏和共享奖励归因问题。当前结果支持将主要精力先放在可判读的生成链与奖励归因上，而不是直接重复全量学习或宣称 Q 已提分。

这段陈述对应已保存证据；不把 MemRL 已有的 Q 公式称为原创，也不把本次开发结果替代完整 CLE 的最终评价。
