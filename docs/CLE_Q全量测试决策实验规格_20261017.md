# CLE Q 全量测试决策实验规格

日期：2026-10-17。决策协议：`cle-q-full-test-decision-v1`。执行实验继续使用 `cle-retrieval-q-v2-public-contract`，不改已固定名单、参数、数据和历史成绩。范围限旧版 CLE、Python、固定经验库和现有学习 Q；不重新学习 Q、不训练模型权重、不启动完整 CLE、新版 CLE 或 MASE。

## 要做出的决定

本实验判断：现有 Q 信息是否值得投入全量代码生成测试。先回答“是否有可复现的作用和收益”，再检查“原项目评测环境是否就绪”。全量分开指：原 D_gate 全池的开发诊断，以及冻结后 Python Base、Python Plus 的正式评价。D_gate 曾用于本项目开发，全池成绩不能称为全新独立测试；Base/Plus 的结果不得回流调参。

全量不是本轮默认动作。只有科学门和对应运行环境门都通过，才建议制定并执行全量清单。检索路线单独通过，只能支持继续研究检索，不能替 Q 获得全量资格。未达到门槛则保留失败证据并收口，不自动加题、追加学习轮数或重跑取最好成绩。

## 假设和最小比较

Q 值（经验卡过去被采用后获得的反馈分数）的预期作用链为：同查询和同候选下改变排序 → 引入更合适的卡 → 模型实际采用 → 代码落实 → 功能与安全联合通过。只改排序、只声明采用或只有总分增加，都不足以证明这条作用链。

| 臂 | 查询与门槛 | 选卡策略 | 比较目的 |
|---|---|---|---|
| A | 当前 R0 | 纯相似度 | 原检索基线 |
| B | 校准后锁定的 R* | 纯相似度 | 分离检索改动的作用 |
| C | 与 B 相同 | 相似度加学习 Q | 测量 Q 的增量 |
| D | 与 B 相同 | 同 CWE 内打乱 Q 和 visits | 排除任意排序扰动的作用 |

CWE（漏洞类型编号）内置换同时搬动 `(Q, visits)`，保留各类的数值分布。R*=R0 时合并 A/B，实际只跑三臂。主比较为 C−B 与 C−D；B−A 是另一条研究问题，不混写成 Q 收益。

## 门 0 人工标签与评价契约

入口：`retrieval_q_study import-review → summarize`，必须使用新公开契约配置。

1. 人工确认全部 914 个题卡对，填写双方依据、理由、审核者和日期；AI 不代签。
2. 对 `insufficient`（信息不足）和有争议标签作最终裁决。102 的解码技术表述、136 的访问过滤卡和异常捕获卡是重点，不按 AI 结论直接确认。
3. 标签针对整卡是否适用；不要求单卡包办整道题，但不能忽略卡内明确的技术错误或冲突指令。判断依据只用公开题面，不看隐藏测试、参考答案或模型成绩。
4. 若无法仅凭公开契约裁决，记录具体缺口并停止；公开契约如需再次修改，另立版本，不覆盖本轮输入。
5. 6 题校准池应存在人工确认的 direct（直接适用）正例；没有正例时以覆盖不足停止，不通过降门槛制造正例。

人工尚未完成是 `WAIT_HUMAN`，不是实验性能失败。当前 14 题参考可运行和有限依赖检查已通过；这不证明全量数据不存在其他缺陷。

## 门 1 只用校准集确定一个检索改动

复用现有 R0、仅原题 R-query、仅门槛 R-threshold。严格执行 `cosine > δ`，原 δ=0.7613717780938312。门槛候选只来自校准实际余弦值、原 δ 和 −1。

相对 R0，候选池内 F1 至少增加 0.05、任务命中率不下降、冲突率不增加才可替换；无合格改动就保留 R0。并列规则沿用原规格。若原设置零返回，冲突率仍写 null；候选必须零冲突才能通过对应保护条件。R* 锁定后不根据开发或确认成绩修改。

四指标（准确率、精确率、召回率、F1）只针对共同候选池，不能冒充全库召回率。0.05 是工程推进门槛，不是统计显著性。

## 门 2 八题真实代码生成

入口：`retrieval_q_study run-development`。属于 Phase3 对应开发评价，不训练或准入新经验；P7 是生成策略，不是 Phase7。

每题共享首次初析；同检索设置的 Q 臂共享首次查询、候选和余弦。调用原 `run_one(P7)`：首次 Joint（同一份代码同时通过功能与安全）通过即早停，否则最多一次修复，交付末次代码。修复轮各自使用原 P7 许可的反馈；不能跨臂传播测试结果。前 2 题属于这 8 题内的流程检查，不额外加题。

| 检查 | 进入确认的条件 |
|---|---|
| 公共技术条件 | 全题完整 F/S 测量、零流程技术错误、零未解决契约缺陷、原生产物格式通过 |
| 检索路线 | B 比 A 的候选池 F1 至少增加 0.05；任务命中不下降、冲突不增加；F 与 Joint 均不下降 |
| Q 结果 | C 比 B、D 的 Joint 各净增至少 1 题；C 的 F 不低于 B |
| Q 介入 | 至少 3 题同查询排序变化；至少 2 题新增成员实际采用 |
| Q 落实 | 至少 1 个救回题具有“Q 改选—新增卡采用—生成代码落实”的逐项证据 |
| Q 选卡质量 | 候选池四指标相对 B、D 均不下降；缺失分母不默认通过 |

出现 API、解析、候选不一致或验证技术错误，立即停后续付费任务，记录 `STOP_TECHNICAL`。正常生成后未通过 F/S 是模型结果，不是技术错误。修复已观测缺陷必须另立协议，历史结果不重写。

Q 门未过，Q 路线停止：改选不足写“干预不足”；已采用但未获益写“机制已介入、收益未建立”；选卡质量下降写“选卡质量退化”。若仅检索路线通过，允许沿原规格只确认 A/B，明确 Q 已停止。

## 门 3 最多二十四题预留确认

仅门 2 对应路线通过时执行 `run-confirmation`。确认前锁定名单、代码、参数、比较和标签规则；做完整公开契约及参考执行预检，有缺陷则停，不静默换题或缩分母。确认集仅对本轮配置选择隔离，需披露历史 CLE 暴露。

Q 路线确认 B/C/D；两路线都通过时增加 A。只执行一次，不按中途成绩调参。每臂完整覆盖原 24 题。确认标签在方案锁定后形成并由人工审定，另检查生成代码的实际落实。

Q 科学门沿用既定标准：两项比较 C−B、C−D 的 Joint 差均为正，精确配对检验经 Holm 校正后均 p≤0.05，并存在改选、采用和代码落实证据。另报告 F/S、救回与损失、配对区间、缺测及成本。全量推荐再要求确认 C 的功能通过数不低于 B，完整流程无技术错误、无未解决契约缺陷。

仅点估计更高写“方向性信号、证据不足”；未显著不等于证明无效或等效。24 题仍不足时以 `STOP_INCONCLUSIVE` 收口，不追加样本或学习轮数。检索确认复用配对 F1 区间及 F/Joint 不下降要求，不把它替代 Q 科学门。

## 门 4 全量运行环境与范围

通过科学门仅形成“值得进一步测试”的推荐，不证明全量收益，也不自动运行。执行环境另核验：

| 目标 | 必须补齐的条件 |
|---|---|
| D_gate 全池开发诊断 | 全池名单及公开契约预检、参考校准；固定全部分母；不更新 Q；披露历史暴露，不称为独立最终测试 |
| Python Base/Plus | 原 safecoder-python-validator:local 及 porta-bench-runtime-python3:latest 可取得且来源明确；原验证器正向校准通过；常驻容器与 watchdog 通过；Base/Plus 串行 |
| 最新三臂规格 | 冻结消费者接入同 CWE 打乱 Q，验证同候选和冻结期间 Q 不变；不能用另一个打乱规则替代 |
| 冻结评价行为 | 不依据隐藏 Joint 早停或修复；沿原冻结入口两次固定预算、交付末次代码；隐藏反馈不进入提示、选卡或 Q 更新 |
| 成本和存储 | 用已完成开发/确认的实际分臂 Token 和每题尝试数估算全量用量；未知账单费用写未核实；输出盘空间检查通过，不删除历史文件腾空间 |

上述环境检查不额外进行模型生成。原镜像缺失时为 `BLOCKED_ENVIRONMENT`；不能写成 Q 性能失败。全量名单若发现缺陷，不直接删题后开跑；先报告无法按原规格开展，并对新数据协议单独作决定。

## 数量和费用边界

沿用 6 题校准、8 题开发、最多 24 题确认，不增加实验样本。新增代码生成至多 4×8+4×24=128 次 P7 任务；每次最多两次代码尝试，模型调用还包括初析、检索后分析和规划，不能把任务数当 API 次数。两臂合并或路线停止时实际数量更低。

已有 14 次共享初析和 914 对模型标签直接复用。确认候选池每题最多约 112 对，最多 2688 对新增 AI 判断；每对最多一次新判断，原生内部重试单列用量。人工未完成前不发起新付费生成。成本按共享初析、标注、各臂和 Embedding 分列；不把旧单价估价写成实付。

## 终态与探索失败报告

| 状态 | 可以作出的结论 | 后续 |
|---|---|---|
| WAIT_HUMAN / WAIT_CONFIRMATION | 必要证据尚未产生 | 待对应步骤，不能写性能失败 |
| STOP_COVERAGE | 校准池没有直接适用正例 | 以卡库覆盖不足收口 |
| STOP_TECHNICAL | 本协议流程或契约未能有效完成 | 失败报告记录技术原因，不否定 Q 原理 |
| STOP_Q_DEVELOPMENT | 开发未过 Q 结果或作用链门 | 不启动 Q 确认；若检索通过，单独记录其路线 |
| STOP_Q_CONFIRMATION / STOP_INCONCLUSIVE | 确认未建立收益或样本证据不足 | 不放大全量，不声称普遍无效 |
| BLOCKED_ENVIRONMENT | 科学信号可能通过，原评测环境未满足 | 不运行对应全量目标 |
| RECOMMEND_FULL_TEST | 科学证据和对应环境均合格 | 另锁定全量执行规格；不等于已经取得全量结果 |

报告沿项目现有“执行规格→真实结果→机制证据→统计→成本→限制→停止决定→复现”格式。使用 [探索失败报告模板](../configs/cle_q_full_test_decision_20261017/探索失败报告模板.md)，填写实际数值、原始产物位置和失败阶段，未运行项写“未执行”，缺测写 null 和原因。历史实验独立列出，不拼接分数、不用模型标签替代人工标签。门槛未过也保留成功案例和费用，不挑最好轮次。

原生逐题文件继续位于现研究运行目录；决策快照放 `translation_work/diagnostics/20261017/cle_q_full_test_decision/`，精简摘要放 `results/curated/cle_q_full_test_decision_20261017/`。不复制原始大包。当前状态见 [决策阶段报告](CLE_Q全量测试决策阶段报告_20261017.md)。

## Agent 执行顺序

1. 读取新配置、原 manifest 和人工完成的 CSV；导入后 summarize，门 0 未过即停止。
2. 由现入口锁定 R*；执行前核对名单和冻结参数，运行 8 题开发并检查逐题作用链。
3. 写入有证据的 agent_code_review.json 后重新 report，按 gate_D 决定 Q/检索路线是否确认；Agent 代码审查与人类标签是两类记录，不互相代替。
4. 通过的路线执行一次预留确认，完成人工标签和 confirmation_code_review.json，再 report；据确认统计作收口决定。
5. 运行本配置的零 API 决策快照；停止时完成失败报告，等待时保留阶段报告；仅获推荐且对应环境通过后，才进入单独全量执行规格。

以上操作不包含启动完整 CLE 训练、重新学习 Q 或全量 Base/Plus。
