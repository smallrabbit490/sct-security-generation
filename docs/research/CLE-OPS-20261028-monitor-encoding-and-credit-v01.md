# 为什么工作台再次显示0个worker？

本次已修复工作台监控线程退出的问题；当前正式实验无法恢复的直接原因是生成服务明确返回“账户余额过低，不足以支持本次请求”。学习保留743/1122题次，功能安全对照保留1660/2980格，未把未交付题算作失败或完成。

## 守护故障及修复

10月28日09:00，Windows PowerShell进程清单包含非UTF-8输出。Python读取线程解码失败后返回空的stdout对象，工作台随后调用strip发生异常，导致监控线程退出，页面一直显示09:00:42旧快照。现在显式将PowerShell输出编码设为UTF-8，与Python读取编码一致；缺失stdout将触发可记录的采样错误，不能被解释为没有实验进程。

29项零API检查通过，真实CIM进程清单解析通过。工作台受控重载后重新采样、收取已结束的Codex修复结果，自主守护已重新开启；此次没有重启成功运行中的实验。页面新增403服务阻塞提示，避免将访问受阻仅显示为0个worker。

## 403原因如何确认？

1. 原Q的861题选卡及功能安全1086题第二次重复的请求均收到HTTP403；原日志未保存错误正文，原失败保留。
2. 同一密钥经原接入点可读取模型列表，模型仍在列表内。格式错误的诊断请求返回400，这些结果不证明正式生成所需额度充足。
3. 单独登记的一条1 Token诊断返回HTTP200，实际用量为输入7、输出1，共8 Token；它不计入正式实验成绩，也未替代任何实验格。
4. 按本次恢复任务，单独登记当前已拒绝请求的接续依据。Q零API回放精确复用K2的167个完成题及861题6条成功响应，停在缺失选卡处，新增HTTP0。另对功能安全1660格完成零API前缀核对，新增HTTP0。三项专项检查分别验证：只接受登记的拒绝请求、有成功响应就禁止重发、未登记请求不能放行。
5. 原模型、原消息、原预算的861题接续请求再次返回HTTP403，保存的完整错误明确说明账户余额不足。短诊断可执行，原正式长请求仍被服务额度检查拒绝。没有启动功能安全新付费段，也没有继续循环补发。

原生Q新段为`FQ_LEARN/K2/segment_004`，仅记录这次拒绝，不增加完成数。接续入口为`configs.cle_weekly_http403_recovery_20261028/resume.py`；它不改冻结源码、原P7规则、题目名单、提示、Q更新或预算。当前403接续授权开关已关闭，Q.run及FS.run的当前收据明确登记provider_balance_or_auth；历史收据另存，旧失败及未知用量保留。
