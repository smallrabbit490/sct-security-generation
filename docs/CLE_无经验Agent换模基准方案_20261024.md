## 1. 目标与旧基线核对

本轮只测：`deepseek-v4.1-flash-1017` 在不使用任何经验卡、也不生成经验卡的条件下，按CLE Agent既有流程做题，能得到怎样的F/S/Joint成绩。它是换模型后的无经验基准，不是重新训练CLE，更不是Q学习。

原设计与代码位置：

- `methods/cle_ablation/README.md`：P0–P7表和训练/测试反馈边界。
- `methods/cle_ablation/runner.py`：`SPECS`、`generate`、`run_one`。
- `methods/sct_trajectory/context_pipeline.py`：原初析、规划、代码生成流水线。

| 旧设置 | 实际操作 | 与本轮关系 |
|---|---|---|
| P0 | 直接给题，单次生成代码 | 纯prompt，不能代替Agent基线 |
| P1 | 单次生成，增加明确功能/安全契约 | 仍是prompt基线 |
| P2 | 初析→规划→代码生成，无经验，最多一次生成 | 不含修订预算 |
| **P3** | **P2＋最多一次修订，全程无经验** | **推荐直接复用的原无经验Agent基线** |
| P7 | 检索经验、适用性复析、规划、生成和修复 | 有经验完整前向链；本轮不运行 |
| Q0 | 原CLE由LLM选经验卡，不使用数值Q排序 | 仍使用经验，不能叫无经验对照 |

不把“P7检索没有命中”冒充P3：前者仍进行了检索/复析等操作；P3从设计上关闭经验消费者，也没有经验提炼器。

## 2. 样本与比较范围

| 集合 | 题数 | 本轮用途 |
|---|---:|---|
| PLT D_gate | 298 | 复用旧无经验消融的全部开发题，逐题生成和验证 |
| Python Base | 115 | 原CodeSecEval验证环境的无经验Agent评测 |
| Python Plus | 140 | Base结束后串行运行，规则同Base |
| 合计 | **553** | 一组P3，不追加其他臂或重复轮次 |

这里“PLT全量”沿用旧消融的298题D_gate口径。PLT原874题包括D_init303和D_grow273；这两池用于建立和演化经验，本方案不学习经验，因此不启动它们。不是1411条原始PLT全集，也不把874混成一个正确率分母。

三集题单执行前固定，不能按模型结果换题。PLT按原CWE轮转/字符串ID顺序的前两题为**1256、100**，作为完整298题中的技术检查，不额外增加样本。保留原题面和验证器，不混入Q探索中的题面修订。

本轮先得到新模型的P3基准。若同条件有经验成绩尚不存在，只能对历史成绩作注明模型/协议差异的描述比较，不能据此宣称经验或Q带来增益。

## 3. 保留的解题流程

公开题目及契约 → 初步分析 → 实现规划 → 生成代码 → 原验证器测F/S。

- **PLT**：首次Joint通过则结束；否则按原许可反馈再分析、规划、生成一次，最多两份代码；按原规则交付末次代码。缺测及生成错误保留，不按低成绩重跑。
- **Base/Plus**：固定两次前向，第二次只可参考自己的上一版代码；隐藏测试状态/错误不进入模型，不按隐藏成绩早停或挑选代码，最终评价末次代码。
- 所有任务输入卡片数量为0；不检索、不调用Embedding、不生成/蒸馏卡片、不更新经验、不更新Q，不进入Phase1–3训练或门控。
- 不额外增加P3原设计没有的经验复析、自生成测试或新接口保护提示，避免一边换模型、一边另改Agent设计。

## 5. 执行顺序与推进门槛

3. **PLT前两题技术检查**：运行1256、100并纳入298题。核对真实模型、user消息、分析/规划/生成记录、代码和验证可读；卡片/提炼/Embedding/Q操作必须全为0。正确率不作为技术推进门槛。
4. **完成剩余296道PLT**：复用已完成前缀，不重跑前两题；保留失败与缺测，统计首次/最终成绩及过程成本。
5. **Base环境校准及全115题→Plus环境校准及全140题**：各集先用原参考实现验证环境，参考答案只进入验证器；校准不通过就停止该集付费生成，报告具体环境原因。
6. **整理基准报告**：553题分别汇总，不拼成一张不分数据集的提分表。缺环境而未执行的集合标“未执行”，不记0分。

任何鉴权/传输未决、重复派发或经验越界属于技术停止；不按模型成绩追加采样或提高预算。已完成失败题不自动覆盖，未决付费请求不盲目重发。

当前Base/Plus阻塞：缺 `safecoder-python-validator:local` 和父镜像 `porta-bench-runtime-python3:latest`，原Dockerfile依赖该父镜像。不能换普通Python镜像冒充原环境。此项不影响PLT本地验证，但会阻塞Base/Plus。
