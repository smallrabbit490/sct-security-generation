# 粒度分阶段入口与成本接续实现

日期：2026-10-24。延续[17报告](17_执行门核对与阻塞交接.md)，本轮推进C的执行代码，不追加历史案例或付费服务控制。

## 1. 完成了什么

新增`granularity_execution.py`和`run_memory_granularity.py`，接通既定20/120/480格（一道题×一次重复×一个记忆档位）的分阶段入口。前20格为1394、102两题，L0–L4五档，各重复两次，复用已有4份初析/选卡。后续新题按公开题面准备一次共享初析与原CLE选卡，五档共用，不重复收费。代码生成、功能/安全验证、最多一次修复、首次Joint早停和末次交付继续使用原P7。

本轮最终85项相关离线检查通过，其中30项为新增（执行/入口21项、阶段9项）。它们验证接线与成本/恢复规则；使用模拟模型回复的本地用例不是模型实验成绩。真实C生成、真实C的Joint数据、分类器标签和Q更新均为0。

## 2. 请求和成本怎样保存

- 聊天、选择器和Embedding分别落盘，均在真实调用前预留并保存预算。选择器保留原请求类型和截止时间；每个传输操作只发一次。
- 每格费用包含复析、规划、生成、修复选卡和本格向量请求；共享首次初析/选卡作为共同开销另外报告，不乘五重复计费。
- 完整输入Token才可用于首选粒度标签。请求失败、费用字段缺失，或材料制作成本未交代时，完整成本为否，不能用0补齐。
- 发现原向量用量累计将缺字段的字典视作已报告用量，已修正缺失标记；合法字段继续累计，向量与模型请求内容不变。旧实验费用及成绩不重算。

当前技术入口只消费已静态审核的材料，不调用新绑定生成模型。后续若引入模型制作材料，必须记入其成本，不能继续声明这部分为零。

## 3. 中断或缺材料后怎样继续

修复选到新卡而缺少对应材料时，保存部分原生轨迹、卡片和查询，停止后续模型调用。补齐材料后，从原目录显式接续：

1. 已完成格保留原件，不重新生成；`rows.jsonl`从逐格权威文件重建，避免重复行。
2. 同格、同输入、已返回请求只回放；原响应与有限JSON归一化后的响应分别保留，预算不再增加。
3. 完整的修复选卡结果也回放，不能恢复时又付费选择一次。
4. 已提交但未返回、失败或输入发生变化的请求不自动重发。技术失败终态不自动重启。
5. 同目录已有写入锁时，第二个执行者停止；遗留锁先核对实际进程，不能仅凭等待超时删除。

离线用例已验证：一次修复缺材料后接续，只新增修复复析、规划、生成3个模拟请求，原付费前缀和修复选卡均未重复；另验证完成前缀不变、未知费用保留、预算到达后不再发送。

沿用`rows.jsonl`、`attempts/`、`generation/`、`validation/`和`retrieval_trace/`，新增`requests/`、`cell_costs.jsonl`及部分轨迹目录。没有另写验证器。

阶段升级仍使用同一480格排程和原目录，20格包含于120格、120格包含于480格。新阶段的累计预算需单独启用且不能低于旧预算，所有旧费用带入，不通过新建阶段清零。技术门仅要求20格流程完整、首次共享一致，不要求技术题必须答对；扩展到480格则必须满足C1。缺测、技术故障或120行但C1未过，都不能启动扩展。
