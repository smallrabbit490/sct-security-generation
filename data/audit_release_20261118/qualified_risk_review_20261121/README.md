# 原合格题的定向人工复核

本批只从原标为**合格**的 PLT 539、CodeSecEval Base 9、Plus 111，共 659 题出发。保留原标签不变；新增 API 规格风险复核，再与历史低通过集合取交集，最多抽取 50 条供人工独立复核。

这是一批针对容易误判区域的压力验证，回答“这批高风险原合格题是否真的合格”。**不能用其确认率估计全部 659 题的准确率**。如需总体准确率，应另外预登记随机抽样；本次不自动追加调用或样本。

## 两个集合如何定义

**A：历史低通过。** 至少 3 份实际测量且代码内容不同的实现，覆盖至少 2 种模型/方法条件，Joint（功能与安全同时通过）通过率不超过 20%。每题按代码 SHA-256 去重，同代码多次回放不重复计数。API 失败、空代码、环境故障和未测量不当模型失败。

PLT 采用既有冻结 `rows_full.jsonl` 中最终实现及对应动态测量，原来源和 arm 保留；Base 采用 2026-09-06 三模型运行的实际 worker 测试；Plus 采用 2026-09-23 Gemini / DeepSeek 全量运行最终实现的实际 worker 测试。条件和模型混合仅用于筛选这批曾多次失败的题，不能写成统一模型能力指标。明确的环境故障被排除；历史工具链和题面可见性与本轮审计并不完全相同，仍可能有未被结构化记录揭示的执行偏差。

**B：规格风险双判共识。** 对全部 659 题分别请求两次判断，yibu gpt-6.1-sol、temperature=0、max_tokens=2400、最多 10 并发，每个请求身份最多 3 次总尝试。模型不知道旧合格标签、历史成绩与其他判次结果。两判都为中/高风险、类型一致，并各自通过公开题面和测试原文逐字引用校验，才进入 B。

规范性风险分四类：接口契约、业务规则或数据、题面与测试冲突、环境依赖。中风险表示两种合理解释没有被规格清楚区分，但仍可能通过常规约定判为合格；高风险表示实质契约缺漏或冲突。低风险不入 B。实现困难、测试损坏、安全测试偏弱、缺正例、本机缺包不能单独作为规格风险。

风险与缺陷分开：判“有缺陷”仍必须遵守既有六规则，指出具体测试断言、不可推断的缺失和原因；测试损坏仅记完整性。引文校验验证字符串存在，不能替代人工语义核验。Plus 同时保留原总 `Test` 和历史拆分字段，审核时明确来源，不能把损坏的拆分字段当作有效断言。

**交集抽样：** A∩B 按数据集/风险类型轮转分层，层内优先双判高风险、较低 Joint 率，同等级固定种子 20261121；最多 50 条，不足不补入交集外任务，不为覆盖所有库凑数。入选库、分母与实际数量以 summary 为准。

## 人工标注顺序

1. 先打开工作台或盲审题包，独立判断 `human_verdict=合格/有缺陷/无法判定`。不要先看新风险意见或历史成绩。
2. 若判合格，`human_defect_type` 留空；可在 notes 说明为什么新增风险不构成必要契约缺漏。若判有缺陷，填写自己的四类首要类型，同时填写断言/调用原文及路径、缺少或冲突的要求、为何不能从公开材料与常规约定推断。指不出三项不能仅沿用机器怀疑。
3. 测试完整性与测试质量单列。损坏、缺测试或未能运行不自动推翻原合格标签。无法判定必须注明具体缺少的材料。
4. 完成独立判断后再显示机器信息，`type_consistency` 在本题包的含义为：人工合格→**确认原合格**；人工有缺陷→**推翻原合格**；无法判定→**无法判定**。原标签没有缺陷类型，所以此处不强迫比较一个不存在的类型。若推翻，分歧理由必填，并保留自己的缺陷类型。
5. notes 可补充对新增风险类型是否同意，区分“表述可改进但仍合格”和“存在影响正确性的实质缺陷”。建议两人独立标注，第三人处理分歧；原始独立判断与看过标签后的修订分别保存。

判“接口契约”时，参数只写类型而测试关键字调用属于缺参数名；但公开完整签名已给名则不能算缺失。其他规则与[上一批人工规则](../human_review_150/README.md)一致。

## 可视化界面

已先同步 GitHub 的 `72793c6` 可视化更新。本批沿用相同界面与本地存储机制，按题包 SHA-256 隔离进度；原 150 题入口仍保持默认。

Windows 可直接双击 `tools/start_qualified_review.cmd`。

```powershell
python tools/dataset_review.py --review-dir data/audit_release_20261118/qualified_risk_review_20261121 --out translation_work/diagnostics/20261121/qualified_review_ui/index.html --open
```

本批不额外调用翻译 API，题面显示完整原文并明确“未提供中文译文”，不冒用旧 150 题译文。页面离线、不执行 benchmark 代码；浏览器保存不写回仓库，定期导出 CSV/JSON 备份。独立题包含模型信息用于后续揭示，属于工作流盲审，不是加密隔离。

## 汇总与边界

人工完成后，单独报告：已标数、无法判定数、可判定数、确认原合格数、推翻原合格数，以及推翻后的缺陷类型分布。**原合格确认率 = 确认原合格 / 人工可判定题数**，报告同一分母下的推翻比例；不要把无法判定直接算合格或有缺陷。

这些是有意挑出的高风险交集，结果只描述本样本，不外推总体准确率、不作为模型提升证据。单模型两次判断不是独立人工一致性。Base/Plus 最终测试及人工发现不得进入 SCT 经验生成、门控或长期记忆更新。

旧包与新包的构建、CSV、判定门控、独立判断快照和存储隔离通过 Python/Node 测试；页面交互使用 DOM 适配器验证，未宣称已完成真实浏览器视觉检查。

本轮只做静态复核，不运行新的动态测试。历史 Function/Secure/Joint 仅作筛选证据；API 金额未测量，token 与失败/未知用量保存在 summary，原始尝试留在忽略运行区。
