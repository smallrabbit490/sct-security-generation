# 经验检查能发现简单检查遗漏的错误吗？

## 结论

**本次零 API 检查未通过进入付费探针的门槛，暂不继续付费实验。**复用三个不同题族的30份已保存交付代码后，经验检查新增发现错误的题族数为0，要求为至少3。当前先保留简单契约检查作为工程改进方向，不把经验检查列为已成立的科研贡献。

这次回答的是“已有候选检查是否值得投入下一轮”，不是对全部经验卡能力的穷尽判断。样本来自已分析的差异题，是回顾性开发材料；没有生成新代码，也没有测量修复后的Joint增益。

## 如何检查

1. 固定算术求值1152、JSON请求497、权限修改1023三个题族，分别取五条件、两次重复的全部已保存交付代码，共30份。沿原execution_index读取，重复保存的同一cell只使用最新记录，不把恢复段当新样本。
2. 简单检查使用公开题面：入口函数存在、基本合法输入、基本非法输入和外部USERS不被重定义。权限行为检查每次注入独立用户字典；原代码是否覆盖该字典另由静态检查判定。
3. 从已有卡片提取更具体的行为检查。算术检查负小数与嵌套负数，JSON检查dict子类，权限检查normal目标角色与重复设置同一角色。检查由本次人工转写，未证明自动生成能力。
4. 只有简单检查通过、经验检查发现真实契约错误，才计为新增发现。同一错误被两类检查发现不计增益。
5. 用原生Joint通过代码检查误报；另运行前提不匹配的来源规则，观察不做适用性筛选会发生什么。原生通过用作现有正确对照，不代表所有输入上的正确性证明。
6. 本地独立Python子进程执行，禁止代码直接文件访问和非允许模块导入。没有导入项目模型客户端，没有访问模型、Embedding或隐藏验证器；原成绩、输入、卡片和运行状态均未修改。

## 误报检查

适用经验检查对13份原生Joint通过代码产生**0次告警**；简单检查同样为0。这是当前三题族样本中的观察值，不能据此给出总体误报率为零。

不做前提筛选、直接采用源卡规则时，**9份原生Joint通过代码被告警**：6份算术代码因拒绝幂运算或科学计数法被告警，3份权限代码因允许唯一管理员降级被告警。

- 目标算术题只允许数字和加减乘除；源卡允许的幂运算不适用。科学计数法也没有目标题的明确支持，不能强制要求接受。
- 权限题没有“必须保留唯一管理员”的规定；不能把另一道题的额外业务策略当成当前题的安全错误。此项告警记作无目标依据，不将未规定的业务策略判为正确或错误。
- JSON对任意Mapping的扩展同样不计有效检查；它未在本次正确对照上产生告警。

这说明适用性筛选能够避免一部分错误干预，但当前证据只支持“应过滤无依据规则”，尚未支持“经验检查额外提高正确率”。
