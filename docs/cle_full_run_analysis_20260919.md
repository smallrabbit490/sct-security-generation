## 三、六个具体问题（逐条）

### 问题 1️⃣【致命】83.8% 的注入是跨 CWE 的

```
同 CWE 注入: 144 (16.2%)
跨 CWE 注入: 744 (83.8%)   ← 绝大多数是跨 CWE
```

**原因**：树只覆盖 8 个 CWE，但最终评测涉及 **19 个**。`hybrid` 模式在同 CWE 不足 `limit=3` 时，会用跨 CWE 经验**兜底填满**。

**后果**：把"正则边界"的经验塞给"加密算法"任务——**语义无关的注入**。分三组看结果：

| 注入类型 | 任务数 | JointPass | fail/pass |
|---|---|---|---|
| 无注入 | 2 | 0% | 0% |
| 全部同 CWE | 5 | 0% | 40.0% |
| 混合 | 84 | 17.9% | 50.0% |
| **全部跨 CWE** | **207** | **23.7%** | **46.9%** |

（注：跨 CWE 组通过率看似更高，但那是**选择效应**——难 CWE 恰好有同 CWE 经验。不能据此说跨 CWE 更好。）

### 问题 2️⃣【致命】固定注入 3 条，不是"按需注入"

```
每任务注入条数分布: {0: 2, 3: 296}   ← 296/298 都恰好 3 条
```
无论经验相关性高低，都凑满 `limit=3`。缺少**相关性门槛**（比如 LLM 打分低于阈值就不注入）。

### 问题 3️⃣【致命】门控只审了 1.9% 的经验，且 Δ 几乎全为 0

```
门控审计: 24 条  /  经验池 1284 条  → 只审了 1.9%
判定: supported 22, demoted 2

ΔJointPass 分布: {0.0: 21, 0.5: 3}
```

**21/24 条的 ΔJointPass = 0**，说明在审计任务上**根本没测出效果**。但因为放宽后的门控规则是"**Δ ≥ 0 即 supported**"，这些"无证据表明有效"的经验**全部被晋升入树**。

**这是门控设计的根本缺陷**：把"无证据"当成了"通过"。我之前按你的要求放宽阈值（不劣化即可），但**没配套要求"至少有正证据"**，导致门控实际退化成了"几乎全放行"。

### 问题 4️⃣【严重】树只覆盖 8 个 CWE，且偏向"难题"

```
树覆盖 CWE: 1333, 179, 200, 327, 347, 352, 502, 601  （8 个）
最终评测涉及: 19 个 CWE  →  11 个 CWE 完全没有经验
```

且进树的恰好包含多个 **Phase1 通过率 0%** 的 CWE（200/347/352/601）。这些 CWE 的种子经验本身就是在"完全做不对"的情况下提炼的，**质量存疑**。

### 问题 5️⃣【严重】经验内容清一色是"加强安全"，没有"保功能"的制衡

被注入最多的经验：
```
seed-643 (21次, CWE-601): "Redirect targets must be validated to prevent open redirect"
seed-336 (20次, CWE-327): "Cryptographic algorithm selection must be restricted to allowlist"
seed-137 (19次, CWE-200): "Apply attribute-level access control when exposing objects"
seed-481 (17次, CWE-352): "All state-changing operations must be authenticated and authorized"
```
**全部是"要加校验/要限制/要授权"** —— 而当前 47.3% 的失败恰恰是**过度防御**（功能被破坏）。
**注入这些经验，等于给已经"太严"的模型继续加码。**

### 问题 6️⃣【需注意】过度防御占 47.3%，是最大失败模式

```
fail/pass (功能失败·安全通过) = 141/298 = 47.3%   ← 最大
fail/fail                     =  73/298 = 24.5%
pass/pass (成功)              =  64/298 = 21.5%
pass/fail (安全失败)          =  17/298 =  5.7%
```
**真正的失败原因不是"不安全"，而是"为了安全把功能搞坏了"。** 而当前经验体系对此毫无针对性。
