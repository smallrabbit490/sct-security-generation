## 1. 三组怎样公平运行？

原生组使用对应独立重复的G0来源卡库；胜出组使用开发阶段选定方法在同次来源重复产生的卡库；通用组使用冻结通用指导。胜出组在调度中暂记GW，表示尚待开发结果确定的G1、G2或G3，不是已经选定了方法。

每个目标题与重复共享首次分析。两种经验方法分别从本组真实卡库做向量召回和大模型终选，至多三张卡，再由原生流程判断采用、制定计划、生成代码。首次未通过时，各组根据自己的代码和反馈至多修复一次。通用组没有经验检索，不把通用指导标成检索所得卡片。两次目标重复分别使用两次来源提炼的卡库，不共享模型返回。

Q回测入口原来要求所有组的卡片正文相同。这里比较的就是正文不同的提炼卡库，因此另接留出执行组件，没有关闭原Q回测的检查。不同库可以具有相同卡号，正文和向量缓存仍按实际内容处理；各库正文与Q在评价期间保持不变。

## 2. 封网检查证明了什么？

检查仅使用人工合成小题和合成服务返回，实际经过原请求器、真实向量召回与终选逻辑、原PLT验证器。真实模型、Embedding和外部网络调用均为0；这些合成代码通过不计研究Joint收益。

1. 四份来源库采用相同卡号、不同正文，两个方法和两次重复读取各自正确内容；四份不同正文均进入向量流程。
2. 三组两重复独立生成；通用组不调用选卡。完成后再次接续不重复生成，完整原生回放不新增HTTP。
3. 首次错误通过本组的一次修复恢复；修复重新检索自己的失败现场。代码及每轮原验证结果均可重放。
4. 部分组已完成时，恢复保留完成格和成功响应。网络失败最多一次物理尝试即停，未知用量保留；未核清请求不会自动补发。
5. 四worker可完成固定技术名单，经验正文与Q不变。方法或来源重复记录发生变化时拒绝恢复。
6. 分析采用实际近邻聚类；“胜出方法对原生”和“胜出方法对通用规则”两项做Holm校正，缺测验证不计作已测失败。
7. 费用按真实物理记录计数，恢复段和回放不重复相加。回放凭据绑定实际完成记录，事后变更记录会使凭据失效。

零API回放的选卡耗时会变为零。比对只排除此计时字段，卡片正文、候选与选中编号、采用、计划、代码及验证仍逐项核对，原耗时记录保留。

## 3. 怎样分析结果并继续？
