# 英文经验与语义检索修订

用户已授权修复上轮发现的检索缺口、核实 ChatAnywhere embedding、统一英文模型提示词与新经验，并在效果和链路验证后以总请求上限 80 启动全量 CLE；启动确认后不监控，不启动 Plus。

## 实施方案

保留现有串行生成修复、三轮训练和候选门控默认流程，不启用未验证的固定三分支或自动全局停用。修复检索后强制插入同任务经验、经验已拒绝但仍传给生成器、规则失败回退未标明的问题。

在现有层次检索基础上增加显式 semantic 模式：用真实 embedding 将公开任务初析与经验适用范围/原则/修法映射为向量，以余弦相似度召回，结合词重叠补充候选，再用一次英文模型选择 0–3 条实际适用卡片。不凭 CWE、类型奖励或同任务 ID 强制注入；保留身份、内容哈希、分数和拒绝理由。缓存以模型、文本版本和内容哈希为键，线程安全，支持增量经验。失败明确留痕，不静默假装向量检索成功。

ChatAnywhere GET /v1/models 已返回 text-embedding-3-small、text-embedding-3-large、text-embedding-ada-002。先测试真实 endpoint、响应维数/有效性和自造契约相关性检查。优先 large，small 为成本对照；最终是否提升以固定训练池代码 F/S/Joint 衡量，不能用官网榜单替代。credentials 仅用现有 load_key，绝不落盘。

全部 CLE 活跃模型提示词、生成的经验内容采用英文；源码注释和面向用户文档保持中文。原中文库不覆盖，比较用英文翻译副本保留 ID/事实/状态/来源，记录翻译失败；新全量从 Phase1 重提取英文经验。模型反馈若含中文，经验入库前验证/规范化，不删除内容后冒充英文。

## 验证与启动条件

单测先复现拒绝经验泄露、强制插卡、向量缓存与排序、模型异常、英文 prompt/经验约束，再实施。固定原始 Phase1 库和既有 D_grow/D_gate 303/273/298 边界，不接触 Base/Plus。对照至少完整 D_grow 273 题，两组使用同一英文库和相同英文生成 prompt/预算，区别仅检索器（修复层次 vs semantic）；先小规模链路验收后全量。报告首次/修复后 Joint、配对统计、缺测、调用与 token，并保留旧结果。无法证明正向收益时不写成功结论，不自动开始昂贵全量训练。

通过后使用 fresh output、v3.2、3072、三轮、原三池、训练侧本地隔离验证、80 shared request slots（所有训练 requester 与 embedding 共用）。先真实三轮小样本贯通并保存源哈希，再 detached 启动全量；仅核实进程命令、启动日志/状态后交付，不创建 heartbeat、不盯跑。

### 运行前固定的统计判据（2026-09-24，未开始代码对照）

主终点为完整 273 个 D_grow 配对任务在最多一次修复后的 Joint；首次结果仅作次要观察。
新检索必须在主终点严格高于修复后的层次检索，双侧精确 McNemar p < 0.05，且完整可测配对敏感性分析方向一致，才能把本实验作为启动全量的正向证据。
同时要求 546 行无缺失/重复、源文件与输入哈希不变、无 embedding 错误/静默降级以及英文准入与三轮链路冒烟通过。
不因中间分数修改 prompt、库、样本量或 embedding 模型；冒烟只检查协议和运行错误，不用其分数挑方案。
若不满足，保留全部结果并报告“收益未证实”，不自动启动昂贵全量。开发池仍非独立测试，显著也不保证最终 Plus 提升。
