## 怎样把含糊的“稳定较优”变成计算规则

C1原有三项门槛保持：至少4族存在稳定成功档和稳定失败档；至少两种档位各有至少2族支持且不能由一档支配；事后最好档上界比最佳固定档至少高10个百分点。

在产生任何真实C02成绩前，将第二项保守落实为**双向稳定优势**：存在两个档位A、B，至少2族中A两次Joint均通过、B两次均失败；另至少2族中B两次均通过、A两次均失败。两档都成功的题不证明它们各有所长。这个明确化比只数并列赢家严格，已经写入`granularity_protocol.json`，不在看成绩后调整。

举例仅用于检查程序：12个合成题族中，前2族只有L1成功，接着2族只有L2成功，其余8族各档都失败。最佳固定档为2/12，每族事后挑最好为4/12，差为16.67个百分点；4族存在稳定差异，L1/L2有双向优势，所以C1通过。它说明值得继续采标签，不能把4/12写成已部署分类器成绩。若L1也能通过L2成功的两族，则最佳固定L1已经达到4/12，差为0，门不通过。

## 原生记录、标签和成本

`granularity_results.py`读取原P7的`attempts`、F/S/Joint、`generation`、`retrieval_trace`和`usage`，保留首次与末次分开统计。`run_one_level`补充档位、重复号和格编号；不另建评分器。

- 同题同重复同档重复记录、其他协议、B包记录、预览以及更新过Q的记录不能混入。
- 正常功能/安全失败属于成绩；请求失败、未完成流程、空代码、缺测或违反既定修复/早停规则属于技术问题。技术问题使C1停在技术状态，不生成机制失败结论。
- 首次有序卡ID必须共用。L0虽然实际呈现为空，其`pre_level_selected_ids`仍记录共享选择；不一致时不产生该题的分类标签。
- 两次都Joint成功的档才进入可接受集合；1/2标为不稳定；五档全失败标“当前五档无成功”，不自动给L0贴正确标签。
- “首选档”只按实际完整逐格输入成本选择。原生行内`usage`可能不包含外部选卡/绑定，不能拿它冒充完整成本。独立`cell_costs.jsonl`须逐格记录`cell_id/prompt_tokens/complete`；任何可接受档成本缺失，首选档保持空值。共享首次准备另报共同开销，不按五臂重复计费。

`summarize --rows <原生C02行> --cell-costs <逐格成本> --out <新目录>`只作离线统计，不访问模型。当前实现只判先导C1，尚未导出可训练的36族标签、训练分类器或完成C2/冻结确认。
