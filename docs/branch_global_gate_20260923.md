## 方法变化

Phase1 不变。Phase2 用共享初析、最新层次检索和经验再分析形成同题上下文，在规划步骤提出三个不同实现方案；分别生成代码，收齐全部代码后再测试，禁止兄弟分支之间传递测试反馈。统一提炼读取全部成功和失败分支，候选记录引用分支 ID，轨迹不伪造串行修复。

训练选优只表示预算内找到可用候选。首分支、测试后选中的分支、三分支任一成功分别记录，不能把测试后选优称为部署 pass@1。明显重复或字段不完整的计划标为无效多样性；仍保留失败及代码重复记录。

Phase3 在所有 Phase2 演进轮结束后执行一次训练 D_gate 全池配对评测：无经验与有经验采用同一代码生成模板，都只有一次生成，无修复、无多分支。检索所需初析仅用于检索，不进入额外规划链。

发生已实测的功能或安全退步时，固定原检索卡片组合逐条移除，不补卡；初始完整组合结果加两次重复确认，累计三次中至少两次支持移除恢复，形成任务条件负证据。出现正负冲突时保留复核；只在新副本将有重复负证据、且未观察到正证据冲突的卡片置为 retired。所有原卡物理保留。随后对剩余库重新检索并全量重测，不能用过滤前分数充当过滤后分数。

完整实测才用于归因。API、检索、验证器和 worker 故障标为 U（未测量），不能用 D 代替。冻结快照保留 retired 审计记录，真实检索排除这些卡片。过滤后同 ID 的正文版本改变会被拒绝。

### 解读约束

- “全量”指 D_grow/D_gate 的全部任务，不表示经验库全部卡片均被召回或逐条独立验证。未曝光经验保持“未覆盖”；保留状态也不等于独立有效性通过。
- 三分支每个指标的 oracle 可能取自不同代码：例如一条仅功能通过、另一条仅安全通过，不能合成为 Joint。另报实际选择策略（首个 Joint 成功，否则首分支）的指标；第三条代码的分数不是选择后的分数。
- U 表示缺少完整动态 F/S 测量，既可能源于运行环境，也可能源于模型空代码、JSON/语法错误。后者仍是端到端方法失败，全量分母中不得忽略；不能把全部 U 称为环境事故。
- `calls` 是请求器逻辑调用数，底层 HTTP 重试未逐次独立计量；token 是保存的成功响应 usage。未拿到账单，不能保证包含超时请求的可能计费，也不能换算为实际费用。
- 三次中至少两次的逐卡移除只形成有限采样的任务条件证据：无经验基线没有重复，多卡交互与模型随机性仍存在；没有观测正证据不代表该卡在其他任务绝对无益。过滤后评测仍用同一选择池，不用于证明泛化。
- 独立诊断运行固定 Phase1 库，验证探索和筛选本身，不等于跑完新方法三轮训练。全量分支实验未对每题提炼或写库；提炼链路及其事实错误另用固定冒烟轨迹检验。训练入口接入不代表推荐立即用于正式重训。

完整实测敏感性分析：多思路/采样剩 223 对，胜负 10/6，Holm p=0.909；多思路/串行剩 225 对，胜负 9/10，Holm p=1。均不支持可靠提升。该子集排除了输出失败等难题，不能替代全量端到端主结果。

**为什么这轮没有实现预期：**

1. 普通三次采样已经有明显代码变化，不是复制同一份实现。819 个普通候选中仅 2 个 AST 重复，多思路为 0；在三份代码都非空的题目中，普通采样 255 题合计 763 个不同 AST（上限 765），多思路 231 题合计 693 个不同 AST（上限 693）。AST 差异不等于算法多样性，但说明“普通采样全都一样”的前提不成立。
2. 多思路有一定互补性，但被额外失败抵消：首发 72 题、预算内 88 题，多出 16 题；普通采样首发 75、预算内 87，多出 12 题。它并未明显扩大可解任务范围：13 个独赢同时伴随 12 个独输。
3. 多思路生成可靠性更差。多思路 819 次生成有 59 次未得到代码、4 次语法失败；普通采样是 24 + 1；串行 475 次是 2 + 2。多思路空代码按 b1/b2/b3 为 4/20/35，提示后面的不同方案更容易失败；这只是位置相关观察，不能断言是多样性要求或长度预算单独造成。规划 JSON 错误为多思路 5 题、普通采样 1 题。所有错误保留，未重新提示后拼入成功记录。
4. 当前分支错误账本只保留 `ValueError` 类别，而 `_content` 对空正文、响应结构错误及输出截断都可能抛该异常。因此不能把 59 次全部称为“3072 tokens 截断”；下一版需要保存脱敏的 finish_reason、错误细类和分阶段 usage 后再判断。
5. 所有分支共享初析和经验复析，所以共同的契约误解可以同时污染三条思路。冒烟 1304 的上下文覆盖问题展示了这种可能。仅要求 API/算法不同，不保证关键假设不同。
6. 串行组提供真实训练反馈并进行修复，初次 71 → 最终 95；并行分支没有反馈机会。串行虽然候选数较少，但模型调用及 token 更多，所以只能说“本配置下分数更高、成本也更高”，不能把它当等计算预算的结构优劣证明。

共享阶段 13 题出现解析/结构错误；普通采样和多思路使用完全相同的共享检索记录，均有 13 题零卡。缺卡降级继续生成是本轮已固定行为，计入结果，不代表这些题实际使用了经验。完整分支证据内未发现环境/worker 故障；模型候选导入、执行、语法和测试失败与基础设施事故分开统计。

**门控实际做了什么：**

- 初始原库检索共曝光 307/1,939 张卡（15.83%），1632 张未覆盖；301 张保留、6 张 retired、0 张正负冲突待复核。保留只表示负证据不足，不表示每张有效。
- 268 对完整可测初始比较中有 25 题维度退步：15 个 A→C、10 个 C→D，无 B↔C 交换。65 个“题目—可疑卡”组合做逐卡移除，每组含 3 次完整/去卡比较，首次完整结果复用。
- 65 组归因支持次数分布：0 次 40 组、1 次 18 组、2 次 6 组、3 次 1 组。满足规则的 7 组对应 6 张卡、6 道题。归因阶段也保留 32 次生成错误和 3 次语法缺测，缺测不计支持。
- 被停用卡涉及的初始 19 题，Joint 2→6；另外 279 题是 66→64。这是按已观察停用结果分组的事后描述，不能当随机试验的局部因果效果。
- 6 道触发确认负证据的题，在最终重新检索后只有 task 1265 恢复到无经验 A；另 5 题没有恢复到基线状态。固定组合去卡和重新检索是不同干预，补入其他卡片、共同缺陷及生成波动都可能影响结果；本次不能分配各原因的贡献。
- 重新检索后 172/298 题的卡片成员变了，174 题成员或顺序变了，283 题代码 AST 变了；124 题卡片 ID 和顺序相同的子集中仍有 4 个非 A→A、5 个 A→非 A。仅固定 temperature=0 不足以在本实验中得到可重复输出，净增 2 题不能全部归因于停用。
- 过滤后召回了 331 张不同卡，部分此前未曝光；停止门控后再检索的行为会引入未经过前述局部归因的卡片。实验保留这些真实结果，没有递归筛选至得分变好。

**缺测明细：** 无经验为 9 次生成 `ValueError` + 2 次语法失败；原库为 13 次初析 JSON 解码失败 + 2 次生成错误 + 6 次语法失败；过滤后同 13 题因初析快照缺失仍缺测，另有 1 次生成错误 + 1 次语法失败。原库另有 8 题检索成功但零卡，过滤后另有 6 题零卡。没有证据把这些都归因于 API 不可用：所有逻辑请求最终都返回，但返回内容未必可用。
