# 把来源细节改写为资源角色，能否提高 CLE 原题 Joint？

本批已按授权完成 30/30 个交付单元，包含两个精确复用的原卡参照。最终 Joint 为原卡 3/10、手改 7/10、通用 5/10。相对通用规则净多 2 次且出现 XML 安全测试通过数下降，未达预设门槛；完成分析后停止本版扩大，未启动自动重提炼。[逐题结果及机制分析](CLE-RPT-20261102-role-preserving-cards.md)

## 为什么做这轮？

[失败归因](CLE-RPT-20261102-card-failure-census.md)已定位 66 份外部资源覆盖、28 份外部模板参数化。局部修改代码分别救回 58、23 份。初析在见卡前就可能混淆资源来源；卡片有时也直接要求照搬来源函数签名。要检验的变化是经验能否正确传递操作所需的资源角色，并纠正这种混淆。

## 固定哪些原题？

已审计固定 12 个登记题族的实际入模卡：803、813、1339、677、683、1326、1060、1028、1218、1221、974、1359。它们占原 54 题回测的 22.2%。其中五个题族存在来源专用说明实际被采用的记录，固定为下一轮手改开发名单：

|题族|可修改的具体问题|已有失败中，相关卡实际被采用的单元数|
|---|---|---:|
|803 命令模板|来源指导把模板当参数，混入来源占位符和参数处理|1|
|813 XML 输出|来源指导将模板称作参数，并携带 HTML 来源变量的处理步骤|2|
|1339 HTML 输出|来源指导明确要求保留来源函数的双参数签名|5|
|1218 文档修改|来源指导要求空库时补测试记录，或增加数据库参数|1|
|1359 文章模板|来源指导要求猜测来源模板或照搬来源占位符|4|

这 13 个单元用于确认卡片确实进入了生成，不作为卡片致错的因果计数。974 也检索到改写模板格式的错误指导，但本次检查的失败记录中没有采用它；其余配置或记录类题的已定位代码错误也没有相应错误指导的采用证据，留作执行环节诊断，暂不增加付费条件。

这是已用于诊断的开发材料。每题从公开题面重新生成，两次独立重复，各条件共用同重复的首次初析，代码独立生成，最多原生修复一次。卡位、编号、顺序和预算固定；生成与修复两轮使用同一冻结卡组，隔离内容改动。原先通过和失败的配对都计入，按最终交付统计救回及损失。

## 三个条件具体怎样做？

|条件|给生成流程的内容|目的|
|---|---|---|
|原卡|原选中卡的实际入模文字|现有参照|
|手改卡|只修改来源函数签名、来源变量和示例值造成的错误角色说明；同一错误前提在实际可见字段中重复出现时一并纠正，保留适用的安全 API、操作顺序和保护目标|检验小改动是否纠正具体行为|
|通用规则|保留公开参数表；使用已有上下文；用户数据按输出语义处理；保留必要校验。这些要求用与经验相同的呈现方式给出|检验效果是否只是通用提示的作用|

例如，来源卡原文要求“函数参数保持为（模板，用户输入）”，改成“按当前任务列出的参数接收输入；将任务已提供的模板作为既有资源使用”。编码动作仍保留，卡内不写目标题变量、测试值或正确实现。若原卡已经正确说明资源来源，保留原文，并将该题作为正确指导是否能落实的观察项；不为制造差异改坏原卡。

运行前先保存逐卡改动和理由，核对哪些句子实际到达复析、规划及生成。初析、模型、参数、卡组和外部生成提示保持配对。模型固定为无 1017 后缀的 deepseek-v4.1-flash。旧模型记录不抵扣新模型单元。

## 需要多大体量，过什么门槛？

五题全部测试：每题 3 条件、2 重复，共 30 个代码交付单元。首次初析共享，共 10 次；每个单元最多首次三步与修复四步，模型请求上限为 220 次，无需新的 Embedding。执行前已冻结卡组、逐处改动及提示，累计 Token 上限为 400 万；实际新增 156 次模型请求、572,998 Token，无未知用量。两份原卡结果及对应初析精确复用，不重新计费。

手改卡进入自动提炼复现阶段，需要同时满足：

1. 相对原卡净救回至少 3 次，且救回分布在至少 3 个登记题族。
2. 相对通用规则也净救回至少 3 次，分布在至少 3 个登记题族。
3. 两个重复分别汇总，均不出现 Joint 净损失；安全通过无新增损失。
4. 救回案例中读到明确链路：角色说明被实际采用，复析或计划纠正了错误，代码使用正确的现有资源，原验证器通过。

配对成绩、按机制的损益、重复波动和检验结果全部报告。这些门槛决定开发筛选，不代替独立题族确认。只优于原卡而未优于通用规则，结论登记为旧经验纠错；本版停止扩样。

## 如何判断是提炼方式的贡献？

手改过门后，再用相同来源轨迹分别按原规则和新规则提炼，各做三次独立提炼。新规则只描述资源角色和已验证操作，不提供目标题。先检查能否自动复现那项小改动，再在同一原题名单上比较 Joint；确认之后另选未参与开发的题族检验迁移。

当前顺序是：逐卡小改与配对规格冻结 → 核算预算并执行手改对照 → 达门槛后才做自动提炼复现。排队全量继续跳过。
