# 自进化结构候选方案

## 目的与边界

当前实现常用的表达是 `D_init → D_grow → D_gate → M*`。这适合作为一次可复现实验的**数据隔离方案**，但不一定要作为论文中唯一的**方法拓扑**。本文件把二者分开：数据仍可按 family 隔离，方法则可以改成更接近“从经验中持续改进”的结构。

所有候选方案都必须遵守四条硬约束：

1. CodeSecEval Base/Plus 只用于冻结后的最终评测，不能反向写经验。
2. 候选经验在独立验证前只能存在于临时池，不能进入长期库。
3. C++/Go/Python 的功能和安全结果必须由对应 harness 或验证器给出，不能由模型自评替代。
4. 任务必须按 Seed Family 隔离，并报告多随机种子和任务顺序影响。

## 方案 A：经验生命周期图（推荐作为论文主叙事）

```text
观察轨迹 → 形成安全假设 → 外部验证 → 经验状态更新
                         ↑             ↓
                 反例/回归 ← 使用经验 ← 检索与适配
```

经验状态不再只有“通过/拒绝”，而是 `provisional → supported → narrowed/revised → demoted/retired`。这种结构最适合解释 SCT 的核心贡献：经验不是静态提示词，而是带证据、适用边界和生命周期的安全知识对象。

**落地方式**：R0/R1/D_gate 可以继续作为数据来源标签，但论文图中将它们放到生命周期节点下；先实现 `promote`、`narrow`、`reject`，有足够反例后再加入 `demote/retire`。

## 方案 B：验证驱动闭环（推荐作为运行时流程）

```text
检索 → 生成 → 编译/功能/安全验证
  ↑       ├─ 安全失败：反思并局部修复
  │       ├─ 功能失败：保留安全原则，修复契约回归
  │       ├─ 工具失败：记录环境诊断，不写经验
  │       └─ 联合通过：提取成功差异和可复用规则
  └────────────── 更新检索上下文 ──────────────
```

它把“门控”前移到每条轨迹，而不是等所有候选生成后再统一判定。独立 family 的回归集仍需保留，防止生成任务自证。

## 方案 C：主动课程与经验回放

```text
历史轨迹 → 弱点聚类 → 选择最有信息量的任务
       → 生成/验证 → 更新经验 → 重新计算任务优先级
```

任务优先级可由安全失败率、功能不确定性、语言覆盖缺口和经验冲突度组成。它比预先固定 `D_grow` 更能体现“系统决定学什么”，但必须额外做固定顺序、随机顺序和主动顺序三种对照。

## 方案 D：经验种群与版本竞争

```text
经验种群 → 检索/组合/变异 → 生成代码 → 独立评测
    ↑                                  ↓
    └──── 晋升、合并、收窄、淘汰 ──────┘
```

每条经验保留版本、来源、适用语言和评测分数；不同版本在多个 CWE/family 上竞争。它能吸收 Darwin Gödel Machine、AlphaEvolve 的“档案 + 变异 + 评估”思想，但存储、去重和计算成本明显更高，适合附加实验而非第一版主线。

## 方案 E：分层技能树/记忆

```text
语言无关安全原则
        ↓
       CWE 策略
        ↓
     语言适配策略
        ↓
   函数/框架验证模板
```

它可以自然回答“如何突出多语言”：同一安全原则在 Python、Go、C++ 中有不同实现和 harness 证据。检索时先召回上层原则，再按目标语言选择适配卡，避免把 Python 补丁原样复制到其他语言。

## 方案 F：Solver–Verifier–Curator–Scheduler 四角色

```text
Solver 生成/修复代码
Verifier 提供编译、功能和安全证据
Curator 抽取、合并、冲突检测和状态更新
Scheduler 选择下一任务或下一条经验
```

这是最清晰的模块化结构，适合代码实现和审计；代价是需要更多接口、日志和消融。第一版可把四个角色实现为同一进程中的四个模块，不需要四个独立模型。

## 推荐组合与实验顺序

推荐不要一次性重写全部流程，而是采用“两层表达”：

1. **论文主叙事**使用“经验生命周期 + 验证驱动闭环”（方案 A+B）。
2. **实验数据协议**继续保留 family 级的 `D_init/D_grow/D_gate`，保证与已有 96 条 PLT 实验、冻结 M* 和 Base/Plus 结果可比较。
3. 第二阶段增加主动课程（方案 C）作为消融；第三阶段再考虑种群竞争（方案 D）。
4. 分层技能树（方案 E）应优先用于多语言实验；四角色拆分（方案 F）用于工程重构和审计，不必作为额外模型贡献。

## 最小可行改动

在不改变现有评测协议的前提下，先新增以下字段和状态：

```json
{
  "experience_status": "provisional",
  "evidence": [{"tool": "cpp_harness", "functional": true, "secure": true}],
  "applicability": {"cwe": "22", "language": "go", "boundary": "..."},
  "parent_ids": [],
  "conflicts_with": [],
  "utility_delta": null
}
```

然后做四个最小对照：无记忆、固定 M0、现有追加式更新、生命周期更新。只有在独立 family 和冻结 Base/Plus 上重复得到稳定结果，才把结构变化写成方法改进。

## 相关论文依据

- Darwin Gödel Machine：档案中的候选 Agent 通过修改、评估和并行分支开放式演化。
- AlphaEvolve：代码候选由多个 evaluator 反馈驱动迭代改进。
- Agent0：课程生成器和执行器相互施压，主动产生更难任务。
- SBCO：将 verifier bank 和 harness policy 作为可优化对象，强调验证器驱动的闭环。
- Live-SWE-agent：运行中演化 Agent scaffold，但成本和安全风险较高。
- On the Fragility of Self-Improving Agents：任务顺序、随机性和规格不充分会放大自进化结果波动。

这些论文提供结构启发，不代表当前 SCT 已复现其结果。
