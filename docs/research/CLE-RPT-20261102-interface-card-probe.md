# “判断数据来源”经验卡能在相同题面下救回 Joint 吗？

在近期员工目录卡片诊断之外选择 URL 重定向、RSS 校验、SQL 式查询三个登记题族。另从重定向题删除允许域名列表的接口声明，单独观察模型会不会报告真实缺口。这是同一道题的变体。每个条件两次独立生成，使用 deepseek-v4.1-flash，失败最多修复一次。两组都允许用同一格式报告缺接口。通用组要求遵守公开接口，卡片组说明怎样查找数据来源及何时报告缺口。本轮测量固定卡片指导的作用，未运行检索、Q 排序或全套 P7。短指导与长卡片之间还存在长度差异。

|输入|通用组最终 Joint|候选卡最终 Joint|最终报告缺接口（通用／卡片）|
|---|---:|---:|---:|
|重定向，已给域名配置|2/2|2/2|0／0|
|RSS，已给配置|2/2|2/2|0／0|
|SQL，dataset 由函数参数传入|1/2|0/2|1／2|
|重定向，移除配置声明，单列诊断|0/2|0/2|0／1|

完整接口共六对，救回 0、损失 1、四对共同成功、一对共同未通过。对未交付代码的运行记交付 Joint 未通过，功能与安全测试分别留空。配置题另做离线动态回放，更换允许域名，要求接受新域名、拒绝移除的旧域名，两组各 4/4。查询题卡片组两次均在修复阶段把已列出的 dataset 参数报成缺少访问路径；通用组也有一次终止，但其理由是查询语法和类型转换细节。真实缺口变体中卡片组一次指出缺少域名来源，另一次自行构造域名列表，通用组两次自行构造列表。缺口识别与 Joint 单独计数。

运行共 16 个单元，22 次模型请求，19,043 Token。按执行前记录的门槛，须在至少两个完整接口题族获得净收益，且不能增加误报。两项均未满足，停止扩大当前卡片。目录实验中补接口的成绩继续归入输入条件，不作为卡片收益。
