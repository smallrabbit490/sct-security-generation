## P1 哪些题能用于检验提炼收益？

**原因。** 先排清公开要求冲突和缺失，才能解释生成失败与经验作用。

1. 按原题号核对874题。先重读20题直接冲突的公开条件及具体测试，再检查167题缺失项和55题歧义；逐模板检查632题是否还有未登记的特殊返回、默认值和外部对象要求。
2. 每题记录公开信息、CLE可读的运行对象、允许反馈、隐藏验收选择及可构造的实现路线。不能只凭参考实现通过就判公开信息完整。
3. 建立互斥用途。公开信息足够的题进入主比较候选；歧义已裁决的题记录解释；缺失及冲突题进入数据诊断。C、D类依旧保留题号、原记录及原因。
4. 如需补题面，单独形成只补公开接口、格式或策略的修订草案，标清哪些变化改变原任务。具体样例值、密钥、隐藏输入及期望答案留在诊断侧。

**完成条件。** 874题均有用途与依据。结果写明已复核题数、仍待裁决题数和使用版本，不把A类静态未检出当作可解性证明。参考可运行率、公开可解性、生成可达Joint分别统计。

**训练上限如何表达。** 当前参考预检874/874说明参考程序在对应测试上可运行。人工候选和零API修复提供已测可达结果。没有穷尽合法实现时不把其中任何数值命名为数学理论上限，也不据20个冲突题推出模型测试通过率最多854/874。

## P2 return和raise丢失会影响哪一步？

**原因。** 这两个字段已经确认没有直接进入当前向量查询，但影响程度还没有测量。

1. 保存原始字段到query_embedding_text、向量请求文本、候选和模型终选提示的映射。当前874题检查作为起点复用。
2. 在独立诊断入口构造加入return、raise的查询文本。检查默认值、别名、空字段和异常要求是否完整到达，不改活动实验使用的检索源码。
3. 从已有记录选出返回或异常决定卡片适用性的实例，核对初析是否已经表达同一要求。分清直接字段丢失、分析间接覆盖、真正遗漏三种情况。
4. 若需要真实召回与Joint比较，另冻结原查询对完整字段查询的配对条件。与改卡实验分开，单独核算新增向量和选卡成本。

**完成条件。** 文本是否到达可以零API确定。排序、选卡和Joint的变化用实际调用测量；接线检查只报告字段覆盖。

## P3 人工卡能在现有公开条件下达到什么结果？

**原因。** 先确定经验究竟还缺哪项可用知识，再决定如何改提炼器。

1. 对P1可用清单逐题写出应采取的代码动作、该动作的来源、原卡是否已表达及为什么仍会失败。全题做用途登记，详细比较先限定为50个不同题族。
2. 50族覆盖至少两种不同错误机制，以真实有卡失败为重点，同时保留原来通过的回归对照。每族先取一道题，其余同族题另作迁移用途，避免用同族题填充独立题族数。
3. 原卡和人工候选用相同编号、相同卡位。仅用当前公开信息或合法训练来源改动内容，明确动作、适用前提和必须保留的行为。通用对照同步获得已经确认的普通规则。
4. 如果为解释上限而查看目标题ground_truth，卡片标记target_reference_visible，只用于答案可见诊断。可部署候选标记public_or_training_source，逐条记录依据。
5. 先复用保存代码做最小操作回放，检查合法与禁止行为以及原成功损失。随后形成原生卡、人工候选、强通用规则三组的模型比较方案。

**规模与门槛。** 条件方案为50族×3组×2次独立重复，共300个代码单元，每次最多修复一次。已有精确同条件结果逐单元确认后复用。工程继续线设为相对原卡净救回至少5/100、至少3个正向题族、至少两种机制、损失最多2/100，两个重复的净收益均非负。超过原卡但没有超过通用规则时，只支持纠正旧卡的价值。该门槛沿用50题族阶段的投入尺度，统计确认另看题族区间与配对检验。

**本周交付。** 逐题用途索引、50族卡片与依据、保存代码回放、可执行三组方案及预算。此时尚无新增模型Joint。

## P4 ground_truth适合在什么位置帮助提炼？

**原因。** 原生冷启动已经使用来源漏洞与补丁，候选需要说明在已有用法之上具体改善了什么。

1. 对冷启动种子提炼、来源轨迹提炼两个接点分别画出实际输入。训练来源可用自身ground_truth；留出目标题的ground_truth限于只读数据预检与单列诊断，Joint由unittest判定。
2. 复用已有来源验证入口，先核对修复方向、原对象及实际操作，再撰写卡片。多项改动共同必要时保留组合，不把同一个保留对象动作计成多个机制。
3. 原生提炼和候选提炼使用相同来源、相同材料可见范围、相同调用预算。公开通用规则为第三对照。若额外开放了参考信息，先登记为信息条件变化。
4. 候选只增加支持P3有效动作的必要表达，按整张卡检查其他字段有没有写回相反建议。内容合格后才形成冻结库。
5. 采用未参与规则设计的库内留出题，登记本次静态审查和旧实验的接触情况。题族与别名交叉核对，使用“库内留出”表述。自然检索的原生、新版、通用三组与固定供卡开发分开。

**下一阶段方案。** 最多50个留出题族，三组各两次，共300单元。只有P3达到内容与收益条件后才冻结具体名单和新预算。本周如尚未满足，只交付接口、候选和留出清单。

**最终研究结论的门槛。** 新版相对原生的配对Joint差值为正，题族95%区间下界大于0，预登记主要检验达到0.05；若同时检验相对原生和通用的两个主要比较，采用Holm2。实际救回、损失和两个重复分别报告。若主张来源经验额外价值，还须超过强通用规则。选中、采用和落实用于解释路径，不替代完整名单的Joint。

## P5 代码波动从哪一步产生？

**原因。** 已有重复结果不同，需要分清提示、模型输出、检索和执行差异。

1. 优先复用已完成同卡50族、原生提炼与固定动作、六族正常检索及新版提示复测记录。按模型来源、公开版本、卡文、提示和生成预算建立可比对，不跨模型拼接。
2. 依次核对初析、候选、终选、采用、规划、首轮代码、修复代码、测量。找到每个主要得失配对最早出现的行为差异。
3. 对代码做语义差异归类，重点检查外部对象覆盖、接口误用、格式与异常、阈值、拒绝合法输入、建议未落实。复用已完成最小回放。
4. 同提示重复出现差异，只能说明当前流程存在波动。要归因到具体提示写法，先冻结语义等价的提示对照，保持卡、候选、模型及修复预算相同。

**完成条件。** 每个归因有实际代码及验证依据。若需新增提示对照，单列方案及预算，不把“提示词有漏洞”预填成结论。本周至少完成既有全部主要救回和损失配对的索引及未解释项登记。
