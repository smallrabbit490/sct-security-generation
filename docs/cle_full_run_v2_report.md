## 二、分析口径（重要：v1 对比曾用错方法）

**必须用「同 task_id 配对」对照，不能比较整体均值**——两版评测池虽同为 298 条，
但若存在任务差异，整体比例会失真。

实测噪声参照：同配置两次运行在 64 条配对上的 fail/pass 差 = **+0.0pt**（噪声极小）。

| 口径 | 正确性 |
|---|---|
| 整体均值比较 | ❌ 不可靠（我曾据此误判噪声达 22.7pt） |
| **同 task_id 配对** | ✅ 唯一可信口径 |
| 机制性指标（晋升数/注入条数/跨CWE占比/去重对数） | ✅ 确定性，不受生成噪声影响，作为**主证据** |

## 四、需要说明的两点（避免误读）

1. **跨 CWE 审计为 0 是合理行为**：v1 全量里 `cross_cwe_count` 全为 0，
   原因是 audit 池（298 条 / 19 CWE）同 CWE 供给充足，LLM 自然优先选最相关的同 CWE 任务。
   这不是缺陷；泛化性已由**检索层面**的跨 CWE 对照实验覆盖
   （见 `docs/cle_negative_findings.md` 实验二），且 v1 中 83.8% 的注入本身就是跨 CWE。

2. **树规模可能比 v1 更小**：新门控要求 Δ>0 才晋升，
   而多数经验 Δ=0（→ unmeasured）。这是**预期行为**——宁可树小，
   也不让零证据经验污染检索。判断标准是"注入的经验是否更有效"，而非"树是否更大"。
