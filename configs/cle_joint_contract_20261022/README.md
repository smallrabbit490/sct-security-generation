# CLE 公开契约与修复交付分支

## 目的与当前状态

目标是提高 PLT、Base、Plus 各自的正式 Joint（功能与安全同时通过）率。本分支已实现新消费者 `P7_public_contract_v1`，完成静态真实轨迹审计、本地行为测试和12题PLT原生环境正对照。**尚无新模型生成、尚无三个集的新Joint成绩。** 当前执行环境缺少原 ChatAnywhere 模型凭据，以及 Base/Plus 所需原 Docker 验证环境；新入口在付费调用前明确阻止运行。

代码从 `556e1b4fd8cc45074962bb2a662e05091b943659` 接续，旧 P7 入口、旧数据、全部旧失败记录和 M1 均保留。本分支不续跑旧 Q 学习、不变更卡正文、生命周期或模型。

## 已实现的行为

1. **完整公开信息进入检索。** 新入口把 PLT 原生 `return`、`raise` 映射到旧检索器已经支持的 `return_description`、`exceptions`。原路径漏掉当前874题的返回信息、650题的异常信息。查询内容哈希区分新旧缓存，原入口行为不变。
2. **公开契约成为可执行检查。** 从公开题面识别入口、清晰参数列表和明确要求保留的外部绑定，注入规划/生成并对候选作纯AST检查。模糊要求保持未知，不从隐藏fixture、测试或参考实现推导规则。
3. **修复使用固定公开用例。** 只从公开任务生成至多6条用例，经同一模型语义复审后，在任何候选生成之前冻结。该复审不称独立评审或人工确认。c0/c1使用相同用例；公开执行结果绑定代码和用例指纹。
4. **修复不能用总通过数掩盖回归。** c1须保留c0全部已通过公开用例，不新增明确契约违规、不把原可测规则改成未知，且至少修复一个公开失败或违规。否则交付c0。空用例、缺测、全通过且无违规时不生成没有选择价值的c1。
5. **先选交付代码，后正式计分。** 新消费者最多生成两个候选，仅所选候选进入原正式验证器；隐藏F/S不返回生成、检索、选择或Q。`final`是交付分数，不能读取`attempts[-1]`代替它。旧P7作为当次新生成的对照时保留其原反馈/末次交付规则。
6. **有界、可审计。** 必须显式指定任务和冻结卡库；卡数不符、输入缺失、已有输出目录均拒绝。保留全部真实尝试、提示、检索轨迹、缺测和跳过理由；无长期记忆更新。HTTP请求含最坏重试预留，Token使用保守上界阻断，实际返回usage另记，不能把预留额当账单。

内部用例可能有错、可能缺少外部环境，静态检查只覆盖明确可解析规则。这些机制的目标是减少可识别回归，**不保证正式Joint提高，更不保证三个集同时提高**。

## 运行入口

依赖当前项目的Python环境及测试依赖；原真实模型请求器只读取 `CHATANYWHERE_API_KEY` 或项目约定的本地凭据文件，不在命令行、配置或产物中写密钥。Base/Plus必须使用原 `safecoder-python-validator:local` Docker环境。

默认命令只作零API预检。以下使用已提交的D_init v4b任务和原1939卡正文库，适用于默认 `semantic_llm`（不读取Q）：

```bash
python -m methods.cle_ablation.run_joint_contract \
  --dataset PLT \
  --tasks configs/cle_dinit_full_learning_20261020_v4b/tasks.json \
  --memory docs/cle_evidence_package_20261015/experience_pool_1939.jsonl \
  --arms P7 P7_public_contract_v1 --limit 2 --repeats 1 \
  --max-http-attempts 2500 --max-total-tokens 20000000 \
  --out translation_work/diagnostics/20261022/cle_joint_contract/new_preflight
```

真正执行需给一个**全新**输出目录并加`--run`；入口会先检查运行条件、再使用原验证器逐题校准参考实现，校准失败则在模型调用前停止。用户已授权接管执行；此开关用于区分运行和预检，不额外引入审批要求。

若显式研究冻结Q消费，先从仓库Release `cle-project-snapshot-20261022` 获取 `CLE-full-project-20261022.zip`，运行：

```bash
python configs/cle_joint_contract_20261022/restore_snapshot_inputs.py /path/to/CLE-full-project-20261022.zip
```

然后显式指定 `translation_work/diagnostics/20261020/cle_q_online_v1/D_grow/frozen/m_star_q.jsonl`。缺失当前快照不能默默退回零Q或其他M1。默认主线先测整个消费者包，不做Q效果归因；原1939卡库与当前快照已逐卡确认只有`q_value/q_visits`字段不同。

Base/Plus分别指定其 `data/SecEvoBasePlus/{Base,Plus}/Python_{Base,Plus}.json`，沿用项目要求串行执行，避免不同运行清理彼此的Docker资源。PLT门控评价指定恢复的 `tasks_D_gate.json`；298题已被历史比较曝光，不能称全新独立留出集。每个数据集单独生成报告，不能用总平均掩盖其中一个下降。

## 有限后续与停止条件

唯一主线是旧P7对新消费者的当次同题比较。先运行固定2题双臂真实小链并保留它们，确认生成/公开检查/原验证器/usage完整后，才决定是否扩大到最多48个D_init family、每臂2次。最多192行、384份候选；最多2500个HTTP尝试和2000万保守Token上界，先到即停，不能将提前停止写成全量完成。新臂额外有公开测试生成/复审成本，不称等Token对照或单一Q因果实验。

未来开发筛选门槛建议：完成48题且配对平均Joint增益达到5个百分点、无数据契约/隐藏反馈事故，才值得冻结方法做PLT298/Base115/Plus140正式比较；增益不大于0则停止这条付费主线，0至5个百分点仅报告不确定开发信号。这个5个百分点是**未来工程筛选提案**，不是旧研究预注册标准，也不是显著性阈值。三集的收益必须由各自真实配对成绩与不确定性支持，不能事先许诺。

目前阻塞是可核实的运行能力缺失，不是“还需批准继续”。已有代码、静态审计和12题校准已经完成；恢复凭据/原验证环境前不会冒充真实模型重跑，也不会自动启动大规模学习。
