# CLE 实验人员工作方法调研与 Skills 体系

调研日期：2026-10-17。对象是旧版 CLE 的历史人机协作实验流程；依据仓库文档、E盘原始会话和运行产物。本轮未调用实验模型、未重新生成代码、未修改历史实验与Q库。

## 调研结论

本项目的可复用方法不是“每次跑一遍全量”，而是：从具体失败形成问题，设计最接近的同题对照，先证明改动确实进入执行链，再判断是否影响最终代码，最后通过冻结评测或独立确认决定是否保留。遇到中断则定位已完成阶段、恢复到新目录，保留失败记录和费用。

据此形成7项技能：项目接续、数据与公开契约、实验设计、训练与开发执行、冻结评测、逐题结果与失败分析、检索与Q专项。前6项覆盖本课题常用工作；第7项保留近期Q任务的特定流程。技能不把某次题数、模型、重试或并发当成长期统一要求。

## 实验人员实际上怎样工作

### 从研究想法进入可检查的阶段成果

seq 495要求分步骤实施并产出可验证结果；seq 2407要求调出每阶段具体例子；seq 2474进一步追问真实代码、第一次与修复后动态测试、回放选样、审计数据量及树中具体操作。其有效工作方式是用阶段产物和题例检查实现，不满足于流程图或“已完成”的叙述。

迁移到技能后，阶段验收沿数据实际流动展开：任务→分析/规划→生成→验证→提炼→入池→检索消费。历史root_cause和prev_fix_assessment在提炼端存在、入池却丢失，说明只检查字段生成不足以证明机制落地。该方法由cle-training-run承担。

### 用同题对照排除较简单的解释

54题检索四臂固定题目和经验池，既测交付成绩也测调用；273题多分支研究用普通三采样对照不同计划，而不是只与一次生成比较。后续同时报告首候选、任一候选成功和实际选中，发现正确代码已经生成却被选择器漏选。

技能继承的是控制变量和核对最终交付的做法。不会继承“某臂名写关闭就已消融”的捷径：当前矩阵command_for_arm只映射部分组件，必须沿CLI、执行分支和运行记录检查真实变化。该方法由cle-experiment-design与cle-result-analysis承担。

### 先定位瓶颈，再决定扩大哪一种实验

语义筛选出现长JSON、拒绝ID、截断等失败后，研究人员重放固定历史查询比较协议可靠性，再做端到端比较。调用成功率改善和Joint改善是两类结果。273题语义检索未超过旧法后，没有继续完整CLE训练。

这支持“先有诊断性信息再付更大预算”，但不支持永久禁止全量：用户批准的门槛和当次证据满足时，可以推进。历史有的实验允许保留故障估计实际效果，新Q协议则要求零技术错误；技能必须读取对应协议，不能强行统一。

### 开发成绩与冻结成绩分开

Phase3停用后得分提高仍来自同一个门控池，带选择偏差。09-25又发现冻结路径使用空tree或不同TF-IDF/生成额度，随后对齐冻结文件、公开契约、检索、预算和Docker重新测量。当前课题需要继承这种检查消费路径的方法，不能直接把训练门控提升写成最终泛化。

原冻结日志曾允许任务内反馈，近期消费者已修订隐藏反馈边界；技能采用当前协议的无隐藏反馈要求，并把旧行为明确作为历史事实。该方法由cle-frozen-evaluation承担。

### 出错后恢复有效工作，而不是整批重跑

Phase3恢复案例先排除任务/卡ID异常，定位检索瞬态字段被计入冻结版本比较的问题；随后修复真实缺陷、做相关回归和小链验收，从完成的Phase2恢复到新目录，保留旧失败目录。

这种方法节省重复Phase1/2费用。它不意味着可以绕过指纹检查：源码或协议变化时要有新的输出和身份；同版本继续时用原入口支持的检查点。该方法由cle-training-run承担。

### 结果回来后读失败题，而不只读总分

原会话要求展示ABCD四态、失败案例、回放选择和树变化。后续报告进一步用同题救回/损失、功能损害、实际采用和代码落实定位原因。典型例子包括多候选上界高于实际交付、Q额外通过题没有卡片介入，以及题面和夹具不一致导致失败。

技能让Agent把这些原因分别说明，不从fail/pass状态直接认定过度防御，也不从“卡片采用了”直接认定Q选择正确。该方法由cle-result-analysis承担。

### 把实验效率纳入研究结果

耗时复盘指出阶段审计、修复轮和长尾调用决定总时长，日志完成间隔已经含并发，不能拿它当串行耗时。54题检索的调用减少约53%，旧估价却只减少约10%，因此调用、Token、实际费用和墙钟分别核算。

技能保留测量与复用的原则；提高并发、缓存基线或跳过修复只能依实际协议与输入一致性决定，不复制某一历史并发数，也不按失败成绩挑容易题降低成本。

## 哪些历史做法需要修正

| 历史表述或做法 | 为什么不能直接继承 | Skills中的处理 |
|---|---|---|
| 小样本未涨分就断言“检索不是瓶颈” | 样本和干预有限，不能排除其他检索改动 | 写本条件下收益未建立，并保留替代解释 |
| 调用下降53%称费用减半 | 调用长度、共享开销和价格不同 | 分列调用、Token、墙钟和可核实费用 |
| 当前题oracle实现大幅提升就证明记忆粒度有效 | 同时改变答案可见性和针对性 | 标为上界诊断；隔离任务代码示例才可作可部署比较 |
| 同门控集过滤后涨分就称泛化 | 筛选与评分复用同一数据 | 披露选择偏差，另做冻结评价 |
| 消融标签写false就当关闭 | 部分字段没有实际CLI/代码映射 | 核对运行分支与真实行为 |
| 基线0分就删题、难题首轮失败就跳修复 | 改变分母并可能引入择优偏差，历史建议未充分验证 | 仅在预先规定的研究设计内改变预算，不事后筛题 |
| 模型标签直接当人工金标准 | 两者证据来源不同且AI理由有错 | 分别保存，不冒签；不足信息明确待裁决 |
| 原聊天中“需要拍板就叫我”变成所有操作审批 | 是特定历史会话的授权安排 | 服从当前用户指令与实际权限，不增加通用确认门 |
| 所有Q任务都强制6/8/24和零重试 | 是近期特定协议 | 专项reference里保留，通用技能不固化 |

| [cle-retrieval-q](../skills/cle-retrieval-q/SKILL.md) | 检索四指标、经验采用与Q机制 | 匿名标签、共同候选比较、改选/采用/实现证据 |

先用cle-research定位，再按实际任务只加载需要的专项。T/A/F/R与Phase不是另一套流程；专项技能调用原项目入口，不创建新验证器、不把所有操作包装成另一个总runner。

项目源保留在skills/，每项含SKILL.md、agents/openai.yaml和按需reference。cle-research另提供只读inspect_cle_run.py，用于快速读取明确指定的运行概况。七项描述限定于CLE，普通其他项目任务不应触发。

## 使用示例

- “用 $cle-data-contracts 核对136的公开上下文和夹具依赖，保留原始题目。”
- “用 $cle-experiment-design 为经验卡结构改动选择最小对照，说明是否需要重训。”
- “用 $cle-training-run 从已完成Phase2的运行恢复Phase3，只读原目录。”
- “用 $cle-result-analysis 解释这批Q为什么改选被采用却没有提分，按项目格式收口。”
- “用 $cle-retrieval-q 接续当前研究，先读取实际gate和人工标签状态。”

技能不会因被调用而获得额外API预算、发消息、推送GitHub、全量训练或改写数据的授权；已经明确授权的工作则按范围直接推进。具体实验的人工标签要求是数据质量门，不是通用操作审批。

## 验证与维护

结构校验、链接检查和只读脚本的实际运行结果另见 [Skills验证记录](CLE_Skills验证记录_20261017.md)。本轮验证不等于新做了CLE方法有效性实验。

新工作方法仅在出现真实任务、明确要求或已观察失败后补充；改动对应技能或reference，不向总入口堆积全部历史。更新项目源后，本机技能入口指向同一目录；不复制旧运行参数到全局配置，也不提交机器专属入口。
