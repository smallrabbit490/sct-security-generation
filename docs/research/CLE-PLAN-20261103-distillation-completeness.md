# 五阶段提炼研究：本轮怎样补证据？

本轮冻结 11 月 3 日的来源动作、三份 13 卡库和原生 P7。最终问题是：只改变来源经验的提炼方式，正常检索、不强迫采用、最多修复一次时，能否提高新题的最终 Joint？以下顺序先定方法，再看成绩。

1. **种子与背景。** 按卡号核对三个库：背景卡来自哪里，哪些卡的检索正文和实际呈现发生变化，其他评分和结构是否一致。相同背景只说明控制了背景差异，不构成种子提炼的效果实验。
2. **来源与修复。** 用原版 D_grow 输入逐一读取 K1/K2/K3 各 273 条记录。每轮单列未获反馈资格的任务；在合格记录中取全部实测失败→Joint 的两轮修复。按原生类别报告没有进入正向提炼的轨迹，不用后来的契约重算历史资格。
3. **验证与写卡。** 原样运行 K0 的冻结提炼器。只认五个本地反事实验证都满足的动作，报告新来源题族、重复出现次数及未产卡原因。新卡仅作为旁路研究产物，不加入三份冻结库，不用目标输出改规则。
4. **接回正常流程。** 在此前六族两重复的自然检索实验上，逐请求比较原提示、重复编号和返回模型，再以原验证器回放。旧原生臂要同时复现代码、测量、功能、安全与修复次数。对另外两库只在完全相同请求上复用同重复的响应；缺向量或提示不同就在第一处停，绝不借旧成绩填新臂。
5. **独立终点。** 核实库外 PLT 有原验证夹具的题族数；再检查 D_gate 中未进入已有实验/诊断的题族。按公开要求分别寻找需使用外部对象、同域但关键操作不同、无此操作的对照；不能凑齐具有区分力的新族，就停在可行性结论。若有合格题，用三库同题两重复，以全名单计算配对最终 Joint，采用子集只解释机制。探针沿用净救回至少 3、至少 2 个新族、两重复净增各非负、无配对 Joint 损失和安全退步；正式替换需独立确认集按题族计算的差值 95% 区间下界高于 0。只胜原生支持工程纠错；声称从来源获得额外知识还须胜公开规则。

本轮先完成无付费的来源、加载、回放和样本资格检查。前批额度仅涵盖旧迁移批。样本达不到终点设计时不扩大；已有训练、全量队列、生产库均不改变。

**资格核查后的内部探针登记（在查看以下目标的代码、成绩及本次干预结果之前）。** FFS 曾为全部 298 道审计题保存实验行，严格未投放的审计族为零。内部探针单独使用曾进入 FFS、当前未在指定提炼开发清单或报告中命中的六族：427 验证 API 消息、873 向外部队列加任务；1215 修改文档、1229 转账；1259 验证密码、894 解析字符串。前两题检验读取或更新既有对象，随后两题还须正确授权，末两题检查无此对象时是否误伤。排除与来源项目成员管理和用户档案同模板的题；不按历史通过率、选卡或控制结果替换名单。它们只能支持库内前瞻探针，不作最终独立确认集。

先让原验证器跑六份未改参考，再对前四份只加入同名空替代，另跑一个相同初始化但赋给未用名字的对照；两道无外部对象的题只跑未用名字对照。只测原验证器能否区分两个程序。候选库、规则、目标和两次重复在此之前冻结，技术控制与模型生成分账。随后的生成设计为 6 题 × 3 库 × 2 次独立重复 = 36 个单元，正常检索、最多一次修复；另找独立确认材料之前不升级正式库。

**若探针达到门槛，独立确认怎样做？** 由不参加提炼的评测方封存未向开发者披露的题族、公开接口与功能/安全双测试。先按题义排除来源模板别名，冻结目标清单、抽样分层和分析代码，再运行三组。预先规定每族等权：先在族内平均两个重复的配对最终 Joint 差，再按族算总体差和 95% 区间；双主要对照（候选对原生、候选对通用）按 Holm 控制整体 0.05。用先导批的题族差异波动估算样本量，预定最小值得采用的改善和预算后一次冻结，不以边跑边检验决定何时停止。如果没有独立材料，只发表库内配对结论。六题控制的正负结果均不得用于重写该候选后再把这六题当独立验证。
