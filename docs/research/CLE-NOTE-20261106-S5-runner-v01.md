# S5的300个单元怎样执行、恢复和分析？

**固定50例的执行入口、断点复用、原生回放和统计分析已接通。封网技术验证通过20项，正式新生成仍为0／300。** 当前唯一派发缺项为本批新预算批准，旧守护和排队全量保持关闭。

## 1. 一共会调用多少次？

每例有两次独立重复。每次重复先做一次新初析，再把同一初析分别交给原卡、移除焦点卡、只删除焦点动作三组。各组独立复析、规划和首次生成，生成后使用原验证器，结束该单元。固定卡片直接进入采用阶段，没有检索、Embedding或修复调用。

|环节|固定数量|共享边界|
|---|---:|---|
|新初析|50例×2次＝100次|同例同重复的三组共享；不同重复独立|
|复析、规划、生成|300单元×3次＝900次|三组之间、不同重复之间均独立|
|逻辑模型请求|1000次|不含未来传输恢复尝试|
|代码单元|300次首次生成|原结果不填作新E0|

模型固定为不带1017的`deepseek-v4.1-flash`，thinking关闭、temperature为0、单user、4096输出预算，最多三张卡。其他已冻结实验规则不变。生成侧只接收公开题面和实际卡文，不接收旧目标代码、旧测试反馈或目标参考代码。原测试材料仅供本地验证器使用。

## 2. 预算核算结果是什么？

[预算提案](E:/ResearchRuns/CLE/20261105_six_questions/S5/generation/budget_proposal.json)为累计162,000,000 Token保守占用上限、1200次物理HTTP上限，Embedding为0。该值来自实际原生提示构造、未知输出的64KiB工程预留及20%传输预留，使用既有“UTF-8字节加输出上界”的占用算法；它是资金控制用的保守上限，不是预计实付Token。币种费用尚未估算，提案尚未批准。

已知用量按实际响应记录，未知用量保留预留，恢复段累计原物理请求。共享初析、各组请求和无法定位作用域的请求分别登记；分析只消费物理账本，不把回放或各行共享usage再加一遍。

## 3. 怎样从断点接续？

入口为`python -B -X utf8 -m configs.cle_weekly_plan_20261105.attribution_stage`，在项目根目录使用指定venv Python。

1. `check`核对原材料、运行源码、离线检查与本批预算。当前返回`S5_new_batch_budget_not_approved`，不会创建模型客户端或启动正式实验。
2. 预算获准后，`launch`才会启动固定批。运行锁覆盖整个批次；已有本批进程时不再启动，其他CLE实验运行时保留其worker，本批等待。
3. 真正中断后先用`audit`检查完整单元和未决请求，再用`probe`零API重放已保存前缀，确认停在准确的缺失请求。
4. 无未决且预算仍有效时，用`launch-resume`进入新段。完成单元直接复用；未完成单元的成功响应精确重放，只请求此前没有返回的新边界。原段不覆盖。
5. 未决请求、模型不符、来源或提示分歧均停止，不当作正常模型失败，也不自动重发。正常模型JSON降级或空代码保留为模型结果；验证缺测另列。
6. 300个单元保存后自动做原生零API回放并调用分析。若只缺收尾，`finish`仅回放和分析，不创建付费生成段。

每个实际请求继续遵守工作日北京时间09:00—12:00、14:00—18:00禁用窗口。只读检查、精确回放和分析可以在禁用窗口进行。

## 4. 怎样避免把采用标记当成因果证据？

主要对照是E0与E1、E0与E2的焦点动作落实差异，Joint是次要结果。采用、计划和代码分别保留。代码动作必须由当前Agent实际阅读后填写审阅记录，记录理由、实际代码及代码位置；只有采用标记时，主要动作统计保持未测。

任务按同例同重复配对，区间和置换按29个真实公开接口近邻组聚类，两项主要比较做Holm校正。另列两次重复的结果与波动、Joint救回和损失、未执行单元、模型生成失败、原验证器缺测及费用。中间部分结果保留部分状态，完整范围未齐时不签署最终结论。

分析入口还会输出逐份代码阅读队列。完成50例焦点材料准备与运行器接线，仍不等于完成S2／S4所有建议的观察对应表，也不等于300份新代码的实际因果审阅。
