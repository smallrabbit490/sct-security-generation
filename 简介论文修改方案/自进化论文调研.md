# 自进化论文调研及对 SCT 的可用启发

## 调研目的

本文件不是相关工作章节草稿，而是围绕当前 SCT 的核心难题整理自进化研究：经验如何产生，如何从失败和成功轨迹中抽象，如何检索和复用，如何验证后写回，如何修订或淘汰，以及如何避免错误经验在后续任务中传播。

论文链接均指向公开的 arXiv 页面或论文项目页面。检索日期为 2026 年 9 月 8 日。带有“预印本”标记的论文应在正式论文中再次核对发表状态和版本。

## 先给结论

对当前 SCT 最有直接价值的不是再增加一个“经验库”，而是借鉴下面六个机制：

1. 用 Reflexion、Self-Refine 和 CRITIC 的思路，把外部执行反馈转成结构化反思，但不把模型自评当成唯一真值；
2. 用 ReasoningBank、ReMe、A-MEM 和 Mem0 的思路，把经验做成有结构、有链接、有状态、可压缩和可淘汰的对象；
3. 用 Voyager、MemSkill、Memento-Skills 和 Socratic-SWE 的思路，让经验或技能从真实轨迹中形成，并通过后续任务继续检验；
4. 用 LATS 的思路，在高风险任务上保留多个候选和验证分支，而不是一次生成后立即写经验；
5. 用 SEVerA 的思路，把安全不变量写成硬约束或输出契约，至少在经验门控阶段先检查这些不可违反的条件；
6. 用 EVOMAL 和相关记忆安全研究提醒自己：经验库本身是攻击面，必须记录来源、限制复制、隔离候选经验并检测自传播。

## 一 论文清单与独特机制

### 1. Self-Refine

- 论文：Aman Madaan 等，Self-Refine: Iterative Refinement with Self-Feedback，2023。
- 链接：[arXiv:2303.17651](https://arxiv.org/abs/2303.17651)
- 方法特点：同一个模型依次承担生成器、反馈器和改写器的角色；每一轮根据反馈改进当前输出，不需要额外训练。
- 对 SCT 的启发：可以用于任务内修复环节，让候选代码经历“生成—安全审查—修改—再次验证”。
- 不能直接照搬的地方：Self-Refine 的反馈可能来自模型自身，SCT 的安全经验晋升必须要求外部测试、静态分析或目标语言 harness 证据。
- 建议落点：作为 `D_grow` 的任务内修复基线；增加“单轮生成”和“最多两轮验证修复”的消融。

### 2. Reflexion

- 论文：Noah Shinn 等，Reflexion: Language Agents with Verbal Reinforcement Learning，2023。
- 链接：[arXiv:2303.11366](https://arxiv.org/abs/2303.11366)
- 方法特点：不更新模型参数，而是把环境反馈转成语言反思，存入情景记忆，供后续试次使用。
- 对 SCT 的启发：失败结果不应只记录为 `false`，应转化为“失败根因—下一次行动”的短反思，并限制其可见范围。
- 可采用形式：

```text
失败现象：路径穿越测试失败
根因：只做字符串前缀判断，没有解析规范化路径
下一次行动：使用目标语言的规范化路径和目录边界检查
```

- 建议落点：为 `d_grow_rows.jsonl` 增加 `failure_root_cause` 和 `next_action` 字段。

### 3. CRITIC

- 论文：Zhibin Gou 等，CRITIC: Large Language Models Can Self-Correct with Tool-Interactive Critiquing，2023。
- 链接：[arXiv:2305.11738](https://arxiv.org/abs/2305.11738)
- 方法特点：模型通过外部工具检查自己的输出，再根据工具反馈修改；强调工具反馈对自我改进的作用。
- 对 SCT 的启发：把编译器、静态分析器、Python/Go/C++ harness 和资源检查统一看作外部批评器；经验来源应包含工具证据，而不只是语言模型的解释。
- 建议落点：统一记录 `tool_name`、`tool_result`、`repair_delta` 和 `verification_delta`，形成可审计轨迹。

### 4. Language Agent Tree Search

- 论文：Andy Zhou 等，Language Agent Tree Search Unifies Reasoning Acting and Planning in Language Models，2023。
- 链接：[arXiv:2310.04406](https://arxiv.org/abs/2310.04406)；代码：[GitHub](https://github.com/lapisrocks/LanguageAgentTreeSearch)
- 方法特点：把蒙特卡洛树搜索、语言模型价值评估、自反思和环境反馈结合起来，保留多个行动分支。
- 对 SCT 的启发：安全代码生成可以在高风险 CWE 上保留多个候选修复，优先选择“功能和安全均通过”的分支；失败分支可用于生成负面经验。
- 建议落点：不必把完整 MCTS 用到所有任务。可以在 CWE-22、CWE-78、CWE-502 等高风险类别上做小规模分支搜索实验，比较单候选和多候选验证。

### 5. Voyager

- 论文：Guanzhi Wang 等，Voyager: An Open-Ended Embodied Agent with Large Language Models，2023。
- 链接：[arXiv:2305.16291](https://arxiv.org/abs/2305.16291)；项目：[voyager.minedojo.org](https://voyager.minedojo.org/)
- 方法特点：自动课程、可执行技能库、环境反馈和自验证共同形成持续技能积累；技能是可解释、可组合、可复用的代码。
- 对 SCT 的启发：经验卡可以进一步变成“可执行验证模板”或“语言适配技能”，例如路径安全检查技能、反序列化安全检查技能，而不只是自然语言规则。
- 建议落点：把经验拆成“安全原则卡”和“验证模板卡”两类，后者可以生成目标语言检查代码或 harness 片段。

### 6. Learning From Failure

- 论文：Renxi Wang 等，Learning From Failure: Integrating Negative Examples when Fine-tuning Large Language Models as Agents，2024。
- 链接：[arXiv:2402.11651](https://arxiv.org/abs/2402.11651)
- 方法特点：失败轨迹不是噪声；经过质量控制后，负例可以提供优化方向。论文强调不能简单丢弃失败数据。
- 对 SCT 的启发：`D_grow` 中的失败应分为可归纳安全失败和不可归纳的 API/环境失败。前者可生成候选负面经验，后者只进入诊断记录。
- 建议落点：增加失败质量标签：`security_gap`、`functional_regression`、`language_api_error`、`harness_error`、`environment_error`。

### 7. SCoRe

- 论文：Aviral Kumar 等，Training Language Models to Self-Correct via Reinforcement Learning，2024。
- 链接：[arXiv:2409.12917](https://arxiv.org/abs/2409.12917)
- 方法特点：使用模型自身分布产生多轮纠错轨迹，并通过在线强化学习和奖励设计避免只拟合离线修复样本或发生行为坍缩。
- 对 SCT 的启发：如果未来做参数训练，不能只把历史成功修复轨迹做 SFT；应在当前模型分布下采集纠错轨迹，并防止模型只学会一种修复套路。
- 当前可采用内容：先不做 RL，而是做多轮轨迹采样和“初始候选—修复候选”的对比记录，为未来训练准备数据。

### 8. ReasoningBank

- 论文：Siru Ouyang 等，ReasoningBank: Scaling Agent Self-Evolving with Reasoning Memory，2025。
- 链接：[arXiv:2509.25140](https://arxiv.org/abs/2509.25140)；代码：[GitHub](https://github.com/google-research/reasoning-bank)
- 方法特点：从成功和失败经历中提炼可泛化的推理策略，而不是保存整条原始轨迹；还通过 memory-aware test-time scaling 增加多样经历。
- 对 SCT 的启发：经验生成应同时使用成功和失败轨迹，且保存“策略摘要”而不是完整答案；可以为同一任务生成多个候选，提供对比信号。
- 建议落点：R1 不再只从失败生成经验，增加成功修复差异通道；对候选经验保留来源轨迹摘要，不保存完整参考答案。

### 9. ReMe

- 论文：Zouying Cao 等，Remember Me, Refine Me: A Dynamic Procedural Memory Framework for Experience-Driven Agent Evolution，2025 预印本。
- 链接：[arXiv:2512.10696](https://arxiv.org/abs/2512.10696)
- 方法特点：多面经验蒸馏、上下文自适应复用、基于效用的新增和淘汰，直接针对 append-only 记忆的膨胀和过时问题。
- 对 SCT 的启发：经验库需要完整生命周期，而不是 `promote/reject` 二元写入。应根据后续任务效用收窄、降级、合并或退役。
- 建议落点：将 `M*` 之外的运行库设计为带状态的 `M_t`，保存 `support_count`、`contradiction_count`、`last_used_round` 和 `utility_delta`。

### 10. A-MEM

- 论文：Wujiang Xu 等，A-MEM: Agentic Memory for LLM Agents，2025。
- 链接：[arXiv:2502.12110](https://arxiv.org/abs/2502.12110)；代码：[系统](https://github.com/WujiangXu/A-mem-sys)
- 方法特点：借鉴 Zettelkasten，把新记忆写成带上下文、关键词和标签的笔记，并动态建立记忆之间的链接；新记忆可以更新旧记忆的描述。
- 对 SCT 的启发：经验之间应有“同义、前置条件、冲突、语言适配、特化”关系，而不是独立文本列表。
- 建议落点：先实现轻量链接，不必上图数据库：`related_experience_ids`、`conflicts_with`、`specializes` 三类字段即可。

### 11. Mem0

- 论文：Prateek Chhikara 等，Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory，2025 预印本。
- 链接：[arXiv:2504.19413](https://arxiv.org/abs/2504.19413)
- 方法特点：动态提取、整合和检索长期记忆，并比较不同记忆结构和检索设置，强调效果与延迟、token 成本之间的平衡。
- 对 SCT 的启发：经验检索需要同时报告质量和成本；top-k、上下文长度和重复经验会影响 baseline 公平性。
- 建议落点：在实验中记录检索延迟、检索 token 数、top-k 和经验重复率，不要只报告最终 JointPass。

### 12. MemSkill

- 论文：Haozhen Zhang 等，MemSkill: Learning and Evolving Memory Skills for Self-Evolving Agents，2026 预印本。
- 链接：[arXiv:2602.02474](https://arxiv.org/abs/2602.02474)
- 方法特点：把“如何抽取、合并、裁剪记忆”本身做成可学习、可进化的 memory skills；controller 选择技能，designer 定期检查困难案例并改进技能集合。
- 对 SCT 的启发：当前流程把经验抽取器写死了。可以把“安全差异抽取”“失败根因归纳”“语言适配抽取”“冲突检测”做成不同的经验形成技能，并让控制器按任务类型选择。
- 建议落点：第一版不训练 controller，先做规则路由；将来比较固定抽取器和任务自适应抽取器。

### 13. Memento-Skills

- 论文：Huichi Zhou 等，Memento-Skills: Let Agents Design Agents，2026 预印本。
- 链接：[arXiv:2603.18743](https://arxiv.org/abs/2603.18743v1)；代码：[GitHub](https://github.com/Memento-Teams/Memento-Skills)
- 方法特点：使用 stateful prompt 和结构化 Markdown 技能，采用 Read—Write Reflective Learning，让技能路由和技能内容共同演化，不更新模型参数。
- 对 SCT 的启发：把经验分为“读阶段检索”和“写阶段更新”，并记录状态上下文；经验库的写入可以由专门的经验设计器完成。
- 建议落点：为每条经验增加可读的状态、适用上下文和更新历史，形成类似技能文件的稳定格式。

### 14. Socratic-SWE

- 论文：Chuan Xiao 等，Socratic-SWE: Self-Evolving Coding Agents via Trace-Derived Agent Skills，2026 预印本。
- 链接：[arXiv:2606.07412](https://arxiv.org/abs/2606.07412v1)
- 方法特点：从历史解决轨迹中抽取结构化技能，再生成针对 Agent 弱点的修复任务；候选任务要经过执行验证，并用 solver-gradient alignment 判断任务是否真的有训练价值。
- 对 SCT 的启发：`D_grow` 不应只是固定随机样本，可以由历史失败模式生成针对性任务；但新任务必须通过执行验证和 family 隔离。
- 建议落点：在 96 条 PLT 试验完成后，做一个小规模“弱点驱动采样”附加实验：根据失败根因生成同类但不同 family 的任务，观察是否比随机 D_grow 更能产生有效经验。

### 15. SEVerA

- 论文：Debangshu Banerjee 等，SEVerA: Verified Synthesis of Self-Evolving Agents，2026 预印本。
- 链接：[arXiv:2603.25111](https://arxiv.org/abs/2603.25111v2)
- 方法特点：用形式化输出契约包裹生成模型调用，拒绝不满足硬约束的输出，并使用已验证 fallback；将搜索、验证和学习分离。
- 对 SCT 的启发：安全经验中可以区分硬不变量和软建议。硬不变量应在代码生成后立即检查，不能等待经验门控才发现违反。
- 建议落点：先实现“经验级硬约束”：每张经验卡必须包含 CWE、触发条件、必须满足的不变量和禁止模式；代码验证器检查这些字段是否存在，目标语言 harness 检查不变量是否满足。

### 16. Self-Evolving Coding Agents Survey

- 论文：Hao Zhou 等，Self-Evolving Coding Agents，2026 综述预印本。
- 链接：[arXiv:2608.03392](https://arxiv.org/abs/2608.03392v3)
- 方法特点：将自进化目标分成记忆、技能、工具、工作流、组件、拓扑、环境和上下文等类别，并总结进化时机、代码特有反馈、基准过拟合、可逆性、成本和安全问题。
- 对 SCT 的启发：论文应明确 SCT 进化的对象是“外部结构化安全经验和检索/门控策略”，不是模型参数、Docker 环境或 Agent 拓扑。这样研究边界会更清楚。
- 建议落点：在方法图中标记哪些对象可更新，哪些对象在最终评测前冻结。

### 17. EVOMAL

- 论文：Xiaodong Wu 等，EVOMAL: Self-Poisoning in Self-Evolving Coding Agents，2026 预印本。
- 链接：[arXiv:2608.25776](https://arxiv.org/abs/2608.25776v1)
- 方法特点：指出 Agent 会模仿检索到的恶意技能，生成并再次保存带恶意载荷的新技能，形成自传播的记忆投毒；论文定义了 agent self-poisoning rate。
- 对 SCT 的启发：候选经验池和长期库都是安全边界，不能只检查危险 API，还要防止经验的错误复制和跨任务自传播。
- 建议落点：新增三个安全指标：错误经验命中率、错误经验传播率、候选经验未经门控进入正式库的比例。对经验写回做来源绑定、不可变审计和候选隔离。

### 18. Who Grades the Grader?

- 论文：Xing Zhang 等，Who Grades the Grader? Co-Evolving Evaluation Metrics and Skills for Self-Improving LLM Agents，2026 预印本。
- 链接：[arXiv:2607.12790](https://arxiv.org/abs/2607.12790v2)
- 方法特点：研究评价器本身也可能被自进化过程“投机”或退化，因此使用固定锚点集和独立隐藏集约束评价指标的演化。
- 对 SCT 的启发：D_gate 的判定器不能只用模型自己生成的评价；要保留固定锚点、独立门控集和锁定的评测协议，检查是否出现“永远通过”或只优化表面指标的退化。
- 建议落点：为质量门控保留小型人工或规则锚点集，并在正式 D_gate 之外设置不可见审计子集。

## 二 对当前 SCT 的直接改造建议

### 1. 把三步流程改成一个验证驱动循环

当前图中：

```text
D_init → M0 → D_grow 经验自进化 → D_gate 门控 → M* → 最终评测
```

建议论文表达为：

```text
R0：从已验证的漏洞—补丁案例形成初始经验
R1：检索经验、生成代码、工具验证、反思并形成候选经验
R1 内部的门控：质量检查和初步验证
D_gate：独立任务有效性与回归验证
M_t 更新：晋升、收窄、修订、降级或退役
冻结 M*：执行 Base/Plus 和多语言最终评测
```

这样 R1 和门控在概念上属于一个闭环，但 D_grow 和 D_gate 仍是不同数据集合。

### 2. R0 加入动态验证，但分清证据等级

建议 R0 每条经验记录：

```text
source_task
source_family
generated_code
functional_result
security_result
static_result
validation_backend
evidence_level
```

`evidence_level` 至少取：

```text
dynamic_functional_security
dynamic_functional_only
static_only
syntax_only
unexecutable_test
```

只有达到约定证据等级的经验才能进入 M0；其他经验可以保留在审计文件中，但不能冒充已验证经验。

### 3. 经验卡改成“安全假设”，而不是一句规则

建议采用：

```json
{
  "id": "plt-180",
  "cwe": "22",
  "trigger_context": "外部输入参与文件路径构造",
  "security_invariant": "规范化后的最终路径必须位于可信根目录内",
  "recommended_action": "规范化路径并执行目录边界检查",
  "unsafe_alternative": "只使用字符串前缀判断路径归属",
  "language_adaptation": {
    "python": "Path.resolve + relative_to",
    "go": "filepath.Abs/Rel + 逃逸判断",
    "cpp": "weakly_canonical + 路径组件比较"
  },
  "non_applicable_boundary": "不涉及文件系统路径时不适用",
  "evidence": [],
  "status": "provisional"
}
```

这会同时回应 ReasoningBank 的策略抽象、ReMe 的生命周期、A-MEM 的结构化链接和 SEVerA 的硬约束思想。

### 4. D_gate 改成三层加一层传播风险

现有三层可以保留，并增加经验传播安全检查：

```text
质量门控：经验是否完整、可复用、无答案泄露
有效性门控：独立 D_gate 上 JointPass 是否改善
回归门控：H_pass 上是否产生安全或功能退化
传播门控：经验是否在相似任务上复制错误或越界扩散
```

传播门控可以使用：

- 高相似任务集合；
- 经验命中后的失败率；
- 经验引入前后的错误类型变化；
- 错误经验复制到新经验的比例。

### 5. 增加弱点驱动的 D_grow 采样

Socratic-SWE 的方法提示我们，D_grow 不一定只能随机选择。可以先用固定的 32 条 D_grow 做正式结果，再做附加实验：

```text
第一轮失败轨迹聚类
→ 找出最常见安全弱点
→ 生成同 CWE、不同 family 的新任务候选
→ 执行验证后加入下一轮 D_grow
```

这样可以检验“经验进化是否能主动发现自身缺口”，但必须把新任务和原始正式测试分开报告。

### 6. 检索器采用渐进式路线

当前项目的 `retrieve_cards()` 主要是 CWE 匹配和词汇重合。建议保持三档实验：

```text
词法检索
→ 预训练多语言 embedding
→ 只用 D_init 训练的轻量检索器
```

第一版不建议直接训练 embedding。D_init 较小，直接训练容易只记住 CWE 或关键词。多语言 embedding 可以先验证“问题—经验”的语义检索是否比词法匹配更好；如果确实需要训练，训练集、负样本和调参只能来自 D_init，之后冻结检索器。

## 三 适合当前项目的最小实现版本

为了避免一次性把系统做得过重，建议先实现下面这条可验证链路：

```text
D_init
→ 生成安全代码并执行可用测试
→ 抽取结构化安全假设
→ M0
→ D_grow 检索 M0 并生成代码
→ 外部工具验证
→ 从成功差异和失败根因生成候选经验
→ 质量初筛
→ D_gate 独立验证
→ 回归检查 H_pass
→ promote / narrow / reject
→ 冻结 M*
```

首轮只实现 `promote`、`narrow` 和 `reject` 就足够；`demote`、`retire` 可以在有反例数据后加入。

## 四 建议新增的实验和指标

### 机制消融

| 设置 | 目的 |
|---|---|
| 无记忆 | 测量基础 Agent |
| 固定 M0 | 区分静态经验复用和持续进化 |
| append-only | 测量没有门控和淘汰的风险 |
| 只有质量门控 | 测量语法/静态检查是否足够 |
| 质量加有效性门控 | 测量独立任务收益 |
| 三层门控加传播门控 | 测量错误经验传播控制 |
| 只用失败轨迹 | 与成功加失败双通道比较 |
| 只用最终代码 | 与完整修复轨迹比较 |

### 必报指标

- D_init 动态、静态和不可执行样本数；
- D_grow 代码生成成功率、验证失败类型、候选经验数；
- D_gate 候选经验的 promote、narrow、reject 数量；
- M0 和 M* 的经验数量、重复率、冲突数；
- Base/Plus 的 Function、Security、JointPass；
- Python、Go、C++ 的同语言和跨语言结果；
- 经验命中率、命中后失败率和错误传播率；
- 每任务模型调用数、token、延迟和检索成本；
- API 空 content、超时、编译失败和 harness 缺失数量。

## 五 优先级判断

### 可以直接用于当前 SCT

1. Reflexion：结构化失败反思；
2. CRITIC：工具反馈驱动修复；
3. ReasoningBank：成功和失败轨迹的策略抽象；
4. ReMe：经验更新、收窄和淘汰；
5. A-MEM：经验链接和上下文索引；
6. SEVerA：安全不变量和硬约束；
7. EVOMAL：经验投毒和传播风险指标。

### 适合做附加实验或对照

1. Self-Refine：任务内多轮修复；
2. LATS：高风险 CWE 的多候选搜索；
3. Voyager：可执行验证技能卡；
4. MemSkill：多种经验抽取器和任务自适应路由；
5. Socratic-SWE：由失败轨迹驱动 D_grow 任务生成；
6. Memento-Skills：结构化技能文件和读写式记忆。

### 暂时不宜直接实现

1. SCoRe 的在线强化学习，需要更大规模、稳定的多轮轨迹和奖励设计；
2. 完整 MCTS 或 Agent 拓扑进化，工程成本高，且容易掩盖 SCT 的安全经验贡献；
3. 直接训练大型 embedding 或端到端记忆控制器，当前 D_init 规模不足以支撑可靠结论。

## 六 最终建议

当前最合理的改法是把 SCT 定义成一个“带安全约束的经验生命周期”，而不是一个简单的经验追加流程：

```text
经验从可执行验证轨迹中产生
→ 以带边界的安全假设保存
→ 在后续独立任务上验证
→ 根据收益和反例更新状态
→ 对传播风险进行检查
→ 冻结后进行多语言联合评测
```

这条主线可以同时吸收自进化研究中最有用的思想：轨迹反思、工具反馈、结构化记忆、效用更新、技能演化、硬约束和记忆安全。它也能让当前 R0、R1、D_gate 的调整有一个统一解释：R0 负责形成有证据的初始知识，R1 负责从新轨迹提出假设，D_gate 负责独立判断假设是否值得传播。
