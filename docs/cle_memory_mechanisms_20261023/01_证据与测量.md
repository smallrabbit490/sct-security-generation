## A03 完成检索四指标的人工作业

现成材料：`translation_work/diagnostics/20261017/cle_retrieval_q/public_contract_v2/human_review.csv`；协议目录 `configs/cle_retrieval_q_public_contract_20261017/`。914对AI初标为89 direct、385 conditional、285 irrelevant、153 conflict、2 insufficient，目前无人类确认。

人工每次看：公开题目与契约→卡片全文→卡片所需前提→可否局部应用→标签与理由。隐藏方法、排名、Q值和模型成绩。

- direct：在公开契约下可直接使用，不要求一张卡包办整题。
- conditional：需要题面未保证的前提或实质修改。
- irrelevant：不解决当前问题。
- conflict：与公开契约或技术事实冲突。
- insufficient：材料不足，待补证据；不能自动当负例。

人工标签、AI标签分别保留。可先审102、136和两条待裁决帮助理解，但原协议正式主表要求完整确认，不能把抽查当作914对已完成。改成抽样估计须另定协议与抽样权重。

统一评价池内计算TP/FP/FN/TN；所有方法用同一池：准确率=(TP+TN)/总数，精确率=TP/(TP+FP)，召回率=TP/(TP+FN)，F1=2TP/(2TP+FP+FN)。分母为零填null并说明。另报告召回阶段Recall、最终选入Recall、冲突率、空返回及任务命中率。

这些是**候选池内**指标；未标全库不能报全库Recall。旧标注的δ=0.7613717780938312，与近期Q/契约实验的δ=-1分开报告。合法复用要求题目契约、卡片正文和标签定义一致；新视图改变了信息，则旧标签不能自动转移。

现有入口：`methods/cle_ablation/retrieval_q_study.py` 的 `import-review` 和 `summarize`。执行时指定上述配置目录、已有运行区和真正人工确认的标签文件；不要调用 `retrieve` 或 `run-development` 来代替复核。本轮没有导入任何人工签名。

## A04 建立现象清单，不把症状直接当根因

每条历史尝试记录：任务/题族/CWE、公开契约版本、卡ID、召回及门槛、最终选入、声明采用、代码落实、安全动作、功能变化、F/S/Joint、技术状态、归因证据等级。采用和落实必须分开。

| 类型 | 判定所需证据 | 示例/容易误判的地方 |
|---|---|---|
| 公开契约缺失 | 测试要求未出现在允许的公开输入 | 1037、989；不能仅凭失败推断 |
| 来源假设迁移 | 来源对象/常量/环境被引入且不符合当前契约 | 截图中的替换person、新建Person；模板名重定义 |
| 模型未落实有效建议 | 适用卡明确要求保留行为，模型却违反 | 1003的卡要求保留模板，声明采用后仍重定义 |
| 经验内容不适用/冲突 | 不看生成成绩，公开契约已足以判定不适配 | 同CWE异family的对象、返回、URL规则不同 |
| 安全修复引发功能损失 | 可定位安全动作导致合法输入或功能被破坏 | 截断、过严白名单、删除正常行为；需局部复验 |
| 评价盲区 | 测试通过但未检查明确功能义务 | 907的队列副作用；“通过”不等于实现了整个契约 |
| 环境/请求失败 | 明确网络、依赖、超时等记录 | 885网络空响应不能归为记忆有害 |
| Q信用分配问题 | 给多卡同一总奖励；区分卡建议与模型落实 | 不可把坏代码的所有责任自动归给每张卡 |
| 模型波动 | 同输入重复结果与候选变化对照 | 两次代码不同本身不是Q或记忆因果证据 |

优先分析已有18损失+20救回；再加入同一次实验的全部同成绩任务作对照。38例是按结果挑出的诊断样本，不能估计全项目失败比例。保存多标签，不强迫每题只有一个原因。

**包A验收**：输入身份和分母可解释；人工复核状态如实；新样本公开契约及来源资格明确；每个已知/未知原因有记录。只缺Notion原件时，不阻断其他可做的零API分析。
