本周只推进用户11月5日确认的六项工作：公开题面下安全/功能/Joint可实现性分类、人工选已有卡的准确率上限、参考代码辅助提炼、同题同卡生成成败分析、经验对代码的归因、论文价值与完整方案。下次组会按11月11日安排，六项已直接写入[汇报提纲](reports/CLE-MEETING-20261111-v01/11月11日CLE组会汇报提纲.md)。本计划替代v01的当前排期，v01及已完成结果保留。

## 门槛怎样参照Base与Plus的历史结果？

已检查当前项目、10月16日归档、原ZIP和两份Git历史，没有找到结果Excel。找到9月6日对照论文方法的本地JSON：Python Base上AutoSafeCoder、RA-Gen、SWE-Agent、AgentCoder、SecAwareCoder分别报告Joint为7、7、6、6、9/115。现有原版性审计将这批列为早期提示适配，不能直接当作论文原始Agent。对应Plus只有partial汇总，各方法报告140条生成错误、Token为0，尚不构成有效的0%正确率结果。

因此，当前不能据这批材料锁定“本项目对论文Agent”的正式Base/Plus差距。正式差距须在同模型、同题目、同公开输入、同预算和同验证器的可比结果上逐集计算。原记录与核查结论见[门槛依据](../../results/curated/CLE-threshold-reference-20261105.json)。

已有对齐的内部有卡/无卡记录可用于校准效应尺度：Base为5→6/115，差0.87个百分点，双方各3题缺测；Plus为40→41/140，差0.71个百分点，无缺测。两项配对p均为1。这是历史内部对照，不能改名为论文Agent对照。

当前采用以下分层判断，不再给所有方向套用“至少提高5个百分点”。

|层次|判断门槛|用途|
|---|---|---|
|探索完成|固定名单、全部条件、登记阶段和两次独立重复完成；诊断项逐例分析完成|验收本轮工作，与收益是否过门分开|
|正向或负向信号|同题净救回大于0或小于0，同时列出救回、损失、重复差异和缺测|记录方向，单次净多1例也保留，不宣称稳定提分|
|临时实用效应|用较大的单题刻度0.87个百分点作投入参考；仅用于真实代码生成的Joint比较|在完整D_init303、D_grow273、D_gate298各两重复的原集分母上，净多6、5、6次分别达到该刻度；这不是跨数据集收益预测|
|正式差距目标|可比论文对照补齐后，按每集的实际差距设置：开发目标为单题刻度与半个缺口的较大值，追齐目标为整个缺口|差距为零或已领先时，另报对论文Agent的实际增量，不制造负缺口|
|方法结论|独立目标题、强简单对照、实际干预证据、配对区间和预登记多重校正齐备；Joint与成本一并解释|实用门未过不等于无效；达到实用门也不自动等于统计确认|

上表的0.87个百分点是基准不完整期间的临时尺度。论文Agent差距未核实前，不以它宣称追齐或超越论文方法。内部仅测错题时，将净救回折算回预登记的原集分母，同时报告错题子集本身的分数；不足全覆盖时不报全体上限。

## 1. 对三个D集按CLE根据公开题面对安全通过/功能通过/joint的可能性进行分类

**目的。** 分别判断CLE仅凭公开题面，是否有足够信息生成通过安全测试、功能测试，以及两者同时通过的代码。确定问题卡在安全要求、功能要求，还是二者同时满足的条件，再明确研究用途。

1. 覆盖D_init的303题、D_grow的273题、D_gate的298题。逐题列出CLE能看到的公开字段；参考答案和隐藏测试用于验证侧核对，不算作CLE已有的信息。
2. 每题分别填写安全通过、功能通过、Joint三个判断。安全维度检查安全策略、可信边界和必要条件；功能维度检查接口、输入输出、异常和环境依赖；Joint维度检查同一份实现能否同时满足两方面要求。
3. 三个维度各自使用“可按公开信息实现、信息缺失、存在歧义、要求冲突、待核查”标签，并列具体依据。判为可实现时说明实现路线或已有公开行为回放证据；安全和功能各自可实现时，仍须检查二者能否兼容。不把人工判断写成模型实测概率。
4. 复用原874题静态筛查作问题线索，逐题补齐三维判断。验证侧发现公开要求与原测试不一致时，另列冲突证据及受影响的维度。需要补充的题面另存建议，原题、原测试、历史成绩及分母保留。

**判断与交付。** 874题各有安全、功能、Joint三项分类、依据和研究用途；三个D集分别汇总每个维度的类别数量及组合分布。现有20题冲突、167题缺失、55题歧义、632题未检出阻断是原静态筛查结果，不能直接当作新三维分类已经完成。参考程序通过、公开信息支持实现、模型实测通过分别报告。

**已有证据。** [分类报告](CLE-RPT-20261105-public-solvability.md)及[逐题表](../../results/curated/CLE-public-solvability-20261105/tasks.csv)。

## 2. 人工为错题选择已有卡片，三个D集的准确率能达到多少？

**目的。** 测量现有卡库中更好的选择能达到什么Joint率，确定向量召回、候选池构造和模型终选还有多少提升空间。本项只改选择，已有卡片的正文、结构和数量保持冻结。

1. 盘点D_init、D_grow、D_gate已有全量记录，分别锁定可比的题面、模型、卡库、Q状态和生成预算，再确定错题清单。保留各集原总数、已测数、缺测数及S1的问题分类；范围覆盖三个D集的错题，不再限定为50个题族。
2. Codex为错题人工选择已有卡片，最多三张。登记两种选择：只从原检索候选池中选择，以及从同一冻结卡库全部卡片中选择。查看题面和CLE当时可见的代码、反馈；不把隐藏测试或目标题参考答案写进选择依据与生成提示。
3. 设置三个对照：A原自动选卡，B原候选池内人工选卡，C全卡库人工选卡。题面、首次初析和后续生成规则一致，每组两次独立重复、每次最多修复一次，初次与修复的选卡均遵守原边界。用于筛出错题的历史失败不充当新A组成绩，避免把正常重试救回当成人工选卡收益。
4. 先冻结人工选择和对照规格，再核算预算。复用符合条件的输入和独立成功响应；本次只更新计划，真实生成尚未派发。

**统计与判断。** 三个D集各报A/B/C的Joint、错题救回数、净收益、两次重复差异及成本；模型和题面版本分层。另报保留基线原通过结果后，人工重选救回可达到的原集诊断通过比例。该比例定义为本项的“人工选卡实测可达上限”，与全体自动运行的成绩分别列出，缺测不计作已测失败。

B优于A，且代码采用了人工换入的卡，说明终选存在可利用空间；C优于B，且救回所用卡原候选池缺失，说明候选召回存在可利用空间。S2完成后，无论收益方向，S3—S5继续按固定范围验证卡片内容和用卡生成的瓶颈。某个具体向量模型是否有问题，需要保持查询与其他检索环节一致后另作比较。交付每集上限诊断、逐题选择依据及瓶颈定位，不手工改写卡片。

## 3. 题目的ground_truth可以在CLE的流程中哪个阶段参与经验提炼

**目的。** 在原生流程已经读取来源漏洞与补丁的基础上，确定改进提炼方式的具体位置。

1. 分别核对冷启动种子提炼、来源题生成与修复、轨迹提炼三个阶段。记录各阶段实际能看到哪些公开要求、参考片段和生成证据。
2. 结合已有来源代码、S2发现的现有卡片缺口和S4—S5的用卡问题，提出提炼要求：动作方向是否正确、适用前提是否成立、合法行为是否保留。原生组和候选组使用相同来源材料；卡片内容与结构的改动归入本项。
3. 先用既有来源代码及原验证器核对动作，检查候选卡是否确实表达该动作。需要真实模型出卡或生成时，在本项内核算预算并冻结两次独立重复；本次计划更新不派发。
4. 冻结卡片后才登记不同目标题的迁移验证。D_gate参考代码只用于离线诊断，不用于生成面向D_gate的经验卡。

**判断与交付。** 分开回答“来源动作成立”“提炼器写对”“卡被采用”“代码落实”“Joint提高”。探索结果先按净救回、重复波动与实用尺度判断。后续独立确认预登记两项主要比较：新版对原生、新版对通用规则；稳定方法优势须有正净收益、题族聚类95%区间下界大于0、Holm两项校正后p小于0.05，并核查两次重复方向。统计确认不是本轮继续执行的前置门。实际采用、代码落实与配对成绩共同用于解释提炼机制。人工选卡收益属于S2，不能抵充自动提炼收益。原生提炼保持当前默认；本项所有预登记阶段及对照完成后再作整体判断。

## 4. 同一道题选了相同卡片，为什么生成代码仍有对有错？

**目的。** 从多次全量记录中锁定“同题同卡、生成成败不同”的题，找出错误原因，判断卡片结构和CLE让大模型按卡生成代码的提示词有什么优化空间。

1. 按同题号、同题面版本、同模型、同生成预算配对，再核对实际选中的卡片编号、正文版本、呈现顺序和所属阶段。主分析保留同卡条件下既有Joint通过、又有已测失败的题；使用已有全量记录，不新增全量重复。
2. 首次生成与修复分别比较。首次选卡相同只用于首次代码比较；解释最终Joint时核对修复阶段的卡片和预算。相同选卡后采用不同的记录保留，用于定位用卡差异。
3. 逐题阅读题面、卡、采用说明、计划、正确代码、错误代码和原验证证据，定位首次偏离正确实现的地方。检查卡片的动作、条件、合法行为或冲突信息是否表达清楚，并核对生成提示是否要求模型将这些内容落实到代码。
4. 分别交付卡片结构改进和用卡生成提示改进，明确每个改动针对哪种已观测错误。与检索白名单的return/raise字段问题分开登记；白名单核查作为已有流程诊断保留，不代替本项同题同卡分析。

**判断与交付。** 每个入选题给出一对或多对成败代码、最早差异及原因；区分未采用、理解偏差、计划遗漏、实现违背和修复引入错误。卡片结构和生成提示各形成有依据的修改建议。实际提分由后续同条件对照测量，不能仅以出现波动认定某个提示有错。

## 5. 经验卡的哪些内容影响了生成代码？

**目的。** 对经验影响代码做归因分析，回答哪条建议改变了哪个代码动作，以及这种改变带来什么结果。

1. 逐条建立“卡片原句—模型采用或拒绝—计划中的动作—实际代码位置”的对应，优先复用S4成败对和S2换卡记录。
2. 查阅已有同题无卡、不同卡和不同表达的对照，核对卡片内容改变时，相关代码行为是否随之改变。没有匹配对照的记录只列出已观察到的对应关系。
3. 对关键代码动作加入或撤销一次最小改动，用原验证器回放，检查该动作对功能、安全及Joint的影响，同时核对原通过行为。该回放检验代码动作的作用；卡片是否诱发该动作，由用卡记录和受控输入对照回答。
4. 按有益影响、有害影响、采用后未落实、未观察到影响归类，指出影响来自具体哪句话、哪种结构或哪项适用条件，回写S3提炼要求和S4生成提示建议。

**判断与交付。** 交付卡片到代码的逐题归因表、关键代码差异及验证结果。S4解释同卡成败原因，S5检验经验内容与代码行为之间的作用关系。先复用已有记录，新增受控生成须另有该批预算。

## 6. 如何把本课题写成一篇有价值的论文？
