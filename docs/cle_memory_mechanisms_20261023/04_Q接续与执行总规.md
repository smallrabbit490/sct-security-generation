# 包D：Q接续、统一执行规格与收尾

本文件是分包任务书。旧D02、剩余D_grow和全量D_gate仍暂停。B02共享准备及两题编排已实现；首个真实条件因格式/API故障停止，产生1份非空首次代码，末次缺测。停止原因另见08报告；这不代表下列所有付费包均已恢复。

## D01：先把旧Q工作结清，不以覆盖率代替效果

**问题**：现有Q记录能否解释“经验本身不合适”和“经验合适但模型没有正确实现”的区别？

当前已完成零API复盘：326题/503次尝试、902次卡片有效更新关联核对，403次获奖惩尝试；3个公开绑定例子旧/新分别执行，未改变正式成绩。55张卡存在同CWE异族纯方向相反反馈；仍是观察性现象，条件Q不启用。结果与边界见[10_Q奖惩归因与覆盖率复盘](10_Q奖惩归因与覆盖率复盘.md)，不是902张卡逐条质量审定。

输入：10月22日人工修订报告、18损失/20救回逐题表、在线学习的 `task_rows.jsonl`、尝试记录、选卡/采用ID及冻结库。优先使用原生阶段 summary；`results/curated/cle_q_online_20261020/reinforcement_analysis.json` 仍有早期运行中快照，不能覆盖较新的原始记录。

零API步骤：

1. 给每次尝试连接任务、family、CWE、选入卡ID、声明采用ID、实现证据和F/S；已选未用、声称使用但未实现分开。
2. 标记四种信用分配问题：好卡被错误实现而受罚；同次采用多张卡但统一奖惩；跨family适用前提不同却共享一个Q；仅排位改变带来的曝光差异。
3. 按来源family与反馈family交叉汇总：访问次数、不同反馈family数、正负更新和实际采用。明确1939张卡的主来源均为D_init，不把D_grow反馈说成D_grow新建卡。
4. 对保存了完整F/S的**训练侧**尝试做影子统计：分别列功能与安全结果，检查混合奖励掩盖了什么。只形成分析列，不回写Q，也不把观察性分项统计说成已验证的新Q。
5. 用1003等“卡片要求保留对象，代码却违反”的实例检验归因。缺少代码落实证据时填未知；不凭 `adopted` 声明认定实现正确。

产物建议：`q_credit_cases.csv`、`card_family_feedback.csv`、`q_pending_work.md`。验收：每个解释能追到原始尝试；无新训练、无从D_gate成绩反向学习。

**结论规则**：若大量失败来自消费者违反清楚的卡片约束，先修消费者；若同卡在不同family的适用性不同，提出条件化假设，但不能仅凭事后交叉表启用条件Q。

## D03：只有出现独立新依据，才安排有限Q增量对照

**启动条件**：包B或C确定了一个冻结的经验消费者，有可核对的功能安全机制证据；代码、卡片视图、任务名单和预算已固定；用户明确恢复此付费包。仅Q覆盖率上升不满足条件。若没有新依据，用既有负结果收口。

建议上限：24道D_gate、4臂、2次重复，共192次P7级任务、最多384次代码生成。使用包A预留的Q专用24族，与粒度确认24族及旧契约48题不交叉。它是项目内保留确认，须披露历史CLE暴露，不能称为整个课题从未见过的最终测试。

### 四臂究竟改变什么

| 臂 | 同一候选集合内的呈现顺序 | 最终选卡者 | Q是否更新 |
|---|---|---|---|
| Q0 | 原CLE顺序 | LLM，最多3张 | 否 |
| Q1 | 纯语义相似度顺序 | 同一LLM，最多3张 | 否 |
| Q2 | 冻结学习Q参与排序 | 同一LLM，最多3张 | 否 |
| Q3 | 同CWE内打乱 `(Q, visits)` 后参与排序 | 同一LLM，最多3张 | 否 |

Q0是原CLE有记忆方法，**不是无记忆组**。无记忆组已在包B/C测量；这里主要判断Q在相同消费者内的增量。

接线依据：`methods/cle_ablation/run_memory_q_full_gate_v4.py` 的全四臂均传 `retrieval_mode='semantic_llm'`，仅 `candidate_order` 改变；复用该接法。**不得直接用历史 `run_memory_q.py` 的Q1/Q2数值直选替代LLM选卡**。实现前检查实际调用参数，保留原选择器及原生轨迹。

共同规格：

- 冻结快照明确指定为 `translation_work/diagnostics/20261020/cle_q_online_v1/D_grow/frozen/m_star_q.jsonl`，本次核对972/1939张有反馈。它包含未完成的D_grow在线轮次，不冒称完成两阶段强化。
- 所有臂使用同一正文、状态、资格过滤和向量；Q3只置换同CWE的数值对，种子20261015，不移动正文或来源。
- `deepseek-v3.2`、thinking disabled、temperature=0、max_tokens=4096；Embedding `text-embedding-3-large`；δ=-1、λ=0.5、最多3张。λ是已冻结排序参数，不解释为LLM主观决策百分比。
- 同题同重复共享首次初析、查询、候选和余弦。重复之间独立生成并记录；修复轮允许因本臂代码而不同，不能要求修复候选也强行一致。
- 不向LLM显式增加Q数字解释或新提示词；该变化若要做，应单列未来变量。
- 若消费者是原P7：首次Joint通过即停，否则最多一次修复，交付末次代码；若选用了契约消费者：所有臂都采用其冻结的公开选择规则，并另命名协议，不能仍声称交付规则与原P7完全相同。
- 先跑名单前2题完成技术验收，计入24题而不是额外挑选。技术错误停后续；模型产出错误仍如实计分，不能按失败成绩重试。

### Q比较与门槛

主要比较Q2−Q1、Q2−Q3；Q0作为原项目强参照，同时报告。逐题先查“同查询改排序→改成员→采用→实现→F/S/Joint”，不能只查排名。

建议工程信号门：两项主要比较Joint均提高至少5个百分点（48次配对至少净多3次通过），两次重复方向均为正，F与S均无下降，且至少2个不同family存在可核对的救回路径。该门槛不等于显著性。

确认推断按family为区组，重复观测不冒充独立题：报告救回/损失、配对差和按family重采样95%区间；使用family内配对置换检验，两项主要比较Holm校正。两项差均正、校正后p≤0.05、且机制链成立，才写“本协议下支持Q增量”。只过工程门或点估计正，写“方向性信号，证据不足”；不追加题或改阈值救结果。

如果消费者、名单、重复、候选与快照任一条件不同，旧Q0/Q1不能自动复用。只有逐项一致的原生运行才可复用；否则在预算中完整列入。

## D04：全任务统一测量和产物

### 与原CLE四个Phase的关系

| 原项目阶段 | 原作用 | 本任务的对应方式 |
|---|---|---|
| Phase 1 / D_init | 初始经验构建 | 读取已形成的1939卡和合法来源例子；不重新蒸馏 |
| Phase 2 / D_grow | 生长任务、反馈和经验演化 | B/C借用D_grow作方法开发，卡库与Q冻结；小分类器训练不等于重跑CLE生长或微调LLM |
| Phase 3 / D_gate | 训练侧审计、筛选与门控 | 新24题对照属于项目内确认/审计，禁止用这些成绩更新Q或训练分类器 |
| Phase 4 / Base/Plus | 冻结后的独立外部评测 | 本任务不启动；在D_gate冻结Q也不自动变成Phase 4 |

任务包的A/B/C/D是工作板块，不能与原项目Phase 1–4按字母逐一等同。旧D_grow剩余250题是在线Q学习；新B/C的D_grow任务是冻结记忆下的对照，两者不混写。

原检索方案的R-query/R-threshold也保留在待办：先完成914对人审，再复用原协议6题校准记录选R*；按候选池F1至少+5个百分点、任务命中不降、冲突率不增的原门槛判断。缺少的召回响应不自动重发Embedding；不与粒度及Q同时调参。若本轮先研究呈现机制，检索设置保持δ=-1并声明与旧检索方案不同。

### B/C默认执行参数

复用旧CLE：`deepseek-v3.2`，thinking disabled，temperature=0，max_tokens=4096；`text-embedding-3-large`；δ=-1，LLM最多选3张，Q不参与B/C的排序且不更新。首次按原候选顺序选择，固定后才渲染视图。运行次序种子20261023。若需要更换模型，另立协议与基线，不能沿用当前模型的效果数字。

B/C只改变指定经验视图，其余公开题面、初析、P7验证器和反馈许可保持一致；首次和交付两套成绩并列。公开契约检查只用于准备或单列干预，不能在某臂额外加入新的修复反馈。

### 测量口径

| 项目 | 主口径 | 易混淆之处 |
|---|---|---|
| F / S / Joint | 同一份交付代码的功能、安全、两者同时通过 | 不把两个不同候选的F和S拼成Joint |
| 四状态 | F+S+、F+S−、F−S+、F−S−，另列缺测 | F−S+只是现象，不能直接定性过度防御 |
| 机制 | 首次查询成员变化、声明采用、代码实现、约束违反 | 声明采用不等于实现；有卡变化不自动等于成绩变化由卡导致 |
| 检索四指标 | 人工确认的共同候选池内Accuracy/Precision/Recall/F1 | 不是全库召回率；AI初标与人工结果分表 |
| 分类器指标 | 档位预测、合格集合命中、相对固定策略的Joint/成本 | 不与题卡适用性四指标混成同一表 |
| 覆盖率 | `q_visits>0`卡数/1939，另报不同反馈family数 | Q=0可能已经更新；更多覆盖不等于更准确 |
| 成本 | 各阶段请求数、输入/输出Token、Embedding、重试和未知用量 | 没有账单依据不能称实付费用；历史预算不是实际消耗 |

历史914对标签只能评价相同题目—卡片正文。新功能/安全视图与粒度文本改变后，若要声称其检索或适用性变好，需要对应的新盲评标签；不直接继承旧标签得出改进结论。

### 文件格式

当前联合准备配置位于`configs/cle_memory_mechanisms_20261023/`，含名单、预检、共享准备与分析入口；功能/安全视图、离线足迹及两题真实P7编排已实现。原始输出通过`translation_work/diagnostics/20261023/cle_memory_mechanisms_v1/`映射至E盘。L0–L4渲染及原P7函数接线已实现，仅两卡两组绑定/20份预览；粒度付费编排、真实成绩和分类器未完成。预览、共享准备与故障终态均不能当作合格模型配对运行。

沿用原生 `rows.jsonl`、`attempts/`、`generation/`、`validation/`、`retrieval_trace`；新增文件只承担本任务需要：

| 文件 | 必备内容 |
|---|---|
| `manifest.json` | 数据/题族、任务与重复、冻结快照、协议/代码版本、预算、分支 |
| `views.jsonl` | card_id、视图/级别、来源及公开适用前提；不含目标答案 |
| `pair_cases.csv` | task_id、family、repeat、arm、交付代码、F/S/J、错误多标签、选卡/采用/落实证据 |
| `metrics.json` | 计划数、完成数、缺测、各臂F/S/J、配对结果、阶段门 |
| `cost.json` | 初析/视图制作/标注/各臂/Embedding请求和Token，失败用量 |
| `decision.md` | 通过/停止/不确定及对应证据，未执行项 |

不要擅自把原生runner的字段替换成新结构；新表用任务、重复、臂、尝试、卡ID关联。最终精简表放 `results/curated/`，原始记录保留运行区。

### 实现接口和最小验证

实际复用点：`context_pipeline.py::experience_text` 当前只注入白名单字段；新增视图必须显式接入，不能只在卡JSON加字段。`run_context_pipeline` 保留首次共享初析、采用ID和反馈边界；`semantic_retrieval.py` 保留召回/排序/LLM选择；官方F/S验证器继续使用原实现。

最低离线检查：固定card_id下视图切换不改任务；目标答案/隐藏测试不进入视图和分类器；对照首次候选一致；Q快照评测后不变；原P7最多一次修复与末次交付正确；指标零分母为空并给原因；同family不跨新训练/验证；停止门失败不再调用付费模型。不得以开发便利重新写一套F/S验证器。

收尾按原项目“规格→实际执行→配对成绩→逐题解释→成本→未执行/停止原因”写中文报告：

- 拆分有益：说明相对混合经验改善的是何种功能损失，不能只报平均分。
- 固定粒度有差异但不可预测：保留较好的固定策略，停止分类器。
- 分类器不优于固定档位/简单规则：报告路由增量未建立，不用训练准确率替代下游Joint。
- Q只改选没有结果收益：保留机制介入证据，写稳定收益未建立，终止当前Q扩展。
- 缺原始文件或数据/技术门不满足：报告缺项及已完成部分，不伪造失败成绩。

本任务包不恢复剩余250题D_grow、不进行D_gate在线Q更新、不启动Base/Plus、新版CLE、MASE或全库重建。未来有明确新授权再更新具体包；旧结果、用户修订Word和原始数据均保留。
