# CLE主线与实验互引报告模板

周报格式于2026-10-27更新为[周报模板v02](CLE-TPL-weekly-experiment-report-v02.md)及其[Word版](CLE-TPL-weekly-experiment-report-v02.docx)。本文件保留为历史阶段报告模板，不再作为新周报的默认版式。

用途：组会、阶段总结与研究接续。正式报告保持实验报告语言，不写成讲稿。每份报告固定截止时间，后来新增结果放新版或独立进度页。

## 阅读结构

报告顺序固定为：**研究主线 → 要求快捷回答 → 综合分析 → 实验验证 → 数据与来源**。第一页说明主线、总判断和阅读方式；主线句子、快捷回答、实验均有稳定ID。

Word使用内部书签链接；网页使用同页锚点；Markdown使用显式锚点。三种版本引用同一份正文。点击“验证E01”进入对应实验，实验末尾可返回主线M01、要求R01、实验目录。网页支持在页内搜索，不要求启动工作台。

先用一小段解释本报告必要的缩写和读表方法；首次出现的新概念就地解释。主线和快捷回答使用完整句子，让读者不打开实验也能掌握当前结论。

## 一 研究主线

<a id="m01"></a>
### M01 一句可检验的主张或问题

写清自变量、结果和适用条件。例：在固定经验库与同一生成流程下，Q参与排序能否提高最终交付代码的Joint。

验证：[E01 对照实验](#e01)——检验最终结果；[E02 机制实验](#e02)——检验中间路径。**当前判断：** 已支持 / 局部支持 / 未建立 / 尚未检验。不能用“实验做完”代替“主张成立”。

## 二 要求快捷回答

<a id="r01"></a>
### R01 谁要求解决什么

**直接回答：** 先给一句可用于决策的回答。**任务来源：** 老师 / 学长 / 用户的具体要求及转述性质。**依据：** [E01](#e01)。**对主线影响：** 回到[M01](#m01)。

重复这一结构覆盖每项真实要求；不把尚未执行写成否定结果。

## 三 综合分析

综合多个实验回答：目前最强的证据是什么、哪些解释被区分、哪些仍混杂、主线应保留或收缩哪一部分、下一项完整验证是什么。每个判断链接到实验，而不是再抄一遍全部成绩。

## 四 实验验证

<a id="e01"></a>
### E01 实验名称

来源：[主线M01](#m01) · [要求R01](#r01)。登记ID、协议、模型、经验/Q状态、数据版本、统计截止时间放在内容中。

#### 1 实验目标

明确回应哪句话。本实验把该句中的概念怎样操作化：如“选卡改变”指卡片ID集合变化，而非只改变显示顺序；“正确率提高”指同一交付代码Joint增加。

#### 2 实验内容

对象与分母、对照条件、实际改动、共同固定项、生成/修复预算、统计方法。题目、family、重复、尝试和HTTP分开。

#### 3 实验结果

先给最关键的完成/计划和对照差值，再给必要F/S/Joint、缺测、机制记录与成本。图表放在所属实验内。区间或检验按原协议注明，不跨实验拼总率。

#### 4 实验分析

- **回应来源：** 对M01/R01支持到哪一层；明确写判断及原因。
- **可信度：** 分别说明覆盖完整性、归因控制、可推广范围。不编“可信度90%”，也不把p值换成主张成立概率。
- **局限与替代解释：** 只列当前真实影响解释的限制。
- **主线影响与下一步：** 因该结果保留什么、不能宣称什么、下一项固定验证是什么。
- **原始证据：** 指向报告、manifest、rows或复核记录；缺原始记录时标记仅复用原报告。全文重组不默认进行了新的逐题复验。

## 可信度用语规则

| 判断 | 可表达的含义 |
|---|---|
| 已支持 | 在明确条件内，该层主张有直接对照或可核对事实支持 |
| 局部支持 | 有具体案例或有限样本信号，尚未支持总体或因果推广 |
| 未建立 | 做过对应比较，但现有结果不足以支持预定增益 |
| 尚未检验 | 所需实验、人工标签或验证环境仍缺失 |

可信度必须紧跟**哪一项主张**。同一实验可对“确实执行/改选”有较强证据，而对“稳定提分”证据不足。全量优先原则不改变：技术探针不按成绩取消既定全量，报告必须如实呈现全量负结果。
