# 历史消融与对照实验总统计：哪些方法值得保留

核验日期：2026-10-13。统计对象为目前仓库内可找到的实验记录。本次新增模型调用 **0 次**，没有重新执行生成代码，没有更新经验库。

## 一、先说结论

**当前最值得保留的原型是“接口保护＋经过质量检查的 M1 代码示例”。** 接口保护就是先明确函数名、参数、返回值、异常和合法输入行为，避免安全修改把正常功能破坏；M1 是给模型看其他训练任务的漏洞与修复片段，帮助理解具体修法，绝不提供当前待测任务的答案。

这是一项优先保留的候选，尚不是已证明稳定有效的最终方法。最新确认集上，该组合由无记忆的 17/50 提升到 22/50；逐题看，救回 9 题、丢失 4 题，净增 5 题，但精确配对检验 p=0.267，证据仍不足以排除随机波动。它还使 6 道原本功能通过的题功能失败，说明总分上升不代表没有副作用。

有更明确统计信号的是提示词矩阵中的 P13 和 P22：在本地 Python Plus 140 题上，分别由 28 题提高到 43、42 题，经全部 72 次比较校正后仍有差异。不过它们还改变了经验字段呈现，不能把收益完全归因于某一句话，也没有证明能直接迁移到最新 M1 原型或其他语言。

**复杂架构、记忆自我修订、语义检索和扩大经验库，目前均未显示出稳定、可独立确认的优势。** A7 有价值的部分是“先在开发集比较流程，再冻结后确认”的实验组织方式；当前并没有证明完整的自动架构搜索或成功的记忆自进化。

## 六、旧矩阵中影响结论的实施问题

### CLE 的标签不等于模块真的被关闭

`methods/cle_ablation_matrix/run_training_matrix.py` 的 `command_for_arm` 只映射了部分开关，包括上下文流程、前次证据、内部检查、分支数、修复次数、检索模式、反过度防御和门控模式等。analysis/planning/codegen/extract/repair/replay/retrieval/distillation/reanalyze_after_retrieval/failure_evidence/hsk_tree/quality_gate/independent_validity/h_pass_regression 等设置没有按标签传入；其中还被排除在 unsupported 提示之外。

核对保存的实际启动参数（忽略输出路径、恢复路径和并发）发现以下组完全相同：

- C2-4、C2-5

- C2-A2、C2-B1、C2-E0、C2-I0、C2-R1、C2-T1、C3-2、C3-3

- C3-0、C3-1

因此，C2-4/5不能证明HSK树是否有效，C3-0/1不能证明质量门控是否有效，C3-2/3不能证明H_pass回归门控是否有效。参数相同而分数不同，应视为不同运行产生的波动或状态差异，不能作为模块消融。

24组分别和自己的无记忆对照比较，48次配对经校正后均没有显著差异。不能从不同组分别挑H_pass最高73、Base最高8、Plus最高37拼成一种“最好方法”。C2-A0、C2-B3、C2-I1没有完整冻结评测，排除完整结果表。

C3-3冻结库3896张卡，其中3890张 provisional、6张 retired、active为0，来源为 `cle_runner_freeze_tree`。它不能被表述为“3896张都通过严格门控的有效经验”。

### C2-A1 的外层结果有序列化错误

C2-A1 H_pass 的300条外层记录全标成未测/失败，但内层保存了297条实际测试，F/S使用字符串pass/fail。本次从内层恢复，得到F90、S195、Joint66、可测297，与当时summary一致；记录297条外内不一致，保留原文件不改。不能把错误外层读成“算法0/300”，也不能假装原JSONL没有问题。

### 40题 oracle 实验不能证明可部署记忆有效

无经验5/40，旧检索经验1/40，直接提供当前题官方参考答案25/40。旧检索相对无经验0胜4负，双侧精确p=.125，旧文档用近似z=-2称其“显著负作用”不成立。

提供当前题答案确实大幅提高结果，但它改变了信息可得性，属于答案可见诊断，不能证明其他任务的示例有同样收益，更不能认定“粒度是唯一根因”。应保留这个诊断，撤回过强因果结论。与最新M1允许使用其他隔离训练任务示例的条件不同。

### 不应计入方法有效性统计的结果

- 原生命周期15个候选全被降级，没有经验晋升，不能写成自进化成功。
- 回放和失败字段A/B检查主要验证代码链路，不是效果消融。
- 09-28 P0–P7中断运行仅有PLT105/2384、Base14/920，并存在容器池互删环境事故，不当作完整成绩。
- 参考实现校准115/115、140/140是在检查验证器，不是模型生成成绩。
- 09-06三个模型的全量Base记录来自旧单提示适配器，不能冒充五条官方Agent流程。真正Agent冒烟每方法只有1题，Prompt每方法2题，均0，不能据此排名方法优劣。

## 七、接下来应该保留什么

| 判断 | 方法 | 理由与边界 |
|---|---|---|
| 优先保留原型 | 接口保护＋合格M1代码示例 | 新旧确认都呈正向分差；最新22/50；仍有功能伤害且未统计确证 |
| 吸收为设计原则 | 保持合法输入功能＋明确安全检查项（P13/P22） | 提示词矩阵Plus有校正后信号；融入M1后的组合收益尚未验证 |
| 保留为实验程序 | A7开发筛选→冻结→新确认 | 减少仅凭开发最高分选方法的风险；不是自动搜索涨分证据 |
| 保留工程收益 | 检索协议修复、层次检索减少调用 | 可靠性与效率有价值，不能写成准确率提升 |
| 暂不作为默认步骤 | 多角色审查、先检查再修、多个候选再选 | 目前没有超过简单M1流程；可能修坏或选错 |
| 保留研究备选 | M3草稿后检索、M4反例修订、训练侧验证反馈 | 有局部信号或合理机制，但独立迁移证据不足 |
| 尚未验证 | 完整MemRL效用学习、跨语言M6、成功记忆自进化、完整自动架构图搜索 | 不能用原型名字代替实际实现和有效性证据 |

当前可以向组会汇报的是：**保功能与具体代码示例是最值得继续保留的方向；复杂架构还没有带来稳定额外收益，主要瓶颈暴露在检查是否正确、选择是否可靠、来源示例能否迁移。** 不能汇报成“十三个方向全部完成并验证有效”，也不能把它们全部判无效。
