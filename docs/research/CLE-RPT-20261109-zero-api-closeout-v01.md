**本轮已完成既定证据范围内的零API补全：全量核对874题分类并关联历史记录，整理54题选卡过程，审计50份来源阶段材料、13组逐建议对应和50例归因材料；重新验证37份旧代码变体，并对新找出的4份失败代码完成最小修复回放。新增模型与Embedding请求为0。**

最有用的新结果是：原基线失败的4道题，在相同初析下，原候选池内的其他卡片组合曾伴随首轮Joint通过。逐份代码核查后，3道失败由宿主配置重新赋值造成，1道由多加必填形参造成；按公开context和接口做最小修改，4道均恢复Joint。扣除旧清单中的813，本次增加3道代码诊断救回，历史与本次去重后共22道。它们测量代码错误的作用，不是卡片提炼方法的提分。

用户撤回的付费批准继续生效；旧守护不恢复，排队全量跳过，原冻结题面、卡片、规则、条件、重复和验证器保持。原始记录和旧结果不覆盖。本轮也没有调用其他AI、联网搜索或新建付费运行段。

## 4. S3：来源阶段可以零API修正什么？

50份冻结来源中，36份直接成功、4份修复后成功、10份持续失败；保存的来源行全部存在。4份修复成功材料将修复后的A状态写在失败类别标题，同时把修复前失败放在未标阶段的证据块中。对应题为1018、1021、1027、1364，逐题依据见阶段矩阵。

本轮为每份实际命中的材料保存了仅补证据阶段标签的离线提示稿，原始证据、其他指导和正式冻结输入均不改。它解决“读者无法区分前后证据”的具体表达缺口；模型尚未读取这些稿件，不填写提炼质量或Joint改善。

86份定向参考检查中60份通过已列断言，26份有公开行为反例。参考质量检查与提炼比较分开：参考通过原验收不担保符合全部公开行为；定向26/86不外推为全库缺陷率。G0保留冷启动本就能够获取的来源GT，本线的未测问题是额外把参考放进轨迹提炼或复审的效果。

## 5. S4：哪些成败对真正共享了输入？

登记的当前五组为497、880、994、1023、1152。497与1152初析相同；880、994、1023初析不同。另有早期6组和10月26日2组，共13组历史材料，不能全部称为完全相同输入的重复实验。

实际读取10对经验复析journal：5对提示与设置完全相同，涉及497和1152，返回内容不同；其余5对提示不同，设置相同。核对的是经验复析阶段，不能据此声称整条规划/生成请求也相同。不同返回提示不能仅靠temperature=0假定流程稳定。

13组168条语义建议的引文全部在对应实际卡文中找到，0处不匹配；它们已与采用、计划和实现观察一一整理。标准库反例还核实了12项事实，包括dict子类、Mapping、str.replace、URL主机与参数、非法百分号、正则尾换行和AST输入等。由此可以将错误API解释、适用条件错误、计划漏实现和验收遗漏分开，不能由整卡采用标记推导建议已经落实。

## 7. S6：整理后能写出的强结论

**第一，原Joint通过与公开契约正确存在可复核的差距。** 全量分类、20题冲突、来源参考反例和行为控制支撑这一判断。

**第二，候选池并非所有失败的唯一瓶颈。** 原候选池内已有4个同初析、其他选卡条件首轮通过的具体实例；逐代码检查后，失败集中在宿主配置覆盖与额外形参。现有记录同时保留了检索、复析、计划和实现之间的区别。

**第三，局部实现错误可以凭公开信息修复，但其与经验输入的因果关系尚未测量。** 新4例均经原验证器确认；旧代码修复不能代替改卡或提炼方式的生成对照。

**第四，经验来源事实与阶段证据需要各自核对。** 参考的公开反例、复析中不成立的API解释和4份来源阶段标签混用均有实际材料支持；这些缺陷提供改进目标，没有直接给出改进后的Joint增益。

已归档的论文Agent资产核查仍未建立可用Base/Plus差距，本轮没有把旧Plus生成错误的0或简化Agent分数当作正式对照。当前能组织的是实证诊断和机制证据，方法提分主张继续列为未测。

### 留出材料接触怎样处理？

本轮4例中，813属于开发名单，1218属于冻结H50。1218的历史成功代码和本轮诊断已经可见，此接触明确登记。原方法规则与H50名单均未修改，本轮没有新H50模型成绩。以后若依据本次新诊断修改方法，1218及相应近邻必须按实际设计接触处理，不能称作未接触的独立盲测；本次不擅自换题或扩大实验。
