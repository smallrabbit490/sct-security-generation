双侧Fisher精确检验（小样本列联表的概率检验）为 **p=0.217639**，没有通过路线图规定的“OR至少3且p≤0.10”提案门。OR（比值比）因救回侧零格而为无穷，不能仅因OR大就判定有可靠信号。去除两个至少一侧未完整测量的历史配对后，剩36例：损失侧1/17、救回侧0/19被标记，p=0.472222，同样不通过。

另行记录公开题面可预先识别的特征：明确外部绑定见于损失侧1003、1037、989三题，即3/18对0/20，未经多重校正的探索性p=0.096728。它只涉及三个历史案例，没有独立验证，不能据此发明并启用Q阈值；签名可解析在38例中全部为真，也无法区分救损。当前路由因此冻结为关闭。

上述结果**不否定此前13道重定义错误的代码证据**。PR #5静态检查只覆盖公开题面明确可识别的约束，不能把“未标记”写成“代码正确”。此外，静态flag本身来自生成后的代码，禁止将其直接作为生成前路由输入。

## 实际实现与验证

1. `joint_contract.make_provider`显式接收并传递 `candidate_order`。`similarity`与`q`均走原 `semantic_llm`，仅改变呈现顺序，最终仍由LLM选0至3张；不能用直接数值top-k的 `semantic_q`冒充旧Q2。
2. 新消费者可接收外部已经冻结的公开suite（内部用例集），即使是空集也不会重新生成；两新臂共享同题同重复的suite及首次初析。运行时核对首次查询、召回成员、余弦一致；修复轮分别依自己的代码与公开反馈继续。
3. 路由只使用明确绑定、签名、候选visits比例、负Q比例、最大visits、排序位移六项生成前特征；不接受Joint、代码、采用或隐藏测试字段。当前 `enabled=false`，入口自动移除无实际差异的条件Q臂，避免多花钱重复同一个消费者。
4. 复用原预算控制、正式验证器和公开修复交付规则；补齐embedding分项上限及按family汇总的配对筛查输出。旧P7默认行为及旧成绩不变。

**220项相关离线测试通过，0失败、0跳过。** 测试包含真实本地公开用例执行、Q排序确实改变选中卡号但仍经过LLM、公开查询不带隐藏字段、关闭路由与相似度提示一致、共享suite/c0初析、预算阻断和阶段门；模拟模型响应的测试仅是工程验证，不是新模型性能证据。
