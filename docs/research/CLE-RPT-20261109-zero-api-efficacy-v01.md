# S1—S6零API工作的研究效力评估

**结论：本轮零API工作形成了题库契约诊断、来源参考反例、同卡成败解释和局部代码修复证据；尚未形成新版提炼、人工选卡或生成提示提高Joint的实测证据。S1的分类任务已完成，S4、S5的历史诊断最接近可检验机制；S2的核心数值问题未回答，S3完成了来源审查与阶段设计，S6形成了论文方案。**

评估日期为2026年11月9日。本周范围从11月5日开始。新增模型及Embedding调用为0；旧模型生成记录的复用、本地验证和人工代码修改分别计量。用户已撤回刚批准的S2筛错和S3来源批预算；撤回时无运行段、请求账本、预算批准文件或活动实验进程，没有在途请求。本轮保持零API，排队旧全量继续跳过。

## 1. 怎样判断零API工作的效力？

按能回答的问题分四层：公开材料是否存在缺失或矛盾；已有代码从哪一步出错；改变一个代码动作是否改变结果；改变卡片输入或提炼方式是否让模型生成更好的代码。前两层可以通过材料和历史记录直接研究，第三层可以通过最小修改和原验证器回放研究，第四层需要对应的模型生成记录。

本次评价研究证据，不将测试数量、运行器数量、已冻结单元或文档篇幅计作科学成果。完成性与效力分开：完成了一项历史诊断，可以提供有力局部结论，同时仍未完成原计划的新方法比较。

## 2. S1已经回答了什么，分类的强度到哪里？

|安全|738|29|88|19|874|
|功能|497|114|262|1|874|
|Joint|461|130|263|20|874|

最有用的结果是把“公开规格不足或矛盾”与“模型没有实现已知要求”分开。例如423、424的公开异常要求与安全测试返回要求冲突；1391的公开矩阵输入与验收数组形式不符。这些具体矛盾可以逐项核查，能改变对失败原因的判断。

130题缺信息和263题存在多义，不等于这些题的所有程序都不可能通过有限测试；461题也不是CLE的最高正确数。不能把461/874当作Joint上限，不能据分类直接删除其余413题，也不能把人工补过接口后的通过归功于模型。

分类表完成了全量覆盖，11月7日独立于原汇总的语义复核只抽查了12项，未形成第二套完整标签或一致性测量。因此，全量标签适合作为有逐题证据的诊断分层，不能称为874题均经独立双重确认。原S1报告中“名单待采用”的过程状态已被后续采用记录取代；当前三角色各50题、实际近邻18/19/19，不能沿用旧过程文字判断当前状态。

## 3. S2的零API工作为什么尚未回答选卡上限？

当前54道复用题中Joint23、未Joint31，23/54描述这一批原结果。完整874题的当前Flash筛错缺820题，完整错题名单W尚未形成；A自动、B候选内人工、C全库人工三组新生成均未执行。

阅读题卡可以判断适用性，历史通过代码可以展示一种已有解法；二者均不能给出“人工重选卡之后模型会通过多少题”。历史失败题按新条件再生成还会受到重复波动影响，因此原失败记录不能直接充当新人工组的独立自动对照。完整W与人工可达率目前没有数值答案。

已整理的卡库目录、信息白名单和选择决定格式减少了后续准备成本，但它们不证明向量召回差、不证明大模型终选差，也不证明人工一定能提高Joint。没有额外生成时，本线应交付适用性与覆盖诊断，保留可达率问题未测的状态。

## 4. S3真正得到的是来源质量结论

定向检查86份来源参考，60份通过已列出的检查，26份出现公开行为反例。26份中25份原参考通过过原验收，另1份命令参考只做接口与词法检查。这证明原Joint通过不能逐条担保来源经验的正确性；26/86来自定向检查，不能当作整个题库的错误率，60份通过也只覆盖已检查行为。

50份来源、M50和H50各保留50题，实际近邻18/19/19，角色间无近邻交叉。M50有24题共享来源安全动作、18题共享局部操作、8题空来源槽；42题对应9个来源事件。它们是已审查的研究材料与对应关系，不是新提炼收益。

原生G0保留了CLE冷启动对来源GT的既有使用。因此本线应回答“来源参考额外进入轨迹提炼或复审，哪一处更有用”，不能把整个方案写成首次让CLE接触GT。普通复审还必须与参考辅助复审分开，以免将多一次检查的收益归给GT。

当前来源500次调用、M50的500个代码单元及H50的300个代码单元都未执行。没有本周新版卡片质量对照，没有最佳阶段排名，也没有提炼方式的Joint增益。参考错误与阶段证据混杂是已定位的缺陷；修复这些缺陷能否让模型更好，仍是另一个问题。

## 5. S4找到了生成链路中可以具体检查的问题

13组案例并非13份完全相同输入的重复实验。其材料由当前5组、旧6组和10月26日2组组成；其中119、1361的初析不同，单列为同卡、不同分析。39份视图、32份代码和168组人工语义建议不能当作独立样本相加。

已定位的问题包括：497额外允许未要求的内容类型；1023、1013覆盖宿主数据；1125、1383的AST节点检查使后续合法运算不可达；1150误用isinstance的类型参数；密码题把正则花括号再次交给字符串格式化；模板题错误绑定宿主模板或参数。这些判断有原卡、计划、实际代码与回放的对应。

它们支持的直接结论是：检索到正确主题的卡以后，接口适配、计划具体化和代码实现仍是独立失败环节。卡片也可能包含错误API解释、来源字段名和来源常量；“来源成功经验”不能保证每句解释都正确。

880的消息长度修复使用了成功代码中的数值，该诊断依赖答案可见信息，不证明公开题面提供了该值。994的单次替换修复则在原Joint保持通过时补足两项公开行为检查。这两种证据分开保留。P0/P1/P2三组300个新单元未执行，尚不能说改结构或改提示能够提分。

## 6. S5最强的结论来自局部代码干预

|证据|真实范围|可得结论|
|---|---|---|
|原代码回放|50份有原生证据，49份复现历史Joint；1105同码当前通过|当前与历史测量条件会改变结果，应先检查环境再谈方法收益|
|局部代码修改|31道旧题、37份变体，其中35份纠错、2份不利方向反例|可检验具体动作对当前行为和验收的作用|
|救回与回归|19道原失败各有修复变体恢复Joint；10道原通过接受有效纠错后保持Joint|这些已定位的局部错误可修正；不代表模型换卡后的通过率|
|宿主配置覆盖|11份代码、6个近邻组；10份原失败仅撤销顶层赋值恢复Joint，另1份原通过恢复合法字段行为|错误重新绑定宿主配置是跨接口复现的具体失败机制|
|原验收遗漏|两份不利方向变体损坏对应公开行为，原Joint仍通过|Joint需要与所研究的目标行为一起检查|

19道救回来自经过定位后选择并修改的旧失败代码，不能报成新模型Joint提高19/50、19/874，或普遍100%修复成功率。163、166的字段层级修复用过夹具信息，属于答案可见诊断，不能当作公开信息足够的证明。

现有证据能确认“修改代码动作改变了这些程序的结果”。要确认“经验中的某一句导致该动作”，还需要固定题面、其他卡及生成预算，只改变相关卡文后观察生成。E0/E1/E2的300格和补充E3/E4的200格均为0个新生成结果。

11月9日已修复补充材料与实际调度：200格覆盖50例、29近邻，两重复；105份卡视图修改、39份不动，共387处字段编辑。按语义分为13例“动作及其限定”和37例“动作及支撑信息”，没有一例被宣称是纯动作独立消融。此前按字段位置分的11/39不能继续解释为纯动作与解释效应。

这些材料修订和27项封网测试证明了相应接口、恢复与收尾路径可用，正式实验结果仍为0。材料审查复用了此前完整卡文审阅，并新增审读全50例动作与实际删除片段；没有新一轮144份全文盲审的主张。

## 7. S6目前应当怎样概括贡献？

可以写出的核心认识是：**原验收通过不足以担保公开契约和来源经验正确；经验进入生成后，实际采用、计划落实与代码实现会分离；宿主配置覆盖等具体错误可通过最小代码干预复现和修正。**

这些结果可支撑契约审计、来源质量和经验消费失真的实证材料。当前尚不能写“新版提炼使Joint提高若干个百分点”，也不能写“已经优于对照论文Agent”。论文Agent身份与有效外部环境、可比Base/Plus结果及新方法独立验证仍有缺口。论文提纲和运行器不会填补这些科学缺口。

S4与S5使用部分共同历史材料，不能将两者重复相加成独立验证。已有分析对本轮规则设计有实际作用；参与过分析的题及近邻作为开发材料，后续泛化主张需要另有依据。论文目前最扎实的材料是可复现缺陷及其机制，方法优越性尚未建立。

## 8. 对投入和下一步的判断

继续增加通用运行器、冻结记录或说明文档，对当前核心科学问题的信息增益已经很小。本周零API工作的效力集中在S1的契约诊断和S4/S5的代码机制；S2/S3的工程准备投入没有转化为它们要求的定量答案。

在不调用API的条件下，最有价值的收尾是复用现有资料形成一张机制证据表：每条结论绑定公开依据、原卡句、计划、错误代码、最小修改、原验证器结果和适用范围；将依赖隐藏接口或成功代码值的诊断单列，避免将其作为通用提炼规则。这里只给出研究优先级，不增加题目、改动冻结规则或启动任何新实验。

若未来重启付费，应由一个具体机制及其尚缺的证据决定最小对照。当前最强候选是宿主配置重新绑定；这说明它值得优先检验，不构成已经有效的提炼方法，也不改写原固定实验范围。
