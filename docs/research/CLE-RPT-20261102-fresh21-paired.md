# 历史经验能否让四次检查比四次通用检查发现更多独立错误？
  
**本轮决定为停止进入修复实验。** 经验检查独有的真实发现全部集中在车辆字段更新。多个登记题族重复了同一个错误机制，未达到至少两种机制的条件。

从两批已完成实验的105个登记题族中，排除前期30个开发或验证题目的题族和别名，按公开题面选取21个新题族（20%），涵盖5类机制。每族固定一题，五条件各两份旧输出。查看本批代码前已保存名单、来源卡、两组各四个输入、判错方式和脚本。复用210个保存单元，其中209份有代码，1份原输出为空。按209份有效代码计算，每组836次检查。受本地标准库导入限制的单元按原检查补跑，原始记录保留。没有模型或向量调用。

题族口径先合并一个题族的全部输出。只要两组各在该题族发现过真实错误，就计入共同发现。因此，一个题族可以有仅经验命中的代码，同时在题族统计中归入共同发现。

**经验组**改变题面提供的允许更新字段列表。例如宿主本次只允许更新车主，代码却在模块加载时用自带的固定名单覆盖了宿主名单，导致合法更新被拒或未授权更新获准。这个检查命中五个车辆题族，其中四族完全由经验组发现。冻结卡 seed-1053 支持按允许名单逐键过滤，具体的“更换宿主名单”也能从题面直接推出。结果证明这个检查有效，无法证明历史卡是想出它的必要条件。

**通用组**用合法域名、合法路径构造最普通的成功请求，在三个URL题族发现代码忽略宿主配置、错误拒绝请求。共同发现的代码来自车辆字段更新和两类签名验证，后者可用已登记签名复现。例如代码自行将签名表清空，正确签名也查询失败。

**误报**单列。两组各在21份公开输入的最小正确对照上运行84次，均为0/84告警。检查旧代码时，经验组另有6份因安全计算abs(2)而告警，涉及两个允许数学运算且没有明文禁止安全函数的题族。6条均作无依据告警剔除，通用组此类告警为0。正确对照仅覆盖固定输入，不能把0/84解释为全库误报率。

**门槛判断。** 独有登记题族数经验4、通用3，经验达到至少3族且多于通用组，正确对照观察误报率也低于5%。独有结果只涉及一种错误机制，未达到至少两种。两组输入按公开问题类型人工固定，通用组的算术检查全部是合法算式，经验组全部检查嵌套构造。该对照只能说明这两套固定输入的表现。停止以当前方案进入付费修复，本轮未测Joint变化。
