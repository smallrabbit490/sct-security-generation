# 原卡动作已落实后，代码还会在哪些环节失败？

**在已审阅的28例中，10份原失败代码都通过局部代码修正恢复了Joint（同一份代码通过功能与安全测试）。其中6份覆盖了宿主数据或密钥，1份错配模板字段，2份漏掉小数格式，另1份错误归一化了运算结果类型。** 原题、卡片和原验证器保持。这个结果确定了旧代码的具体失败步骤；新版提炼或生成提示的提分幅度由尚未执行的新生成对照测量。

本报告固定28例、28个原推断题族ID、18个近邻组。其中25例来自1017模型、3例来自不带1017的Flash，两种历史模型单列保留。共阅读79份实际卡片视图，复现27份原代码，保存120项公开或计划行为观测。1409的原夹具包含绝对路径写文件，本批使用本地模拟接口，原成绩保留。17份旧代码形成20个诊断变体；新的E组仍为0/300，新增API为0。

## 1. 为什么做这次审阅？

S5需要解释经验如何影响代码。正式采用编号只能记录一次模型判断，不能代表建议已经进入计划、代码或最终行为。本次逐份阅读实际入模卡文、复析、计划和首次代码，再用原验证器及明确标注依据的本地输入检查它们之间的联系。28例来自事先整理的50例草案，包含10份原失败代码和18份原通过代码。后续固定条件与重复继续保留。

## 2. 怎样定位失败步骤？

1. 对照公开题面与实际卡文，明确一项焦点动作，同时列出其他卡和题面中的同义要求。
2. 核对正式采用、复析、计划和代码，各自保存原句与代码引用。
3. 准备E0原卡、E1移除焦点卡、E2只删除焦点卡中该动作全部指令的三路材料；其余卡片、顺序和档位保持。
4. 用本地合成输入观察具体行为，分别标注依据是公开要求、保存计划还是替代宿主模板。原验收分数只取原验证器。
5. 对已定位错误做最小代码诊断；纠错与不利方向反例分开，保存救回、损失和仍未修正的问题。

## 3. 哪些改动救回了旧失败代码？

|失败环节|旧题及历史模型|最小改动|原Joint与额外行为|
|---|---|---|---|
|覆盖宿主数据或策略|1015、1012、1370（1017）；1023（Flash）|撤销模块顶层空字典或空集合赋值，函数体不改|4份失败→通过；合法查询、权限与字段更新恢复|
|覆盖宿主密钥|1290、353（1017）|只撤销secret_key空字节赋值，函数体不改|2份失败→通过；两个不同合成宿主密钥分别得到正确签名|
|填充键名与宿主模板不匹配|994（Flash）|保留原name/bio/status键，补上当前参数名的同值别名|失败→通过；原示例模板、当前参数名模板及字面花括号均可处理|
|遗漏小数格式|156、159（1017）|在原白名单之后补:.2f替换|2份失败→通过；敏感字段仍先拒绝。159仍漏匹配嵌套受限路径|
|运算结果类型错误|1160（1017）|整数词元保留int，小数词元保留float，不统一把结果转int|失败→通过；单独补负号没有救回原Joint；负号接括号仍待修正|

宿主绑定诊断合计7例、4个近邻组：6份原失败救回，另1份原通过的1078保持Joint，并恢复了变动宿主字段策略下的正确行为。重新绑定名称与修改旧对象内容需要分开检查。例如USER_PROFILES赋空字典没有清空原对象，却让函数再也读不到它。七个函数体均保持原样。

模板诊断同样有明确范围。994和991的公开文本没有唯一规定占位符拼写，本批用两份合成运行时模板观察兼容范围；加别名覆盖了这两种已登记命名，任意模板映射尚未验证。156/159补的是已定位的:.2f格式，完整格式语言尚未实现。

120项观测中32项未吻合原定公开或计划行为。每项保留预期依据；这些观测不是120道独立题，也不把所有计划未兑现都当作题面错误。原验证器通过与公开动作完整落实分别记录。

两张卡把重复字段失败解释为str.replace自然遗留同名占位符，这个API解释不成立：Python的普通str.replace会替换全部同文子串。本批回调实现确实能正确处理重复字段，但这不能证明旧卡的根因解释正确。156和159的实际失败则明确定位到了带小数格式的字段未被正则识别。

## 5. 卡片的作用现在能说明到哪一步？

两道邮箱题读到了同一张254长度上限卡：49的复析与代码采纳阈值，1256明确拒绝并接受更长的模式可匹配字符串。两题正式采用列表都为空。它们说明“正式拒绝”“部分采纳”和“代码实施”必须分别读取；两个不同题目的旧记录不构成随机同题卡输入对照。

宿主密钥案例也分开了两个动作：1290实际使用了卡片建议的HMAC原语，却覆盖了应使用的宿主密钥。正确执行一条建议不能保证整个程序正确，空密钥赋值也没有被现有记录证明是卡片要求。994采用了三张保护外部模板的卡，模板绑定得到保留，但计划沿用了来源示例的字段名；这是可追踪的文字到代码一致性证据，卡片的因果贡献继续由E0/E1/E2测量。

20个代码变体分为18个纠错诊断和2个不利方向反例。10份原失败代码各有至少一个变体恢复Joint；5份原通过代码接受纠错后均保留原Joint。两项反例分别是450提前取回文档、1028加回目标预注册限制：相关行为退化，原Joint仍通过。它们单列，不并入纠错方案损失率。这说明部分原夹具没有覆盖已观察到的动作差异。
