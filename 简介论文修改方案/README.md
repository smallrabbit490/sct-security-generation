# 论文修改方案总索引

本目录把组会意见、原始 DOCX 约束和自进化论文启发整理成可追踪的修改方案。这里的“方案”不等于已经改动源码：每一项都标注当前状态，避免把设想误写成实验结论。

## 一、按状态分类

| 状态 | 含义 | 当前文件中的典型内容 |
|---|---|---|
| **已完成** | 已完成阅读、整理或现状审计，未改变正式数据和源码 | 组会问题梳理、Base/Plus 缩进问题记录、PLT 统计、DOCX 差异分析 |
| **方案** | 已给出具体方法设计，但尚未作为正式实验实现 | 动态 R0、结构化经验卡、经验生命周期、跨语言检索 |
| **待实验** | 可以实现，但必须先做小规模对照或消融 | 主动采样、多候选搜索、传播门控、任务顺序稳健性 |
| **暂不采用** | 当前规模或成本下不适合直接纳入主线 | 在线强化学习、完整 MCTS、端到端记忆控制器、直接训练大型 embedding |

## 四、当前修改的边界

### 已经整理但没有改源码的内容

- 将组会六点意见拆成需求编号，并纠正“缩进问题属于 CodeSecEval Base/Plus，不是 PLT”的范围。
- 对 PLT 的 CWE、变体和 family 隔离要求做了文档化说明。
- 收集 18 篇自进化论文，记录公开链接、核心机制和 SCT 用途。
- 识别当前实现仍以固定数据分区和简单门控为主，不能把它描述成已经完成的开放式自进化。

### 已提出、但必须通过实验才能采纳的改动

- 用“观察 → 假设 → 验证 → 晋升/修订/退役”的经验生命周期替代表面上的追加式经验库。
- 把编译器、静态分析器和语言 harness 作为外部验证器，记录可审计证据。
- 从固定随机 `D_grow` 扩展到基于失败弱点的主动采样，但新任务仍需 family 隔离。
- 将经验拆成语言无关安全原则、CWE 策略、语言适配和验证模板四层。
- 对高风险 CWE 保留多个候选修复，只有独立验证后才进入长期库。

### 暂时不能写成论文结论的内容

- 候选架构比 `D_init/D_grow/D_gate` 更好；目前只有设计理由，没有实验结果。
- 经验生命周期一定提升 Base/Plus 的 JointPass；需要冻结协议下的多次运行和消融。
- 任务主动采样一定优于固定划分；必须报告任务顺序、随机种子和 family 隔离。
