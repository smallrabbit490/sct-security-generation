## 3. 第1150题从哪一步开始出错？

公开任务要求执行简单、安全的Python脚本，允许计算和字符串处理，拒绝文件、操作系统和导入操作；违规和语法错误应抛`ValueError`。两次初析相同，均提出先验证语法树，再执行允许的代码。

三张可见卡分别建议受限脚本执行、避免误伤合法表达式，以及针对纯数学表达式的白名单。失败运行声明采用三张卡；通过运行采用前两张，拒绝数学表达式卡，理由是该卡不适用于多语句脚本。两份计划都保留赋值、安全内置函数和字符串方法，没有要求禁止全部合法计算。

失败代码在验证入口执行了以下逻辑：

```python
_FORBIDDEN_NODES = frozenset({ast.Import, ...})
if isinstance(node, _FORBIDDEN_NODES):
    ...
```

`isinstance`要求第二参数是类型或类型元组。集合即使装着正确的AST类型，也会触发`TypeError`。因此，正常脚本无法进入执行，危险脚本也没有得到题目要求的`ValueError`。通过代码使用类型元组，实现了相同的检查意图。

最小修改保留所有允许与禁止类型，仅把两处`frozenset({…})`改成`tuple({…})`。原验证器和10项公开行为探针的结果如下。

|代码|功能测试|安全测试|Joint|公开行为检查|
|---|---|---|---|---|
|原L1失败代码|失败|失败|失败|1/10|
|仅修正两处容器|通过|通过|通过|10/10|
|原Q2通过代码|通过|通过|通过|10/10|

公开检查包括算术、字符串方法、多语句赋值、允许的内置函数、无返回表达式，以及对非法语法、导入、文件调用、系统调用和双下划线属性的拒绝。没有执行实际文件或系统命令，也没有运行资源耗尽输入。原失败计划提出资源限制，但生成代码对循环及部分运算仍无执行期约束；这条计划落实缺口另记，没有并入本次原测试救回结论。
