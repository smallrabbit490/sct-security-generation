# CLE 实时工作台与独立 CLI 守护

本模块将运行监控从聊天 heartbeat 移到本机常驻进程。用户于2026年10月27日授权工作台自动寻找 Codex CLI、修复实际错误并接续既定实验。它不创建 Codex 自动化或 Windows 计划任务，不需要聊天窗口或浏览器页面持续打开。

现已升级为按任务清单自主执行：任务定义在本目录[autonomy_plan.json](autonomy_plan.json)，当前为33个节点。执行状态、进展收据和队列保存在E盘`workbench_monitor/autonomy/`。不修改活动实验的冻结配置；原`execution_plan.json`保留来源身份。

## 自主完整执行

1. 持续读取原生完成数、实际进程、冻结库、回放和分析文件，核对每个任务的依赖。学习仍为单worker；冻结评价只在全局四个槽内运行，一个学习加一个三worker评价。完整任务中正常低分不会取消后续固定实验。
2. 就绪任务自动交给6.1 Sol/xhigh。当前学习和评价进行时，可先完成新卡库、交叉等独立零API接线；没有新事件也会继续找尚未完成的就绪任务。CLI一次只处理一个工作项，结束后交回队列。
3. 全量执行、原生回放、统计分析、实际代码复核、分类器训练和报告是不同节点。CLI回复resolved不会直接完成节点；原生总量/状态、回放passed、分析summary与逐题证据满足后才结单。未完成的工作自动从已保存进展继续。
4. 逐题复核使用`agent_case_review.json`保存实际判断和证据路径，覆盖原生case_review_queue全部代表题。它是Agent分析，不是人工检索标签确认。
5. 原镜像缺失、停用的v3.2、人审、认证/余额或固定预算耗尽会明确列为相关任务的外部等待；普通接线没做完不算外部依赖。独立可执行项继续。原镜像每五分钟本地检查一次，人工复核由原导入流程判断；停用v3.2不自行探测恢复。
6. 禁用时段只安排零API准备、回放与分析；不反复派发付费运行的恢复任务。允许窗口到达后，队列自行启动或续跑，原入口仍逐物理请求检查时段和累计预算。
7. 全部可执行任务及分析完成后，生成综合Markdown和可跳转Word，逐项说明主线结论、完整结果和外部未执行项。若外部依赖随后满足，重新推进相关任务并更新收尾报告；不会把等待项写成已完成。

工作台“自主任务”页可查看每个节点、前置条件、当前状态与下一项。原“自主执行”开关控制新CLI派发，关闭不会强杀在途任务。新增执行入口的PID、包与唯一命令标记登记于`registered_workers.json`，工作台再与CIM匹配，避免漏识别或重复启动。

节点按完整阶段结单，已完成题次仍在“实时运行”展示。此处零API工作指不请求实验模型或Embedding；Codex CLI维护用量另外保存，不混入DeepSeek实验成本。

## 自动修复的执行方式

1. 读取实际 CIM 进程，识别普通学习、代理恢复、任意题号向量恢复及后续评价入口。venv启动器和子Python只算一实例；活进程不会因题数未增长而被重启。
2. 摘要显示仍在运行、但连续两次采样均无实际进程，或保存了失败状态时，登记事件。每个新事件只运行一个维护CLI；同一失败不会反复消耗Codex额度。
3. 在 PATH/npm 安装位置寻找真实 `codex.exe`，使用现有登录执行 `codex exec --model gpt-6.1-sol -c model_reasoning_effort="xhigh"`，固定GPT-6.1 Sol与极高推理强度；任务记录同步保存模型和强度。实验模型不因此改变。维护任务可读写项目与指定E盘运行区；命令不经过 shell 字符串拼接。
4. CLI核对协议和失败现场，优先用现有恢复入口零API精确回放，再恢复。用户2026-10-27 18:31已授权同类TLS/网络断连未决请求补发；旧失败、未知执行/用量和累计预算必须保留。认证、额度、预算问题不能按断连补发。
5. 活动实验的冻结源码与输入不改。真实程序问题优先在独立目录修复并验证；不得改旧journal/state/source_identity来绕过恢复。已完成题与成功响应复用。
6. 每轮/每包完成时，CLI接续原生回放、统计和实际案例分析，再启动依赖已齐的下一项。外部依赖在页面明确列出，不替代验证器或人审，不伪造完成。

故障事件优先于“接续计划”，确认故障的等待期间不另派接续任务。CLI在执行任何操作前返回模型容量已满时，保留拒绝记录，60秒后自动用同一模型与强度重试；执行过操作的CLI失败须先核对现场，不能当作空请求重复派发。所有包完成后不额外派空闲任务。

## 本机维护记录

`workbench_monitor/guardian.json`保存开关、已处理事件及最近任务；`jobs/<时间>/`保存任务说明、CLI事件、结果和错误日志。服务重新启动时先核对原CLI PID，避免第二个维护代理。CLI返回 `resolved`、`waiting_dependency` 或 `needs_decision`，页面显示实际结果。CLI自身失败也显示，不写成实验失败。

工作台只绑定127.0.0.1。页面读取采用公开证据白名单，不提供任意文件读取或原始HTTP头；控制请求限制同源。关闭聊天实验监控后，本服务接管，周报写作自动化独立保留。

若CLI修订了工作台自身代码，可在验证后向`/api/guardian/reload`发送同源POST（`X-CLE-Control: workbench`）。受控重载只替换工作台，保存的CLI PID和任务状态由新进程接管，不重启实验worker。

## 不影响正式实验的全链路验收

`python -B -X utf8 -m tools.cle_live_workbench.selftest start`在E盘`workbench_monitor/selftests/`启动独立验收。它复用同一Collector、事件识别、Guardian和真实CLI派发，工作目录限定为隔离文件夹，CLI使用workspace-write沙盒；仅用本地替身生成五条固定响应。替身禁用网络，不导入或启动正式实验。

测试先保存A1结果和A2成功响应，随后在A2解析处注入错误；真实CLI修复后从前缀恢复。A阶段完成触发另一项CLI分析并启动B，B完成再自动分析。程序核对五条收据唯一、五条结果正确、A1/A2分别复用、分析先于下一阶段、重复启动被拒绝、最多一个测试worker，以及固定runner/协议未被CLI改写。整个链路独立运行，不依赖聊天继续发送指令。

`selftest status`查看结果；同一验收请求重复start不会重跑。真实CLI用量与容量拒绝单独记账，不能将“实验API零调用”写成“Codex零用量”。原失败和修复前记录保存后可用`selftest resume`接续同一测试前缀；模拟收据和预算不重置。最终结果在`selftests/latest.json`，不是正式CLE的Joint成绩。
