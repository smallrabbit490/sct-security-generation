# 包B：把安全动作与功能义务分开，再测实际影响

研究问题B：功能失败主要来自建议本身不适用、来源假设迁移、建议缺少功能边界，还是模型明知边界却没有执行？

## B01 最小改动：一张卡的两个关联视图

暂不拆成两座独立数据库、不重新蒸馏1939张卡。给现有card ID增加运行期视图（同一份经验的不同展示），保留原库与原检索文本：

| 视图字段 | 写什么 | 来源要求 |
|---|---|---|
| security_action | 要消除的风险、建议的安全动作、适用/排除前提 | 从原卡逐句提取，不能凭空补一个更好的算法 |
| functional_preservation | 合法输入、已有对象、返回、异常、副作用中哪些必须保持 | 第一轮只重组原卡已有内容；缺项显式记录 |
| source_assumptions | 来源环境、类、数据库、常量及不能直接迁移之处 | 原卡及允许的来源材料；研究索引不注入来源题号 |
| public_bindings | 当前题已提供哪些对象；哪些位置允许修改 | 第二轮“目标绑定”干预才补充，且只来自公开题面 |

**功能视图保留当前题必须做到的事情，安全视图规定要防止什么；两者共同约束同一份代码。** 不使用“先让功能通过，再随意增加安全限制”的串行口号替代检验。

截图例子中的候选边界：保留传入的person及name属性，不新建Person替换它；模板检查仅拒绝公开契约不允许的输入。若题面没有定义允许的模板语法，记录前提缺失，不能擅自禁止所有模板。此例是机制说明，不是从截图确认了完整可运行修复。

现有能力不是从零开始：`context_pipeline.py`已有`CONTRACT_POLICY`、`functional_invariants`、`Preserved_Func`及`Patch_Scope`；`distillation.py`已有正向原则、负向红线和去特化要求。新增点应是**可核验的对应关系及受控使用方式**，而不只是再写一句“不要破坏功能”。

## B02 首轮最小完整对照：12题、五个条件、各重复2次

用包A锁定的12个D_grow题族，固定经验正文、候选、卡片ID和顺序，Q不介入。每题每重复先按原CLE选择至多三张，再冻结这组ID，将它们呈现为以下条件。允许没有卡，不强迫模型选满三张。

| 条件 | 输入的经验 | 回答的问题 |
|---|---|---|
| B0 | 不给经验 | 原模型/公开契约已能做到多少 |
| BF | 共用适用/来源上下文＋功能保留部分 | 是否只是提醒保留功能就足够 |
| BS | 共用适用/来源上下文＋安全动作部分 | 安全建议是否伴随功能损失 |
| BFS | 同一共用上下文＋功能与安全，明确分栏关联 | 两部分是否互补，能否减少“安全但无用”的代码 |
| BM | 同一卡的现行混合表达 | 相对当前项目表达方式是否真的有改善 |

BM与BFS尽量使用完全相同的事实句，只改变分类、顺序及对应关系；原卡没有的功能事实不得偷偷补入BFS。记录输入Token与位置。BF/BS删除了内容，其效果是“内容可用性”变化，不宣称纯排版作用。无法忠实分解的卡需记录冲突/空字段，不能用模型修好原卡后再称仅重排。

主要比较仍预先指定BFS−BM。BFS−BS检查在同一适用上下文中增加功能动作的效果，BFS−BF检查增加安全动作的效果。读取真实卡后，已明确将适用前提和来源验证信息作为各有记忆条件共用的context。由于B0没有这份上下文，五条件不再声称是严格纯2×2设计；`J(BFS)-J(BF)-J(BS)+J(B0)`至多列为描述性差，不能解释为纯功能×安全交互。若未来必须估该交互，需要另立包含context-only条件的新协议和预算，本轮不增加第六臂。此修订发生在任何新生成成绩产生之前。

第一次实验固定原P7消费者：初析→召回/选卡→复析/采用→规划→生成→原验证→若未Joint最多一次修复→交付末次代码。共享首次初析；首次经验集合固定；修复轮沿各臂原P7反馈继续，因而首次尝试是更干净的呈现干预，最终交付是整个流程的实际收益。两种成绩分别报告。

B0整个流程均不注入卡，包括修复轮；其他条件修复时仍按原检索/选择流程产生候选，再应用本臂同一种视图。按题×重复打乱五条件执行顺序，记录请求时段。具体模型和参数见包D统一规格，不因某一条件失败临时更换。

最多120次P7、240份生成代码。前2题的20次P7计入120次，不另加。技术异常停止剩余题，不覆盖失败重跑；模型答错属于有效观察。首次调用前再单独获得恢复付费授权。

**推进门B**：BFS相对BM在24个题×重复观察中净增加至少2个Joint通过（8.33个百分点），两个重复方向均不为负，F不降低，且不出现BM安全通过/BFS安全失败的新退化。另至少两例能够沿“具体功能义务→代码保留→结果救回”说明变化。它是工程筛查，不是安全保证或显著性证明。

若不通过：原样报告。BF胜而BFS不胜说明安全动作可能不适配；BS提升安全却降功能支持冲突诊断；BF/BS/BFS均差而B0好提示不宜强行使用该组记忆；BFS和BM相当则不继续把“分栏”包装成有效机制。

## B03 仅在缺失绑定得到证据后做目标绑定

如果B02中至少两例明确缺少已有对象/返回/副作用约束，允许提议第二个小实验：BFS对BFS+公开目标绑定，保持安全内容不变。仍12题×2重复，两条件最多48次P7；只有输入、模型响应前缀、协议与候选完全一致时才可复用BFS，不按臂名复用。

预先固定绑定规则：公开对象只引用不重定义；输入参数不被来源对象替换；返回及异常依题面；副作用依公开对象契约。信息未知填unknown，不根据隐藏验收反推。两组看到相同公开题面，干预只在于是否显式把卡片动作对应到目标对象。

沿用门B；未通过则停止绑定改动。与10月23日契约消费者整体包区分：这里保持P7反馈、修复和末次交付不变，才能检验绑定提示本身。

## B04 影响足迹 φ 与影响边界 ρ：先零API回放

新报告用`c_base`表示无记忆代码、`c_mem`表示有记忆代码、`c_ref`表示仅用于离线审查的参考代码，避免与P7的c0首次/c1修复混淆。

按Notion定义复现φ（变化语句事件数/两份代码语句数之和），同时保存匹配器定义。事件可能重复覆盖节点，未经证明不称严格0–1距离；分母为零记null。这个数只描述结构变化，不证明功能或安全语义变化。

特征限定为：已有绑定重定义、参数替换、返回形状、正常路径删改、异常变化、敏感调用变化、新helper/import、来源特有名字/常量、不确定项。每个事件绑定代码位置与公开义务；不以“新增helper”一律判错。

离线比较五种选择器：

1. 总选`c_base`与总选`c_mem`，作为两个必要基线。
2. 简单文本diff大小、AST变化量阈值。
3. 公开硬契约检查。
4. 只检查`c_mem`的风险特征，不读取另一份代码。
5. 配对足迹+契约的组合；语义审查若新增模型调用，另列付费分支，不能算零API。

原件接收后先将family排序，再以种子20261023打乱，前70%向下取整为训练，其余留出。阈值只在训练family上定，不能在5817对全量上调阈值后报同一批收益。所有属于同一family的卡和重复同时分组。报告有害拦截、救回误拦、接受比例、最终F/S/Joint、较两个基线的变化。未掌握代码与标签时不编造ROC或重采样区间。这仍是来源题数据的内部留出，不是跨题族新任务迁移的证明。

ρ先表示明确的允许修改类别，而非随意拟合一个“改动比例最大值”。门B4：复杂足迹在留出family等权Joint上相对总选无记忆、总选记忆、硬契约检查和单代码检查均至少+1个百分点，F/S均无下降，且至少2个不同family有实际救回，才值得后续迁移验证。阈值也是工程筛查，不是正式效应证明；失败就保留较强简单策略，不能靠拒掉全部记忆取得漂亮风险率。

Notion目前结果是门控比全部有记忆好0.77个百分点，但比无记忆低1.65个百分点；因此暂不启用AST门控作为生产默认策略。

## B05 区分记忆影响与生成波动的辅助实验

如果回放留下“是否由这条建议造成”这个关键问题，固定6道诊断题（如1003、907、1037、989及2道可核验救回），每题复用2份已保存`c_base`，分别要求：无记忆的同预算编辑 / 带该建议的编辑。两者都看到同一公开任务和同一初始代码，每种只生成一次补丁；共最多24次补丁调用。若12份合法起始代码缺失，先报告缺失；额外生成起始代码最多12次，需计入申请预算。

辅助实验只接受公开反馈，正式验证在生成之后。它能削弱不同起始代码的混杂，但仍是有限随机生成实验，不能证明逐个语句的唯一因果。它不是P7，成绩单独报告。按结果删除违规代码再验证的历史修复只能说明局部缺陷，不计为在线方法成绩。
