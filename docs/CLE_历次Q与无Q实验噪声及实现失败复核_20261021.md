## 最重要的结论

现有记录不能计算“全部失败中有多少纯由模型偶然性造成”。必须分开：同设定重复运行的成败波动、单次记录中的流程异常、可复现的代码实现错误。它们可以重叠，不能相加；更不能将未归类的失败全部归给Q。

扫描22组正式或有效历史生成记录，按实验臂分为43行，共3413条记录。多轮有复用、同题有重复，这不是3413个独立样本，不跨实验求总噪声率。被后续版本取代的7组入口另列附录，不叠加进最终四臂。当前D_grow以扫描时已落盘13题为快照。纯检索标注、参考代码预检不计为模型代码生成实验。

“失败且带流程异常”指JSON解析、采用字段、英文策略、截断、检索/请求错误等至少一项出现在该次尝试历史中，最终Joint未通过。这是共现计数：首轮报错后可能修复，错误也可能不是最终失败原因。缺测列与异常列可能重叠。所有失败保留原分母，未用剔除异常后的分数替换正式结果。

三组实际采用的是同一套303题unittest，已逐项比较一致。对58、51、61份有可疑全局重定义的新代码分别做原样复测及删除指定顶层赋值后的复测，共340次原生validate_plt_row本地验证，未调用API。170份原样代码的未通过均复现；局部删除覆盖后分别28、20、31份恢复Joint。

这证明相应副本上的外部对象覆盖是足以修复失败的具体实现问题；不证明全部卡片建议正确、不证明该错误由Q引发，也不证明重新让模型生成一定会通过。删除赋值是使用现有测试做的诊断，不是新模型成绩。其余筛查到的58/51/61是静态候选数，不能冒充已确认故障数。

无Q参考使用覆盖优先排序，虽然不使用Q数值，仍使用访问/覆盖状态；它不等同于原CLE Q0。与当前比较还存在起始Q和执行时间差异。

## 五、对Q结论的实际影响

1. 两侧都存在模型实现错误和流程异常，不能把有Q组所有失败归因于Q，也不能把所有失败叫作随机噪声。
2. 无Q303题限量与当前Q303题分别138、140题Joint，净差只有2题；已观察的流程异常、外部对象覆盖和重复波动规模均不能忽略。仅凭这个差值无法支持稳定收益。
3. 当前Q组31题仅删除外部对象覆盖就通过，说明Q没有解决生成落实问题。1003的正确模板建议被声明采用却未落实，卡仍被扣Q，是共享奖励归因受实现错误污染的直接案例，详见18道退化题报告。
4. 后续若要测纯偶然波动，应固定同一Q/卡库/公开题目/初析/候选/协议，匹配重复生成；不能用改Q、改卡数或补契约前后的结果替代重复实验。本次只复算和局部验证，没有新增付费重复，也未修改正在运行的实验。
