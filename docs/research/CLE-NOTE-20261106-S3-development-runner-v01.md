# S3开发集如何完整运行？

**50题五条件、两次独立重复的500格运行器已经接通，封网检查8项通过；真实生成仍为0/500。** 24题共享来源安全动作、18题只共享局部操作、8题获准使用空来源槽，分层和名单保持不变。

## 1. 固定执行什么？

五组分别为G0原生提炼、G1普通复审、G2提炼时加入来源参考代码再普通复审、G3复审时加入来源参考代码、G4固定通用指导。每题每次重复共享首次分析，随后五组独立采用、规划、生成和验证；首次未通过时，各组最多修复一次。两次重复不共享模型返回。

42题实际使用9个来源事件。8题在G0—G3共64格使用预先声明的空槽，G4仍使用通用指导。来源候选尚未完成不能当作空槽继续；候选实际返回为空或被原生规则拒收则另记。完整来源50题仍全部提炼，供后续留出评价使用。

匹配说明、来源参考实现和目标题参考实现均不进入生成提示；目标测试只在原验证器内部运行。经验正文、Q、题面、名单、条件及修复规则保持冻结。

## 2. 运行和恢复怎样接续？

入口为`python -B -X utf8 -m configs.cle_weekly_plan_20261105.development_stage`，执行时使用项目既有Python环境。

1. `prepare`保存目标输入、固定500格、协议与预算草案；`check`说明尚缺的依赖。
2. 来源500次提炼/复审及其原生回放完成后，`candidate_pool build`构建真实来源池，`bind-cards`绑定全部400份来源槽。技术合成返回不能进入此入口。
3. 该批新预算获准后，`launch`以单worker顺序执行。工作日禁用窗口仍在每次真实请求前检查。原代理、TLS1.2和证书校验保持。
4. 中断后先`audit`核对已保存单元和未决请求，再`probe`零API复用成功响应，精确停止在缺失边界。只有请求均已核清且探针匹配当前输入、完成记录时，才可`launch-resume`。未决请求不能换目录重发。
5. 500格保存齐后自动`replay`，再`analysis`。生成已齐时只执行`finish`，不再生成付费代码。实际差异代码继续由当前Agent逐份阅读。

请求、成功返回和未知用量均按物理记录累计；多臂共享首次分析、恢复段和回放的用量不重复相加。相同空槽提示仍通过请求位置区分真实各组的独立调用。

## 3. 如何分析和选择留出方法？

主要比较为G2−G1、G3−G1，做Holm两项校正；G1−G0用于解释增加普通复审的作用，G4作为通用规则对照。分别列首次和最终F、S、Joint、救回、损失、修复和重复波动，保留未测验证及正常生成失败的区别。

主区间按19个目标题近邻组聚类，另列共享来源事件分组的敏感性结果。24/18/8三层单列；空槽表现不解释为来源卡的提炼能力。模型声明采用与代码实际落实分别核查。

G1/G2/G3依既定顺序比较平均Joint、相对G0的损失、来源事实错误、成本，同分按组号。完整生成和原生回放之前不选择；来源事实审阅或同口径成本未完成也不填默认零。胜出方案的真实卡、方法和留出规则冻结后，再按独立预算执行H50三组300格。开发不提分仍完成既定留出探索。
