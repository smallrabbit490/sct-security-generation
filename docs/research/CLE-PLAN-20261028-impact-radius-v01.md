# 经验改动了哪些地方，限制不必要的改动能否提高Joint？

## 起因与研究主线

这条思路承接功能与安全经验分开的要求，以及来源经验可能覆盖目标任务对象、配置和参数的案例。用户本次要求将“影响半径”扩展为完整研究线索。这里提出的测量和干预是本项目的新设计，不声称复现尚未取得完整实现的Notion算法。

经验既可能补上安全检查，也可能顺带改坏原有功能。因此，研究不能停在“带卡代码变了多少”，而应依次回答：改动触及哪里？哪些改动与退步相伴？恢复某一处能否救回功能且保留安全？生成时限制无关改动是否真的提高Joint？

主假设：损失更集中于任务依赖边界被不必要地改写，而非所有大范围改动。竞争解释是困难题本来就需要大改，或者模型自行实现错误；代码变化量只是伴随现象。整个实验按这两种解释设计，不预设“越少越好”。

## 已有什么证据？

- 已有AST语句变化测量和外部名称重绑定标记。语句变化比例包含嵌套节点重复影响，只作为历史结构差异指标，不叫真实传播距离。
- 旧303题比较两种带记忆历史方案，不是有卡/无卡的严格因果对照。
- 固定起始代码的B05小实验，两组Joint均为6/12，未得到经验编辑的净收益。
- R01已进入工作台，等待功能安全分析完成；最多6题、12次本地验证。它能确认某个局部改动的作用，不能估计全体错误原因比例。

## 怎样定义“影响半径”？

本轮将它操作化为“修改触及的范围与任务边界”，不合成一个未经验证的总分，也不计算没有可靠依赖图支持的传播距离。

| 维度 | 具体测量 | 用途 |
|---|---|---|
| 改动大小 | 原语句变化比例；同时报告变化语句数量、原代码长度 | 判断是否仅是代码变长或全面重写 |
| 改动分布 | 改动涉及的函数/类数量；新增、删除、改写分别计数 | 判断修改集中还是分散 |
| 任务边界 | 参数被替换、外部对象/配置重定义、返回约定变化、副作用范围变化 | 判断有没有碰到与任务正常行为有关的位置 |
| 必要性 | 根据公开题面和来源卡，逐项判断改动是否必要、是否能确定 | 区分必要安全修复与来源假设迁移 |

静态标记不是错误标签。例如重定义可能合法。必要性必须有公开要求支持；公开要求不足时登记“无法判定”，不据测试答案补写要求。无代码、语法错误单独统计，不记为零半径。

## 各阶段怎样做，结果说明什么？

<a id="ir01"></a>
### IR01：已有代码中，哪种改动与退步相伴？

**目标。** 用已付费结果检验相关性，并确定值得干预的位置。

1. 等FFS完成，冻结其全部298题、五条件、两重复记录；保留原缺测及分母。历史B05与303题单独列示，不合并成新对照。
2. 主要对比BM与BFS的首次生成代码；二者共用初析和来源卡，但呈现不同。B0与BM作为次要对照。首次到修复轮的变化另列，避免混入不同修复反馈。
3. 对所有可解析配对计算上述指标。按相同题和重复配对，展示救回、退步、双通过、双失败四类的分布，分功能与安全报告；最终交付成绩与首次成绩分开。
4. 固定检查最多12道不同题族案例：退步、救回、双通过、双失败各3例，组内按任务ID排序，不够不凑。阅读题面、卡、代码与验证证据，记录边界标记是否成立。
5. 以题族为重采样单位给出差异区间；调整代码长度并分首次/修复说明。两重复不当作两道独立题。

**判断。** 退步组的边界改写更多、且人工阅读能解释具体违反之处，支持“边界改写值得继续检验”；变化量大但不集中于退步，否定用变化量单独作为风险指标。这里只建立关联，不宣称改动大小造成失败。

**成本与交付。** 新生成/Embedding调用0；读取全量保存代码，最多12例深读。输出指标表、四类分布图、案例和分析。Codex分析成本另记。暂不设置自动拒绝阈值。

<a id="r01"></a>
### R01：只恢复一个地方，能否救回原功能？

沿用现有任务，不扩大名额，不另建一份重复任务。按已登记选样顺序选最多6题，先记录预测，再在副本恢复一处可隔离的改动，用原验证器比较原代码与修改版，最多12次本地验证。不修改测试、不读取参考实现来写补丁、不迭代直到通过。

原失败复现且该修改令功能恢复、安全仍通过，支持该处在本题的局部因果作用；功能恢复但安全失败，说明这一修复有取舍；原失败未复现则不能确认该原因；仍失败说明该单点不足以解释。将已完成R01结果链接给IR01即可，不为新线索重做。

<a id="ir02"></a>
### IR02：限制无关改动，能否在相同代码上改善结果？

**目标。** 验证可用方法，而非仅统计代码差异。

1. 从增长集保存的无卡首次代码中固定12个不同题族；按CWE分层、固定种子20261028选取，不按是否失败挑题。先做12题名册的公开要求充分性核查，无法确定边界的题不进入干预名单，替补规则在看新结果前锁定。
2. 每题共享同一起始代码、同一组最多三张卡、相同公开上下文、模型及预算。两臂分别为原经验编辑，以及增加“保留与安全修复无关的参数、外部对象、配置、返回和副作用约定”的边界约束编辑。两臂都只编辑一次，之后不再依据验证结果修复；不是P7完整流程收益实验。
3. 每题每臂独立重复两次，最多48次编辑调用。若原B05某单元所有输入和规则精确相同，可复用；不预先抵扣，也不跨重复共用返回。
4. 首先核验约束确实减少了非必要边界改写，再统计Joint配对净变化、安全新增失败和正常功能救回。按原代码质量分层报告，不能只展示原失败题。

**进入独立确认的门槛。** 至少4/12题出现可核验的非必要边界改写减少；Joint净救回至少2/24次交付；两次重复各自的净变化均不为负；没有新增安全失败。全部满足才建议进入IR03。干预未发生就结束该方法版本，不追加题量；已发生但净损失则不推进；方向不一致则记录不稳定，不靠重跑改变结果。

**预算。** 48次逻辑编辑调用，每次输出上限4096，输出合计上限196608 Token；输入在锁定完整提示后求和，未完成预算冻结前不派发。沿用原模型、时段、传输记录和已授权恢复规则，所有物理重发累计计费。原卡片检索和初析优先复用；缺失不暗中增加API预算。

<a id="ir03"></a>
### IR03：这个改善能否在未用于设计的题族上重复？

1. 在看IR02成绩前从增长集其余题族固定24题，和IR02按family隔离。冻结方法后才运行。
2. 同样两臂、两重复，共96次编辑；不选择IR02中表现最好的题或新改提示。结果用于确认方法，不调阈值。
3. 主指标为最终交付Joint差，题族聚类95%区间；同时给安全配对收益/损失和实际改动。

**正向判断。** Joint净增至少3/48次交付、95%区间下界大于0、两重复方向一致，且没有新增安全失败：支持该固定编辑策略在这批题族有效。Joint差区间上界小于0说明有害；区间跨0则本批未确认收益，不写成无效。安全新增失败即不通过进入全量的安全要求。

**成本。** 最多96次编辑，输出上限393216 Token。这里“没有新增安全失败”是小批观察，不等于证明总体安全不劣。小批通过也不自动启动全量。

<a id="ir04"></a>
### IR04：是否值得把边界约束用于完整审计集？

这是暂缓的主要比较，不进入当前自动派发。IR03通过并获得后续全量执行安排后，在冻结的298题审计集上比较原编辑与边界约束编辑，每题两重复，共1192次编辑，输出上限4882432 Token。需先有同版本、无经验首次代码和冻结卡片输入；缺少这些输入时单独登记准备成本，不拿不同题面或旧模型结果代替。审计集已有历史暴露，称为未参与本方法调参的确认集，不称全新未见基准。

主要通过条件预定为：Joint净增至少3个百分点且题族聚类95%区间下界大于0；安全差的单侧95%下界高于−1个百分点。两项必须同时满足，这是交集判定。前者证明值得采用的正确率收益，后者限定可接受的安全损失。1个百分点是本设计的拟定容忍界限，正式冻结时必须明确接受；不能事后随成绩放宽。样本不足以通过则结论是未达到采用标准，不追加样本救结论。

该实验验证“保存代码的一次经验编辑策略”。若要接入P7生成全过程，另行做同P7对照；不能把编辑收益直接写为整个CLE收益。现阶段不增加这套额外矩阵。

## 会不会得到一个通用影响半径阈值？

本线索先验证位置和边界，不承诺一个变化比例阈值。若后续确需自动预警，只能用增长集拟定并冻结阈值，然后在审计集独立评价误报、漏报和收益；这是条件后续任务，本次不另加实验。小改动也可能覆盖关键对象，大改动也可能是必要重构。
