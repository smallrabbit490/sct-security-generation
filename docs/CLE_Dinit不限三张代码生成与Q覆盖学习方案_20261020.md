# D_init 不限三张代码生成与 Q 覆盖学习方案

原设计日期：2026-10-20。原协议：`cle-dinit-card-cap-v1`。当前执行状态：**已完成2题技术探针、12题对照及全303题不限量学习**；实际采用v2长度预算续跑，见[执行报告](CLE_Dinit不限三张代码生成与Q覆盖学习执行报告_20261020.md)。下文保留原设计规格，实际参数及故障恢复以执行记录为准。

目标：允许模型选取超过三张适用卡进入复析、规划和代码生成，观察更多不同卡能否获得有效 Q 反馈，同时记录功能、安全、Joint 和成本。Joint 指同一份最终交付代码同时通过功能与安全测试；本轮不以正确率作为继续学习门槛。

## 1. 这次具体改变什么

采用“不限三张、按适用性自选”的方式，不强制凑四张或把全部候选都采用。一次最多来自原有向量 Top24 与词面 Top8 联集，去重后不超过 32 张；合法状态、语言和长度过滤保留。

完整流程：

`公开题目 → 共享首次初析 → 原候选召回 → 选卡（允许超过三张）→ 逐卡适用性复析 → 声明采用/拒绝 → 规划 → 生成代码 → 原功能/安全测试 → 必要时一次修复 → 保存末次代码 → 按合格采用记录更新 Q`

选中五张但只声明采用两张，只有两张进入 Q 记账；声明采用五张且测量与流程合格，则五张均可更新。选择、采用、Q 更新均不得再暗中截取前三张。声明采用仍不等于已证明代码落实了每张卡的建议。

## 4. 两组对照与共同设置

| 组别 | 允许选入的卡数 | 用途 |
|---|---|---|
| L3 | 0–3 张 | 12 题新执行的匹配基线 |
| Lall | 0–当次全部候选 | 12 题匹配比较，随后接续至全 303 题观察学习 |

这里的 L3/Lall 是学习策略名称，不重新定义已有 Q0–Q3。

12 题对照中，两组共用同一题面、首次初析、首次查询、候选 ID、余弦和候选呈现顺序。共同采用“起点未学习卡在前、组内按相似度排序”的覆盖优先顺序，只改变选卡数量提示及允许返回数量。Q 数值不参与排序，也不进入提示词。模型仍可拒绝不适用、重复和冲突的卡。

两组使用独立 Q 记账副本；12 题内不根据更新结果改变呈现顺序，避免数量干预和动态覆盖调度混在一起。修复轮按各自失败代码与原 P7 允许反馈重新查询，候选可能不同；首次查询用于严格的共同候选比较，最终成绩衡量完整策略。

共同参数沿用当前有效配置：`deepseek-v3.2`、thinking disabled、temperature=0、生成/复析等原阶段 `max_tokens=4096`、选择器输出预算 256、`text-embedding-3-large`、学习检索门槛 δ=-1、最多一次修复、首次 Joint 通过早停、末次代码交付。数值 Q 混合参数在本轮不发挥作用。

## 5. 执行顺序与题目

### 第一步：离线打通完整多卡链

用可手算的五卡例子验证：选中五张、声明采用五张时，五张完整传入后续阶段，合格反馈产生五条更新；重复采用 ID 只记一次，未采用/被拒绝卡不记，失败代码有完整测量时正常获得负反馈。另验证三张组仍不超过三张、越界 ID 拒绝、正常空选择合法。

检查选择器、复析、规划、生成、原生轨迹和记账之间没有额外截断。保留原上下文预算；溢出或输出截断显式停止并报告，不能静默砍回三张。若必须增加阶段输出预算，两组统一修改并登记新协议，不跨版本拼接成绩。

### 第二步：固定 12 题两组比较，前两题兼作技术探针

沿用当前 303 题清单的前 12 题，名单在新生成前固定：

`1258, 1288, 1299, 1303, 1319, 1338, 831, 1350, 1003, 1008, 1216, 1053`。

先对这些题及相应公开契约完成本地预检。每题 L3/Lall 各运行一次完整 P7；先执行前两题的四次 P7，技术链正常后完成剩余十题。新 L3 不能用旧成绩替代，因为起点覆盖状态与候选呈现已经变化。

允许复用经核对相同公开题目和初析协议的既有首次初析；同题两组必须共用同一份。下游生成与修复不得借用另一组代码或结果。两组执行先后按固定种子 20261020 交错，避免始终一组先跑。

12 题是有历史暴露的开发诊断，不是独立最终测试。若 Lall 没有实际选出或采用超过三张，报告“允许已生效，但多卡干预不足”；不强行添卡、不根据成绩换题。

### 第三步：Lall 接续至完整 303 题

复用本协议前 12 题的 Lall 真实记录，再完成剩余 291 题，不重新付费跑已完成记录。L3 停在 12 题，不自动扩成第二轮全量基线。

此阶段每完成固定 12 题更新一次覆盖呈现状态，末段不足 12 题按实际数量完成；以 Lall 全反馈视图的 `visits>0` 判断是否已学习。下一批优先展示尚未学习的合法候选，批内固定状态。**这是全量覆盖学习的调度措施，不能把其全部增量归因于取消三张限制；数量限制的匹配比较只用前 12 题。**

该状态只影响覆盖优先顺序，数值 Q 继续作为观察结果。全量仅一轮，不自动添加第二轮、扩召回或强制探索名额。

## 6. Q 如何记分

每个有效 c0/c1 代码尝试，对该次模型声明采用的唯一卡 ID 更新：

`Q_new = Q_old + 0.3 × (r − Q_old)`；Joint 通过 `r=+1`，完整测量下未通过 `r=-1`。

每次有效反馈均可更新，不是整道题只更新一次。同一张卡在 c0/c1 分别被采用，可以分别得到反馈。没有采用、技术故障、测量不完整或流程不完整，不强行赋分。全反馈与跨题族新增反馈两套数值分别保存；后者只接受已知跨题族事件。

多卡共享整份代码结果仍是当前奖励规则。这能增加反馈覆盖，却不证明每张卡都对成败有贡献。本轮不同时更换奖励函数，另报告第四张以后卡的适用性与代码落实情况。

## 7. 观察与判定

| 问题 | 必须报告的量 | 怎样解释 |
|---|---|---|
| 是否真正解除上限 | 每次候选数、选中数、声明采用数，超过三张的题数/尝试数 | 配置为不限量不足以证明模型实际多选、多用 |
| 是否覆盖更多新卡 | 从各自起点新增的有效反馈唯一卡数，主库累计覆盖率 | 12 题 Lall−L3 的新增卡差是直接数量策略信号 |
| 增量是否来自尾部 | 选中顺序第 4 位以后独有的采用卡、合格更新卡、新卡及独立题族数 | 分开“多选”“多用”“多反馈”，不把尾部反馈当独立贡献证明 |
| 是否重复更新老卡 | 已学习/未学习卡的更新次数、每张卡访问分布 | 更新事件更多，不代表不同卡更多 |
| 代码有没有改善或退化 | 首次与最终 F/S/Joint，同题救回/损失、公开接口错误 | 12 题只作开发信号，不凭点估计宣布 Q 有效 |
| 多卡是否带来干扰 | 新增采用的冲突/重复/附加前提、代码落实位置、截断与解析错误 | 由逐题记录说明具体原因，不把所有失败归因于卡太多 |
| 成本是否上升 | 各阶段调用、输入/输出 Token、Embedding、缺失用量；每新增反馈卡的 Token | 净增卡为零时，单位新增卡成本为 null 并说明原因 |

检索指标仅在有一致的候选池适用性标签时计算候选池内精确率、召回率和 F1。没有标签就标“未测量”。本轮不改变首次候选召回，不能把卡片 Q 覆盖率称为检索召回率，也不能声称测了全库召回率。

正确率不设继续门槛；未提分照样保存结果。技术/数据契约故障、上下文溢出、超出预算或输出盘不足是停止点，保留失败，不换题、不加重试来刷结果。若出现技术修订，先固定新版本和两组同规格，再继续，不覆盖旧记录。

全量结束分别给结论：增加反馈覆盖/覆盖增量有限；生成收益有方向性信号/未建立；多卡干预不足。即使覆盖增加，也不能直接写成学习 Q 提高了正确率；Q 作为参与者的有效性需要另外设计冻结比较，本轮不启动。

## 8. 规模、成本与产物

- 技术探针包含在 12 题对照内：`2×2=4` 次 P7。
- 12 题两组共 `12×2=24` 次 P7。
- 全量仅补 Lall 剩余 291 题，总计最多 **315 次新 P7、630 个代码版本**；不在本轮增加生成重复。
- 工程预算建议：前 12 题最多 400 万返回用量 Token、400 次逻辑 LLM 调用；包括先导在内全程累计最多 3500 万返回用量 Token、5000 次逻辑 LLM 调用，Embedding 输入最多 150 万 Token。按原生请求追踪计入重试；失败请求缺失用量单列，不声称这构成账单总量的严格上界。
- 当前 296 次新执行约使用 1952 万已知 LLM Token，仅供规模参照；多卡会增加后续输入，不能保证上述估计或把旧估价写成实付。实际金额没有账单时填 null。
- 本次设计检查 D 盘可用约 269 GiB；真实执行前重新检查空间，不自动删除历史材料。

实施时新建 `configs/cle_dinit_card_cap_20261020/` 保存无密钥参数与锁定名单；原生 `rows.jsonl / attempts / generation / validation / retrieval_trace`、反馈事件与两套冻结库放入 `translation_work/diagnostics/<实际日期>/cle_dinit_card_cap_v1/`。精简汇总放 `results/curated/cle_dinit_card_cap_<实际日期>/`，至少包含逐题成绩、逐尝试选用卡、逐卡覆盖、尾部反馈、错误与成本表。

报告须注明新入口实际版本、输入清单、协议和分支。保留旧实验，原入口默认三张；本轮不跑 D_gate、Base/Plus，不新建经验卡。
