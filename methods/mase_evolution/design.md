# MASE 架构与记忆共同进化：流程、证据与网页设计

日期：2026-10-13。状态：方法方向已获用户确认；本文件把工程设计具体化。当前先交付设计与证据审阅网页，不报告任何新方法效果。

## 1. 已确认的目标与边界

用户希望让大模型真正设计和改进团队的工作流程，不再仅从 protect/check/choose 三个手工模板里选择。保留经过来源验证与 family 隔离的 M1，允许其他训练任务的漏洞/修复代码示例；起点为“接口保护 + M1”。性能优先，没有每题六次调用之类的低预算限制。沿用旧 60 个 family 任务探索，冻结后另选未参与调参的任务确认。

新方法源码与网页置于本目录。仓库已有目录名是 `methods/`，不另建平行的 `method/`。逐题数据、候选代码、事件日志和截图按 AGENTS.md 放在 translation_work 中。Base/Plus、D_gate、正式 H_pass 不进入设计员反馈；PLT Python 使用 python -I 临时子进程，不启动 Docker。

目标不是多加几个角色，而是形成可复现的循环：**提出结构 → 真正运行 → 记录结果 → 分析失败 → 修改结构/记忆 → 重测 → 保存可用版本**。完整终身 MASE 是长期方向，本阶段只验证这一机制是否比固定流程有用。

## 2. 三种实现方式与选择

1. 加大手写模板菜单：实现容易，但仍然是人设计、模型选，不满足主要目标。
2. **模型生成可执行流程图（采用）**：基本操作可信且可复用，角色、提示词、依赖关系、分支、候选数、检查/记忆位置由模型提出。流程图通过同一个执行器运行，也直接驱动网页架构图。
3. 模型生成任意 Python 智能体程序：自由度更高，但代码错误和方法错误更难分离；作为第二阶段扩展，不把本阶段流程图称为完全任意程序搜索。

第一阶段允许任意数量的合法节点和组合，不设“三个角色/三个模板”的隐含菜单。执行器支持有向无环外层图及显式 repeat 子流程；重复的判断条件、停止原因必须记录。禁止使用 eval 来执行模型写出的条件。必要超时、重复提案与停滞检测属于运行保护，网页显示实际触发原因，不能伪装成“收敛”。

## 3. 两层团队与独立评分

### 3.1 解题团队：解决当前公开任务

输入只有公开题目、接口要求、合格的其他 family 记忆、先前节点产生的候选/消息，以及公开检查证据。角色可由设计员定义，例如需求分析员、生成员、检查员、反例分析员、选择员；角色名不决定权限。

基本操作包括：

- `llm`：自定义角色及提示词，可输出消息、结构化建议或候选代码。
- `memory`：检索、适用判断和注入；记录可召回、实际检索、拒用、实际注入的卡片 ID 与版本。
- `inspect`：执行公开接口 AST 检查与公开测试，区分未测量/通过/失败/未知异常。
- `select`：根据所有候选共享的公开检查严格改善才替换，保留所选 ID 和理由；模型选择建议尚未接入此操作。
- `branch`：明确记录“有已确认公开问题/无已确认公开问题”，由 problem/clean 箭头控制路径；目前不支持任意语义条件，不允许读取官方评分或答案。
- `repeat`：显式子流程循环，保留各轮候选，重复代码/无新证据/超时停止。
- `finish`：将最终候选固定下来；之后不得根据官方评分换答案。

架构可删除步骤、增加并行生成员、改变消息传递、修改提示词、移动记忆位置、调整检索策略与公开检查策略。不强制 CLE 四阶段。通用执行器、模型设计员、来源复核、真实操作绑定和训练搜索入口已实现。独立候选图目前按依赖串行调度，图中的独立角色不等于并行运行。记忆仍使用同CWE来源筛选与适用判断，允许修改迁移边界和注入位置；任意检索算法/工具集合搜索尚未实现。

### 3.2 设计员：改进下一批任务的处理方法

每一版先完成一批训练任务并固定最终答案。设计员随后读取公开题目摘要、生成候选、节点轨迹、版本差异和脱敏训练评分，提出新流程或记忆修订。

它不能读取当前目标参考答案、官方测试输入/夹具、隐藏异常原文、确认任务反馈或正式测试反馈。训练 task_id 可以用于记录，但不进入可部署的硬编码规则。原始响应与未脱敏长 prompt 不保留；保存受控的角色提示词模板、输入字段清单和指向公开内容的引用，不保存模型隐藏推理。

### 3.3 评分器：只提供测量证据

评分器在 finish 之后评估最终代码；所有唯一中间代码也可以事后评估，用来诊断“哪一步救回/破坏/漏选”。该旁路不接入当前任务的解题团队。训练分数以允许的状态/错误类别批量交给设计员。独立确认的分数只给用户，不回流。

检查器、解题团队、设计员、评分器的数据视图独立构造；仅靠提示词说“不要读答案”不够。graph 中不存在 official_score 节点或到解题节点的官方反馈边。

## 4. 一轮实际运行的完整流程

1. **准备与核验**：冻结 60 题清单、来源库版本、family 关系、源码/配置哈希。旧来源 36→31 合格只是历史事实；当前执行前重新确认缓存签名及来源质量。未观察到漏洞触发的来源单独标注，不声称证明了修复机制。
2. **基线重跑**：当前环境真实重跑 protect+M1；旧 26/60 仅用于历史参考，不能当作新实验的配对基线。
3. **设计提案**：模型输出完整图、角色提示词、记忆版本、修改列表、引用证据、预期改善机制、受影响指标与可能退步。
4. **结构检查**：检查节点/边/类型/起终点、输入可用性、无非法反馈、无无效循环。失败的提案也生成版本记录，状态为“结构无效”，不能从网页消失。
5. **小批运行检查**：使用 60 题中的明确标注子集查执行错误，结果不能当成完整 60 题分数；结构无效/缺测要先定位。之后通过的提案完整跑 60 题。
6. **训练事后测量**：冻结逐题答案后评分，记录每个唯一候选/修复步骤的八类验证状态；逐题事件与结果增量写盘。
7. **与父版本配对**：只比较同数据/环境/任务清单的已完整测量对，列新增 Joint、丢失 Joint、功能退步、安全退步及缺测变化。
8. **接纳或保留分支**：记录门控理由、证据与状态。净提升不等于统计显著。出现不同的功能/安全权衡时保留分支，不只留一个最高分。候选库与正式长期经验库隔离。
9. **提出下一步修改**：设计员从可修改点清单选择一项并说明依据；默认一版只改架构或记忆一种主要因素，少数联合修改必须标记“无法单独归因”。
10. **冻结和确认**：提前固定待确认版本/对照、指标、清单、源码、提示词、记忆、公开检查配置及环境哈希；之后另选独立 family 并只做一次预注册确认。确认后不能拿该结果继续调参并仍称其独立。

版本状态：草案、结构无效、待运行、运行中、运行中断、已完成待门控、探索分支、已接纳、已拒绝、已冻结、确认完成。父版本与架构/记忆哈希分别保存；v001/v002 是同一次 run 下的编号，不跨 run 混淆。

## 5. 数据隔离与确认集审计

60 题是已被多轮调参的开发任务，页面显著标注“探索集，非独立效果证据”。来源 family 与所有目标 family 隔离。正式 D_gate/H_pass/Base/Plus 完全不使用。

确认任务要排除本轮来源/60题/校准/回归和历史参与调参的 family。既有 A7 确认 50 题曾被查看并用于讨论，不能直接称为新方法从未参与调参的确认集。仅属于 D_init/D_grow 不代表历史上未被使用；执行前扫描能定位的历史清单、逐题结果和训练记录，写 history_exposure_audit.json。

确认目标建议 50 个 family，但数量取决于审计后剩余容量，当前不是已抽到 50 题的承诺。历史记录不完整时标注“未找到使用记录，无法证明历史纯净”；容量不足时先询问用户，禁止静默抽取已暴露任务充数。只有 manifest 确认后才启动独立效果评测。

## 6. 中间记录：让网页能查到每一次决定

| 文件 | 必须保存的内容 |
|---|---|
| run_metadata.json / manifest.json | schema、run_id、commit、源码哈希、模型/参数、环境、任务/family清单、历史暴露情况、记录覆盖、开始/结束时间 |
| versions/<id>/version.json | 父版本、状态、作者、架构/记忆版本、修改点、理由、证据引用、门控结果、所属实验组 |
| versions/<id>/architecture.json | 节点、角色职责、输入/输出、边、分支条件、repeat、最终输出、提示词模板版本；可直接画图 |
| versions/<id>/memory.json | 只记录该版本库的引用与哈希；卡片正文另存受控训练产物，并记录来源质量与family |
| versions/<id>/events.jsonl | 每个事件 ID、任务/节点/尝试/调用 ID、时间、父事件、输入引用、输出引用、状态/错误类别、停止原因、实际注入ID和usage |
| versions/<id>/rows.jsonl | 逐题候选代码、首次/最终候选、公开证据、事后评分、候选选择理由、完整节点轨迹、退步与未测量原因 |
| versions/<id>/summary.json | 从 rows 重算的结果和中间指标；记录公式版本、分母、缺测数 |
| versions/<id>/decision.json | 质量门控、训练有效性选择、独立确认分别记录；不得混称正式 D_gate 或 H_pass |
| hypotheses.jsonl | 可修改点、依据、预期指标、修改版本、复测结果、结论强度与下一步 |
| frozen_manifest.json | 选定版本和对照、数据/源码/记忆/公开检查/策略哈希、确认前时间戳 |

JSON 小文件使用原子替换，JSONL 写入后 flush；断点续跑 key 包含 run/version/task/attempt，缓存匹配全部影响行为的输入哈希。截断残行显式记录为“记录不完整”，禁止静默丢弃。并发记录单写入者或锁保护，不以网页服务负责写实验日志。心跳区分正在运行与中断，不能把没有进度误称已完成。

事件可追溯输入但不保存凭据/官方隐藏内容。网页只展示允许的引用和脱敏错误类别。历史导入不制造不存在的节点时间、提示词或官方中间分数。

## 7. 指标及精确分母

Joint 在本项目中表示同一候选语法/编译、功能、安全同时通过。主指标总分母固定为分配的 N 道题，显示通过数/N；还显示已记录数、完整测量数与缺测数。运行未完成时显示“进度 K/N；暂时通过 J”，不拿部分成绩当最终结果。已完成但缺测时同时显示已测 Joint J/M，仅用于诊断，不能替代主结果。

| 指标 | 计算/分母 | 用来检查什么 |
|---|---|---|
| Function / Secure / Joint | 通过数 / 分配任务 N；附已测数 | 真正功能与安全表现，不能相加推算 Joint |
| 新增通过 / 丢失通过 | 与父版本同题且双方完整测量的配对 | 净提升是否伴随退步 |
| 功能退步 / 安全退步 | 父版本该维度pass、新版本fail的完整配对 | 是否为追安全破坏功能，或相反 |
| 修复救回率 | 修复前 Joint fail、修复后 pass / 前后完整测量且前fail的修改对 | 修复是否有效 |
| 修复破坏率 | 修复前 Joint pass、修复后 fail / 前后完整测量且前pass的修改对 | 检查是否误导修复；另列功能/安全破坏数 |
| 候选成功上界 | 已生成候选中任一 Joint pass 的任务数/N | 生成能力；明确这是事后上界，不能部署 |
| 选择漏失率 | 有成功候选却最终fail / 所有候选评分完整且存在成功候选的任务数 | 选择员是否丢掉正确答案 |
| 接口违约 | 具有公开 AST 违约的候选数/实际审计候选数；按节点/首次最终分开 | 是否接口/全局对象被修改；不等于安全证明 |
| 公开检查误导 | 公开全pass但官方fail、公开fail但官方pass的候选计数/完整可比候选数 | 自生成检查是否与真实要求不一致；不是测试逐例精确率 |
| 检索→适用→注入 | 各阶段任务数/N，卡片次数另列 | 记忆是否真的到达角色；相关性不能冒充因果收益 |
| 记忆净收益 | 固定架构、同题有无记忆的完整配对 wins/losses | 记忆对结果的作用；未跑配对消融则未测量 |
| 节点覆盖/分支覆盖 | 已触达节点或路径数/设计中节点或路径数，附触发次数 | 图里画的东西是否执行；低覆盖不自动表示坏节点 |
| 交接可用率 | 成功收到且结构合格的必需输入数/必需输入数 | 上下游丢信息或结构错误 |
| 循环与失败 | 重复代码、停滞、超时、服务/结构错误次数及阶段 | 是否陷入无效工作 |
| 进化接纳/重复率 | 接纳/重复提案数/已评估提案数，区分无效结构 | 是否真的产生并保留改进 |
| 成本与时间 | 设计、记忆修订、公开检查、解题、评分分别记录；均值/p50/p95 | 与多采样同调用量对照，性能优先仍计账 |

分母为 0 的指标显示“未测量/不适用”，绝不显示0%装作结论。官方中间候选只有部分评分时不能推算所有步骤救回率。缺失字段通过 coverage 提示。新版本同时记录所有唯一代码的事后测量；历史 A7 只记录部分候选测量，需要明确区分“首次→最终的任务级变化”与“每次修复的步骤级变化”。

## 8. 可修改点清单

每条采用“观察 → 证据 → 假设 → 修改 → 应改变的指标 → 配对复测 → 结论”的格式。

- 选错候选：共享检查、选择员提示词、同分保留规则；看候选成功上界、漏失及最终Joint。
- 检查误导修复：修改检查生成/复核、修复触发、保留候选与回退；看修复救回/破坏、Function/Secure。
- 记忆拒用或无迁移：改检索/适用条件、角色可见性、注入时机；看检索漏斗并做固定架构记忆配对。
- 信息丢失：改边上的输入、角色职责或提示词；看交接结构错误与接口违约。
- 多余角色/循环：删节点、改条件、并行化；看节点覆盖、停滞、耗时，同时保证Joint。
- 家族/CWE集中失败：根据公开操作和任务条件分流；看分组指标与独立确认，禁止记住 task_id。

模型建议先叫“假设”，试验后才标“已改善/无收益/退步/证据不足”。网页显示修改关联版本，而不是只输出一串建议。

## 9. 网页：从总览到逐题

本地只读网页使用 Python 标准库 HTTP 服务与原生 JS/SVG，不需要 npm build/CDN。图从 architecture.json 生成，不另画与代码不同的示意图。服务仅监听127.0.0.1，文件入口有白名单，不提供任意文件读取或启动模型按钮。

1. **流程与设计**：双层循环、数据边界、实施状态、允许修改的内容；草案显示“未运行”，没有虚构分数。
2. **版本列表**：每次run、每个版本/父版本、修改原因、架构/记忆标识、状态、测量覆盖和Joint。历史A7与新版本不同标签。
3. **架构图**：节点角色、箭头信息、条件标签、点击节点查看输入/输出/权限；可切换总体设计和单题路径。历史图注明由手写代码重建。
4. **中间指标**：最终表现、修复/选择、记忆漏斗、接口/公开检查、覆盖和成本；指标说明含分母和缺测。
5. **逐题轨迹**：筛选通过/失败/缺测/CWE，查看候选代码、公开问题、记忆决定、首次→最终变化与调用事件。不存在的历史证据显示未记录。
6. **版本对比与可修改点**：同run/同阶段/同清单配对比较，新增通过/丢失通过列表、结构增删与角色提示词差异、假设状态及证据。不可比时明确拒绝出净收益结论。

页面显示“最后读取时间”和日志错误。后续活跃run轮询已落盘信息；实验失败仍可读。可导出脱敏JSON，架构SVG和当前表格。当前首次交付以历史数据验证交互，真实搜索接入后沿用同一契约。

## 10. 实验安排与判定

五组：固定protect+M1；仅一次模型设计；架构进化+固定M1；固定架构+记忆进化；架构记忆共同进化。追加调用量相近的固定流程多采样对照，不能把候选上界当实际选择结果。预算不优先限制探索，但所有成本都记录；保护性终止显式标注，可由用户继续。

探索版本主要按同题Joint净变化择优，同时单列退步、完整测量及关键错误。**用户已确认：允许按净提升择优，网页突出新增通过与退步任务；出现安全退步时需要单独审核，不自动晋升。** 不沿用旧A7“任一题退步即拒绝”的规则。训练门控与独立效果确认分开，不能将反复看过的开发结果称为独立有效性门控。
