# 来源参考代码用于复审：独立确认结果

**结论：**在16道未参与方案选择的题目上，复审时加入来源题参考代码的方案最终通过13/32次，原生提炼组通过18/32次，通用指导组通过15/32次。与原生组逐次配对，复审方案救回0次、损失5次；本次没有达到预设的提高通过率门槛。

19道开发题上，该方案按预先确定的选择顺序进入确认。确认集共16个不同近邻题族，每题每组独立生成两次，允许修复一次；模型、题面、验证器及单次预算一致。原生组使用原生提炼的经验，复审组使用加入来源参考代码复审后的经验，通用组使用固定的通用指导。各组正常选卡；参考代码只来自来源题。

复审组相对原生组的同时通过率差为−15.6个百分点，按题族计算的自助法95%区间为−31.3至−3.1个百分点；对两项主要比较做Holm校正后的精确题族置换检验p为0.25。复审组相对通用组救回2次、损失4次，差为−6.3个百分点，95%区间为−18.8至6.3个百分点，校正后p为0.625。区间和p值采用不同方法，均按题族处理；16个题族的结果支持保留这次负向结果，后续方法选择以更多独立题目为依据。

同一道题两次最终结果不一致的数量分别为原生组2/16、复审组5/16、通用组3/16。首次选中至少一张经验卡的次数分别是原生组28/32、复审组28/32；实际声明采用至少一张的次数分别是18/32和20/32。通用组的固定指导按协议直接提供。卡片编号相同的不同经验库可能包含不同正文，选中或声明采用也需结合代码判断是否落实。

对全部11组成败差异逐一阅读了题面、选中卡片、采用记录、计划、每轮代码及原验证结果。用户数据题中，复审组修复后仍清空宿主字典，原生组修复后保留数据并通过。OAuth回调题中，复审组保留宿主允许域名并通过，通用组把域名配置重置为空而拒绝合法回调。API地址题的复审组额外拒绝保留地址；合成DNS结果可重现与其他两组的差异，但原运行未保存解析地址，具体失败触发条件未能定位。设备数据题的公开描述未明确应返回调用参数还是辅助函数结果，原测试要求后者，已登记待复核。
