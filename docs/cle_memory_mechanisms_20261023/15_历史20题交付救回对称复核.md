## 3. 两个方向都能出现“建议与整次奖励不一致”

14报告发现，1241和352的保留义务未落实，卡仍获负奖。救回复核发现相反方向也存在：不是每次正奖都代表卡的具体建议被正确实现。

| 题目/采用卡 | 核对到的建议与实际代码 | 原记账 |
|---|---|---|
| 1004，`hint-79-7759492040233661517` | 卡建议增加一个必填模板参数；新代码保持公开四参数，未执行该建议，外部模板例子通过 | Q −0.3→0.09，奖励+1 |
| 1063，`hint-915-7089564609077456558` | 要求非法字段显式ValueError；共同采用的另一张卡要求静默跳过，新代码执行跳过 | Q −0.057→0.2601，奖励+1 |
| 999，`guard-79-3710351121249422672` | 禁止修改外部BLOG_FORMAT；新代码却重新定义了模板，公开替代模板例子失败 | Q −0.3→0.09，奖励+1 |
| 1022，`hint-862-8899825322851418978` | 保留类型注解、删除空字典；新代码落实，公开配置更新改善 | Q 0.45176259→0.616233813，奖励+1 |

第一行不表示整张卡没有帮助：同卡还反对硬编码，其他共同采用卡也在提醒保留模板。第二行证明同时出现相反建议，不证明两卡在各自来源任务都错误。第三行说明验收+1并不保证全部公开情形通过。第四行是与具体有益建议一致的正向案例，但仍没有隔离Q选择的贡献。

1158是另一种情况：最终代码Joint通过，`workflow_completed=false`，规划解析报错；两张卡的奖励为空、Q保持0.3与0.363，并未获+1。1113无采用卡，同样没有卡片正更新。不能用“成功题数”推算“成功Q更新题数”。

## 4. 这轮证据怎样影响下一步

1. **保留公开对象是优先验证点。** 损失方向有12题配置替换加150的类替换；救回方向有7题配置恢复，且本地例子有正反证据。下一步应在相同题、相同卡、相同预算下验证消费者保留义务，而不是继续刷Q覆盖率。
2. **用Joint训练Q是结果代理，不是单卡因果鉴定。** 多卡同奖惩、未执行建议仍获奖、局部契约缺陷未被当前测试暴露，都可能使Q混入其他因素。不能据本次样本计算整库“错误Q率”，也不据此擅改奖励。
3. **先对称查看同成绩对照。** 38道成绩改变题是事后筛选样本；此前足迹规则在9道都失败题也有标记。需要复核这些例子及无标记的通过例，不能直接用本批训练或启用缺陷门控。
4. **付费和旧Q主线维持暂停。** 新消费者效果、粒度C1、分类器与Q确认均没有因此通过。中转代码控制、公开政策、人审与来源材料各自保持原门。

还核对到现行v3足迹的具体盲区：999和1063的`new_external_rebindings`以及旧/新公开静态规则标记均为空，但本轮外部配置例子两侧都失败。因为两侧已经共同包含硬编码，差分中的“新增重定义”不会触发。未触发标记不能作为正确性通过门；本轮没有看见盲区就立刻改规则、再用同批题宣布提分。

没有同条件重复/反事实时，不能把尚未解释的差异统称模型偶然噪声，更不能给出噪声失败题数。本轮定位的是可复现行为、具体实现错误及信息缺口。
