## 1. 结论与本轮范围

推荐先做“**固定经验内容，学习并冻结 Q，再比较选卡效果**”，有信号后再接入完整 CLE 经验进化。Q 是每条经验在当前生成流程下的历史收益估计，负责改变选卡；不更新模型权重，也不替代经验适用性判断或候选门控。

研究问题是：**在同样的经验库、候选池和生成预算下，历史测试反馈学出的 Q，能否比单纯语义相似度选出更有用的经验，使最终功能与安全联合通过率提高？**

## 2. MemRL 原文与作者实现核验

已下载并抽取 [MemRL v2 原文](https://arxiv.org/pdf/2601.03192v2)，共41页；重点核对第3–4节、5.4节与附录E，并渲染核对第4页公式。下载与作者代码快照保存在忽略区：

```text

  MemRL_2601.03192v2.pdf
  MemRL_2601.03192v2.txt
  MemRL_page4.png
  official_tree.json
  official_code/
```

原文第4节：先按语义相关性形成候选，再用标准化的相似度与 Q 组合选卡；对实际进入生成上下文的经验，用环境奖励更新 Q。第4页式(4)、第5页式(7)分别为：

\[
Q_e\leftarrow Q_e+\alpha(r-Q_e)
\]

\[
score(q,e)=(1-\lambda)z(sim(q,e))+\lambda z(Q_e)
\]

附录E表8中，BigCodeBench 使用 `alpha=0.3`、`lambda=0.5`、`Q_init=0`、`delta=0.38`、`k1=10`、`k2=5`。**其中阈值依赖数据与 embedding，不能直接当作 CLE 的阈值。**

另核验作者仓库 [MemTensor/MemRL](https://github.com/MemTensor/MemRL)，代码快照为 `c1b322ca43de36ddf64c6712f89d0095bfc35ce0`：

- [value_driven.py](https://github.com/MemTensor/MemRL/blob/c1b322ca43de36ddf64c6712f89d0095bfc35ce0/memrl/service/value_driven.py)：`QValueUpdater.update` 更新Q与访问次数；该文件的 `ValueAwareSelector` 是另一个按Q排序并可随机探索的入口。
- [memory_service.py](https://github.com/MemTensor/MemRL/blob/c1b322ca43de36ddf64c6712f89d0095bfc35ce0/memrl/service/memory_service.py)：`retrieve_query` 有相似度/Q组合评分，`update_values` 根据结果更新记忆。
- [BigCodeBench配置](https://github.com/MemTensor/MemRL/blob/c1b322ca43de36ddf64c6712f89d0095bfc35ce0/configs/rl_bcb_config.yaml)：使用成功/失败奖励 `+1/-1`。

本任务以论文式(4)/(7)为设计依据，不把当前作者仓库所有检索入口当成同一种实现。CLE保存的是带边界的抽象经验卡，本次是 **MemRL式机制接入**，不称完整复现 MemRL。

## 4. 具体接入方案

### 4.1 最小数据结构

在 `SecurityInvariantNode` 增加两个字段，并完成 `to_dict/from_dict` 往返：

```python
q_value: float = 0.0
q_visits: int = 0
```

旧JSON缺字段时按未学习的0/0载入。这是现有持久化输入所需的兼容，不迁移或覆盖旧库。Q=0是未学习初值，不解释为50%成功率。Q依赖生成模型、语言、提示和使用流程；不同配置独立保存，不共用一份可写Q。

新卡Q从0开始；经验正文被吸收、修订或归并改变时Q归零。只有状态改变而正文未变，不自动奖励或清零。旧 `support_count/regression_count/utility` 不改语义。

### 4.2 数值模块与三种选择方式

拟新增 `methods/sct_trajectory/memory_q.py`，只实现本次用到的纯数值函数：

```text
reward_from_evidence(evidence) -> +1 / -1 / None
update_q(q, reward, alpha) -> new_q
rank_memory_q(candidates, lambda_q, delta, limit) -> selected, scores
```

从现有 `semantic_select` 提取共同召回部分，复用语言/状态过滤、embedding与24+8候选逻辑。保留现有 `semantic_llm` 行为，增加 `semantic_sim`、`semantic_q` 两个选择模式，不建设另一个记忆服务。

```text
semantic_llm：当前候选联集 → 当前LLM选卡 → 复析/程序采纳
semantic_sim：同一候选联集 → 语义门槛 → cosine top3 → 复析/程序采纳
semantic_q：  同一候选联集 → 同一语义门槛 → sim/Q组合 top3 → 复析/程序采纳
```

`semantic_sim` 与 `semantic_q` 的候选、阈值、最大3张卡和下游调用一致。Q仅改变选卡；不取消当前模型对适用条件和排除条件的判断。

首轮固定 `alpha=0.3`、`lambda_q=0.5`、`Q_init=0`、`gamma=0`。候选范围沿用CLE的24+8，最大注入仍为3，因此不是直接复制论文的10→5。

阈值 `delta` 的拟定校准规则：先准备学习区c0的公开初析并缓存，用与真实检索相同的查询投影计算其与可用卡的余弦分布，取80%分位；排除确认/最终测试任务，校准后冻结。初析可复用于随后的E1生成，单列准备成本；修复查询继续使用该已冻结阈值，不根据修复得分重选。该规则针对CLE的查询—卡表示，是本方案的适配，不是论文原实验参数。记录空召回率与少于3张的比例，不为凑数绕过阈值。

组合评分的z-score在门槛后的候选内分别计算；标准差为0时该分量为0。候选为空返回空；并列依次按cosine、稳定ID排序。第一版不加随机探索、Q淘汰阈值或新奖励权重。

Q为常数时，`semantic_q` 应与 `semantic_sim` 选卡相同；这个消融先用纯数值检查完成，无需为完全相同的上下文重复付费。

### 4.3 奖励和逐次归因

仅在两维测试状态均明确为 `pass/fail` 时学习：

| 同次代码测量 | r | 处理 |
|---|---:|---|
| 功能通过且安全通过，A | +1 | 更新实际采用的经验 |
| 仅功能通过，B | -1 | 同上 |
| 仅安全通过，C | -1 | 同上；不奖励破坏功能的“安全” |
| 两维均失败，D，且有明确测量 | -1 | 同上 |
| API失败、空代码、环境错误、测量缺失 | 无 | 保存原因，不更新Q |

不能只看 `states` 的A/B/C/D：现有代码会将空代码标D，但那不是一条完整可归因的测量。Q更新以验证证据为准，正式正确率仍按既定任务分母报告。

每次生成测试完，只更新该次 `pipeline['cards']` / `agent_context[i]['injected_cards']` 中唯一的经验ID。召回但未采用的卡不更新；多卡共同被采用时，每卡各接受同一个r一次。这是共享结果归因，不能称每卡的因果贡献。

```python
# 示意插入点：_run_rollout 中 validate_and_state 之后，A态早停之前
evidence, label = validate_and_state(row, code, timeout=self.timeout)
if learning_phase == 'D_grow':
    reward = reward_from_evidence(evidence)
    if reward is not None:
        for experience_id in unique(actual_injected_ids):
            node = nodes_by_id[experience_id]  # 对应当前可写训练库中的节点
            node.q_value = update_q(node.q_value, reward, alpha)
            node.q_visits += 1
# 随后再执行原有 if label == 'A': break
```

c0与c1分开记账：不能把修复后成功奖励补发给首次生成所用的另一组卡，也不能在 `_run_rollout` 与 `on_item` 回调各更新一次。同题首次A早停也必须留下正奖励。

例：Q从0开始，实测失败后为-0.3；随后实测成功后为0.09。这个数不是安全认证，也不是增量提分。

### 4.4 更新边界、冻结与并发

- 首版只允许在D_grow的专门校准阶段更新Q。D_gate、H_pass、运行收尾审计、Base/Plus均只读Q；Phase1提供共同初始库，不用来源题成功直接给卡加分。
- 先以 `workers=1` 实现和验证顺序学习。现有线程完成顺序会影响EMA结果，不能直接开原来的高并发并声称同一学习过程可复现。
- 固定库阶段只允许写Q，禁用该阶段的即时提炼、增卡、改正文和门控；这属于专门校准runner，不借用 `FrozenGuard` 把Q也一起锁死。
- 完整CLE阶段再接入 `_run_rollout` 的学习钩子；并行扩展若需要，采用共同Q快照与固定任务顺序提交，另作明确改动，不在首轮搭建并发平台。
- 冻结时在现有JSON/元数据中保存Q、访问次数、模型、embedding、候选规则、阈值、alpha/lambda及更新边界。复用现有冻结检查，不另建一层哈希体系。
- Q诊断留在研究记录中，经验正文与模型提示的字段投影不新增Q；注意检索器给卡附加的 `retrieval_audit` 可能继续进入蒸馏，完整接入时也应隔离这类数值诊断。

用合成数值检查更新、z-score与筛选即可，不运行任务代码、不调用API。检查Q排序能否改变集合：候选数不大于3时可能只有顺序变化，Q全相同则没有干预。离线同时统计实际选卡变化比例，不据此冒称正确率变化。

这样先获得一份共同的可冻结Q估计，后面的组间差异只来自选择规则。它是固定曝光校准，不是完整在线自进化；后者留到E3。

### E2：冻结同一份M_Q，做三组配对开发对照

在未参与Q学习的既定D_gate中预选24题；不足时据实确定数量，不扩充或翻译新题。各题三组都跑，初次公开任务分析可共享，后续修复反馈各自独立。

| 组 | 选卡方式 | Q在此阶段更新？ | 回答什么 |
|---|---|---|---|
| T0 CLE原版 | `semantic_llm`，原LLM选择器 | 否 | 当前方法参照 |
| T1 相似度对照 | `semantic_sim`，门槛后cosine top3 | 否 | 移除独立选卡调用后的参照 |
| T2 Q选择 | `semantic_q`，同候选/门槛，sim+Q top3 | 否 | **与T1比较，隔离Q排序作用** |

T0不新增语义门槛，因此T2−T0是整个选择器替换的效果；不能单独归给Q。T1/T2具有相同筛选门槛与生成调用预算，T2−T1才是首要机制对照。组内LLM都继续执行复析和程序采纳，Q不能强迫采用。

首次通过早停、最多一次修复，各组一致。训练侧验证器保持同一版本。比较顺序按预先固定的任务ID规则交错，避免一组先全部跑完再遭遇服务状态变化。

若T2有可继续的信号，再增加T3：与T2同结构，但Q项换为标准化的既有 `utility`。T2尚未优于T3前，不能声称“学习Q优于已有支持/回归启发式”。不在第一批同时扩奖励函数、教师模型和语言。

### 终点、统计与否证

主终点为每题交付代码的Joint；同一任务只算一次，首次成功早停。首次Joint为次要终点；同时报告Function、Secure、A/B/C/D与未测、API/解析失败、错误回归、召回/采用比例和成本。

主比较预先指定T2对T1。记录救回数b、损失数c，`DeltaJoint=(b-c)/N`；报告配对置信区间及McNemar检验。family有多条任务时按family处理聚类；不能把同题修复、重放和译本当成独立样本。多个确认性比较需按预定方式校正，24题探针不足以承诺显著性。

解释规则：

- T2优于T0但不优于T1：可能是简化选择器或门槛带来的效果，不能证明Q有效。
- Q有差别但最终采用集合几乎相同：报告机制干预有限；不能把调用节省当作正确率提升。
- Q与结果相关但T2不提高Joint：仅支持相关性，不支持方法提分。
- Joint上升但功能回归、缺测或调用预算发生变化：列出变化，不能隐去损失。
- 无提升也保存零结果、任务清单与逐题配对，不改成累计“曾经成功”率。

Q版主线配置应明确为 `ablation=A7, retrieval_mode=semantic_q, context_pipeline=True, repairs=1, branch_count=1, gate_mode=candidate, language=python`。这是待实现模式的目标配置，不是当前CLI已经支持的命令。

## 7. 成本与最少产物

数值Q更新本身不增加模型调用，但取得奖励需要代码生成与真实测试。T1/T2少一次独立选卡LLM调用，节省可能来自这一结构变化，要与Q收益分开报告。

不计重试与可选内部测试，未共享初析时，T0每次生成约5个LLM请求，T1/T2约4个；失败后再走一次相同流程。按24题校准加24题三组比较、全部两次生成粗估，约 `24*8 + 24*(10+8+8) = 816` 次成功路径请求；共享初析、早停可减少，网络/协议重试会增加。**这不是费用报价或硬调用上限。**

先零API检查，再做2–4题链路探针，再按实际usage估算24题预算。Q采集成本单独归入Q方法；已有日志复用也说明原采集成本。至少并列报告训练/校准总成本、在线每题成本和摊销成本，不能只报少一次在线调用。

复用 `CostTracker` 与既有记录方式，不新增计费平台。模型ID、embedding和采样参数从实际无密钥配置/运行元数据确定；本机CLI的embedding默认是large，旧描述可能使用small，不能混用阈值或缓存。

拟新增运行目录：

```text
translation_work/diagnostics/20261015/cle_memory_q/<run_name>/
  run_metadata.json              # 来源、模型、池、参数、阶段与反馈边界
  input_memory.jsonl             # 实际初始库副本
  frozen/m_star_q.jsonl          # 含Q与访问次数的冻结库
  memory_q_events.jsonl          # 学习事件；不复制完整测试输入或答案
  rows.jsonl                    # 沿用attempts中的代码、证据、采用与检索记录
  summary.json                  # 配对指标、覆盖与分组用量
  report.md                     # 实测结论、失败与未完成项
```

Q事件最少包含：`task_id/family_id/pool/outer_round/attempt/invariant_id/selection_policy/q_before/reward/q_after/q_visits`；未更新时写跳过原因。该记录直接服务于排查错归因、重放学习和研究Q变化，不另建通用审计系统。

原始运行区保持忽略。后续经授权上传时，GitHub放源码、无密钥配置与精简汇总；需要完整运行材料时另交付脱敏ZIP，不强制提交 `translation_work/`。网页接入真实产物；不能把示例变成“测试记录”。

## 9. 对贡献的定位

“经验Q更新＋价值选择”直接借鉴MemRL，不能单独宣称原创。当前可验证的增量是它在CLE双维目标、实际采纳与生命周期下是否有效，以及完整成本是否划算。若简单Q有收益，再研究能区分功能损失与安全损失的奖励或更可信的多卡归因；这些属于后续方案，第一轮不混入。
