# S5全卡动作撤回材料审阅

50例补充材料已审定并冻结，覆盖144份实际可见卡。E3/E4共涉及103份卡的386个文字字段，41份卡完整保留。原固定实验、原卡正文与原结果保持原样，本次新增模型调用为0。

本次复用原完整逐卡阅读记录，重新阅读目标相关原句，并逐项决定整句撤回、只撤回片段或保留。逐例决定保存在 `configs/cle_weekly_closure_20261107/review_decisions.json`；对应坐标、原文和保留说明写入运行根下50份 `materials/S5-Dxxx.json`，没有通过关键词命中自动批准。

## 1. 审阅解决了什么？

|问题|审阅后的安排|
|---|---|
|同一建议可能存在于多张卡|逐例检查全部可见卡；103份卡存在需要撤回的目标信息，其余41份不动|
|一句话包含两个独立动作|只撤回与目标有关的片段。例如撤回排除多个@的正则建议时，保留254字符上限|
|删动作时也会删掉理由或适用条件|11例归为动作建议撤回，39例归为动作及相关信息撤回；总体和两层分别分析|
|卡片对同一问题给出相反指导|保留不属于本例目标动作的相反指导，并登记其存在。此批检验撤回指定信息的影响，不同时纠正其他卡|
|字符遮蔽可能改变输入外观|E4保留字段、卡号、顺序、换行和转义字符，实际原生渲染后的字符数与E0一致；模型Token另按实测记录|

E3/E4仍使用原50例、29个近邻组、每条件两次重复，共200个新增首次生成单元。原E0结果只读引用。每份新代码只做首次生成，没有付费修复。

## 2. 哪些具体内容得到保留？

|案例|撤回的目标信息|保留的其他要求|
|---|---|---|
|D003|域名捕获组排除@、限制多个@及对应正则例子|254字符边界、非法输入返回约定|
|D014|用环境变量和测试默认域名替换原配置|单层子域比较、协议和IP限制|
|D021|统一为一个按端口区分的匹配循环|路径拼接、IDN处理和协议检查|
|D028|compare_digest与恒定时间比较|先验签再访问、输入归一化和信任来源|
|D038|额外字符白名单层|AST结构检查、节点白名单和安全求值|
|D047|放宽到Mapping的建议、来源假设及失败解释|CSRF值比较、用户ID要求及字段名问题|

D047原卡还包含一处明确的解释错误：`isinstance(value, dict)`接受dict子类，`OrderedDict`也能通过该判断。它不接受`UserDict`等其他Mapping实现。已在本地零API核对这一区别。原卡的错误解释留在原对照中，新材料只按登记范围撤回，未借机改写对照。

## 3. 后续结果可以回答什么？

总体比较回答：撤回目标相关经验信息后，生成代码是否还实施同一动作，Joint如何变化。39例同时改变了动作建议及其说明，因此按“目标相关信息撤回”解释；11例另列更窄的动作建议分析。所有50例和两次重复均保留，不按效果筛掉案例。

目标动作是否落实，需要在生成后逐份阅读代码并登记。声明采用某张卡、Joint变化或关键词出现次数都不能代替该判断。仍按原方案统计E0−E3、E0−E4两项主要动作落实比较及Holm校正，Joint、重复波动、卡片冗余和干预类型分层作为配套分析。
