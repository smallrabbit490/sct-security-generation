# 修订32道D_grow题：公开契约与Q收益的最小再生成实验

日期：2026-10-20。协议：`cle-dgrow-contract-versus-q-regeneration-v1`。状态：**DESIGNED_NOT_EXECUTED（完成设计，未启动新初析、Embedding、选卡、代码生成或Q学习）**。操作属于A（固定经验库的训练侧开发评价），不是重新训练完整CLE，也不是独立最终测试。

## 1. 这次具体回答什么

1. 在相同的恢复版测试下，补齐公开契约（模型可以看到的任务要求）能否减少错误配置、提高功能及Joint（同一份代码功能和安全都通过）？
2. 公开契约相同时，冻结Q（由历史反馈得到的经验评分）是否提供超过纯相似度与打乱Q的额外收益？

本轮不研究“测试恢复本身使旧代码分数改变多少”，这个问题已有独立补测记录。所有新组都使用恢复后的测试；不能让旧题面组继续使用损坏测试。两组旧生成代码不充当新对照。

## 2. 设计依据与一个必须先解决的限制

已核对32题均属于D_grow，其中CWE601为8题、CWE918为24题，共28个项目推断family（题族）。24题补了context，1399补了security_policy，另外7题只修测试、公开题面没变。因此：

- 契约干预有25题，主要报告24题context补齐的配对结果；1399是安全政策恢复的单题案例，另列。
- 7道公开题面不变的题不重复跑“旧/新题面”两次，A/B共用同一条结果，不当作7个额外独立比较。
- 全32题可报告各策略Joint，但不能把其中7个零差值当成7次契约改善证据。

2026-10-20零API检查发现：原M1和资格屏蔽派生库内，CWE601的162张卡、CWE918的90张卡均为Q=0、visits=0。历史观察组32个首次候选中，只有676出现1张非零Q卡，其余31题没有。检索允许跨CWE召回，所以不能仅凭同类卡全为0就断言未来查询必无Q作用；但必须用新查询核对实际干预。

这些历史曝光数是只读诊断，不是新协议结果。若某查询的候选Q全相同，λ=0.5只会缩放相似度分数，通常保持其顺序；最终仍应以原排序函数逐项比较，处理并列。不能将完全相同的策略重复生成后出现的随机差异解释为Q收益。

## 3. 最小实验组：两组必须，另两组有条件执行

|本协议组名|模型看到的公开题面|候选呈现给LLM的顺序|用途|
|---|---|---|---|
|A old-contract-sim|原始公开字段|纯相似度|契约对照|
|B repaired-contract-sim|修订后的公开字段|纯相似度|共同基线|
|C repaired-contract-Q|与B完全一致|相似度与冻结学习Q融合|测当前Q的增量|
|D repaired-contract-shuffled-Q|与B完全一致|同CWE打乱(Q, visits)后融合|判断学习评分是否优于随机分配|

主要比较：**B−A对应契约；C−B对应Q增量；C−D对应学习评分相对置换的增量。** 不用C−A证明Q有效。不设置“旧题面＋Q”，所以本设计不估计契约与Q的交互作用；这是节省预算的有意取舍。

A/B在未改公开题面的7题合并。Q路线没有达到下述曝光门时，不运行C/D，也不把“未运行”写成“Q无效”。D使用`shuffled_memory(..., seed=20261015, scope='cwe')`一次固定置换，不挑种子。

## 5. 固定名单与执行顺序

完整32题及题族见`configs/cle_dgrow_contract_q_20261020/manifest.json`，无新增题、无按新成绩换题。8题探针固定为：

`675、1399、1080、1081、1083、1084、1085、1087`

8题来自8个不同题族：包含一题公开不变对照675、一题安全政策恢复1399、六题context补齐。按修改类型和原ID确定，不按新得分或Q改选大小筛选。675和1080作为最先执行的两道技术探针，计入8题，不另加预算。余24题包含同族变体，只能称固定开发扩展，不是独立确认。

步骤：

1. **零API准备。** 按ID装配题目，核对仍在D_grow；复用修复v2回执、冻结库与旧产物。建立A/B公开字段差异，确认25题有变化、7题完全一致；列32题的原始学习/开发暴露。新输出另建目录。
2. **只生成8题必要初析并召回。** 新题面8份、旧题面7份，共15份；675共用。仅使用公开字段，复用卡向量缓存。对新题面8个共同候选用纯相似度、冻结Q、打乱Q离线排序，不额外调用LLM选卡。这时执行G1曝光门，决定是否运行C/D。
3. **两题技术探针。** 跑675和1080的A/B及获准的C/D。分别检查阶段、三卡限制、初析共享、验证器和落盘。结果正确率不作技术门；流程故障则停止后续，不换题补跑。
4. **完成8题开发探针。** 用固定任务内随机组序seed=20261020，完整保留首次与修复。按G2契约路线、G3 Q路线分别判断是否继续；实际调用和失败也计成本。
5. **仅扩展通过门的路线至固定余24题。** 契约通过则完成A/B；Q通过则完成修订题面B/C/D，若B已执行直接复用。本轮最多覆盖这32题，不自动学习Q、不启动D_gate或Base/Plus。完整32题阶段按整批执行，不按中途高低分调参。

## 6. 每道题要记录什么

保留原生`rows.jsonl / attempts / generation / validation / retrieval_trace`，新增身份为task_id、family_id、public_contract_version、evaluation_version、memory_version、arm、首次/末次。7题A/B别名另存，不伪造两条独立运行。

- 结果：计划/完整测量/缺测、首次和末次F/S/Joint、救回与损失。
- 契约路径：是否正确引用外部配置，是否重定义配置、改名自拟列表、改变签名/返回/异常；新旧代码实际差异。先按公开契约标注，再用夹具反馈解释，不反写答案。
- Q路径：候选中visited/nonzero-Q比例、B/C/D同查询呈现差异、LLM实际选入、声明采用、代码落实、最终是否救回。数值前三变化与实际选卡分开。
- 成本：初析、各组及各阶段LLM逻辑请求/实际HTTP尝试/输入输出Token、Embedding缓存命中与新增输入Token、失败/格式重试、验证次数和时间。未知usage记未知，不填0；共享费用只计一次。

Joint不能分离所有因果原因；一条“Q救回链”至少要看到同查询顺序改变、选入/采用不同成员、代码落实对应建议及同份代码F/S通过。链条证据仍是机制支持，不把单卡归功当严格因果贡献。

## 7. 继续或停止的门槛

下列是限制投入的工程门，不是统计显著性标准，也不追溯修改旧实验门槛。

|门|通过条件|未通过时的结论和操作|
|---|---|---|
|G0 输入与执行门|修复v2回执对应当前输入；代码和参考环境一致；两题探针无基础设施、解析、上下文传递、原生格式或预算故障|工程未就绪，停止；真实模型功能失败不冒充环境故障|
|G1 Q曝光门，代码生成前|8个新题面共同查询中，至少3题有非恒定Q且C相对B改变完整呈现顺序；至少3题C相对D改变呈现顺序；分布不满足则不再换样本/置换种子|本批没有足够可识别Q干预，C/D不生成；可以继续A/B。不能写Q普遍无效|
|G2 契约路线8题门|在7个公开有变化的配对题中，B较A功能净增≥2题、Joint净增≥1题、安全通过数不下降；至少2题存在可核对的配置/公开要求修复链|不扩大A/B；写当前公开补齐未建立足够新生成收益，并分开解释1399与context题|
|G3 Q路线8题门|G1已过、C/B/D均完整；C相对B和D的Joint各净增≥2题，F不低于B；至少2个不同题族新增成员被实际采用，至少1条可核对的救回链|只改序/采用但无净收益：收益未建立；没有采用变化：干预不足。停止Q扩展，不为获得Q而自动加学习|
|G4 固定32题开发扩展后|契约：变化题配对F/Joint均正向且错误配置减少，24个context题与1399分别报告。Q：C对B、D的Joint各净增≥3题、F不下降，并有≥2个题族救回链；预算与流程门均满足|未过即结束该路线。通过仅建议另立小型跨family迁移确认，不自动重开全量D_gate|

若G2未过而G3通过，只扩展B/C/D；若G2通过而G3未过，只扩展A/B；两者都未过，8题收口。缺测或技术故障使推进门待定，不在不完整分母上宣布通过。

最终按题配对，报告救回/损失、题族聚类95%区间。契约主比较为24个context题B−A，另列1399；Q的C−B与C−D组成两项比较族，沿用题族配对置换检验并做Holm校正。必须说明按8题表现决定扩展产生的选择影响；整个32题是开发证据，即使校正p≤0.05也不是独立确认。只提点估计或未显著均不写普遍有效/无效/等效。

## 8. 成本：先设数量上限，再看实际费用

没有当前中转站账单和实际单价，本方案不编造人民币金额。历史全D_gate记录中，扣除共享初析，各P7均值约7.34个逻辑LLM请求、7.01万Token；初析约1581 Token/份。只作为粗估，本批32题难度和请求长度可能不同。

|---|---:|---:|---:|---:|---|
|8题仅A/B|15|30|15|约108万|150万；250次|
|8题含C/D|31|62|15|约220万|320万；500次|
|全32题仅A/B|57|114|57|约409万|600万；1000次|
|全32题仅B/C/D，含既有8题A|103|206|39|约728万|1050万；1700次|
|全32题A/B/C/D全部|121|242|57|约857万|1200万；2000次|

说明：全32题四组理论128次，公开不变7题A/B合并后121次；8题四组32次减675合并1次为31次。表中是累计上限，不将探针再加一遍。只扩展B/C/D时保留已执行的7条A旧题面结果，所以96+7=103次；39份初析=32份新题面+7份探针旧题面。

普通成功路径：每P7除共享初析之外，首轮4个请求、修复轮5个；选择器格式重试各可再加1个，因此逻辑请求最大为`初析份数 + 11×P7运行数`。全部四组至32题最多1388个逻辑请求；网络层重试可能增加实际HTTP次数，不能用该数字充当物理调用硬上限。

达到Token或实际HTTP预算任一阈值就停止启动新请求，保留在途请求账目；最后一次请求可能越过阈值，单列越过量。并发固定1以限制在途量，不自动上调max_tokens或补充预算。新增Embedding查询Token单独封顶50万；32题全部四组最多57个首次查询及121个修复查询，卡向量复用缓存，冷缓存不自动重算全库。初析、检索、重试在生成前已经发生的费用也计入；无Q代码生成不等于Q诊断完全零费用。

人民币费用在执行前依据本机账号实际输入/输出/Embedding单价填入：

`费用 = 输入Token/10^6×输入单价 + 输出Token/10^6×输出单价 + Embedding输入Token/10^6×向量单价`。

缓存计费按实际账单分类；模型、价格或服务方变更需要重新锁定协议，不把旧估价写成已付款。

## 10. 本轮设计交付与结论边界

只读准备确认了32题/28题族、25个公开变化/7个不变，及当前两库本类Q全零、历史首次候选仅1题有非零Q。尚未实施或运行新生成器，未发生新实验API/Embedding调用、Q更新或D_gate测试。

默认建议：先执行15次P7以内的8题契约对照，C/D必须先过曝光门。若当前库仍没有足够Q差异，就明确收口为“修订契约可以测，当前Q效用在这批题上缺乏可识别干预”；后续若希望检验新学习Q，必须另立学习/跨family评价方案，不能边学习边拿本批成绩当冻结对照。
