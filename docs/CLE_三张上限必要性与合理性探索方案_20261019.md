# CLE 三张上限：必要性、实现正确性与取舍探索方案

日期：2026-10-19。协议草案：`cle-card-cap-study-v1`。当前状态：**DESIGNED_NOT_EXECUTED（方案已形成，真实对照未执行）**。

本轮完成代码核对和零 API 历史计数，未启动新的生成、标注或 Q 学习。工作分支为 `fjy/cle-q-exploration-20261018`，基线提交为 `feff42e91ec04b0e276204c508e98fe9e8b9f833`；执行时还须锁定实际未提交源码，不能只凭提交号复现。

## 1. 先回答什么

**先检验“最多三张是否帮助解题”，再讨论“是否应让更多卡参加 Q 学习”。不把提高 Q 覆盖率作为取消上限的充分理由。**

三个不同问题分别判断：

1. **实现正确性**：程序是否真的让最多三张/不限量的卡进入复析，是否存在其他位置的隐式截断？
2. **实用必要性**：在当前旧 CLE、卡库、模型和任务上，三张上限是否减少干扰、错误或成本，或者反而丢掉必要经验？
3. **数值合理性**：即使有限制有帮助，为什么恰好是三张？三张优于不限量，不等于证明三张优于一张、六张，更不等于数学上的必要条件。

本方案的核心实验只改变选卡数量策略；Q 不参与排序、不更新。先把这个问题单独测清楚，避免同时改变 Q、奖励、模型和卡片内容后无法解释结果。

## 2. 目前已经核实什么

### 2.1 三张上限在哪里

旧 CLE 的相关主链是：

`公开题目＋首次初析 → 向量 Top24 与词面 Top8 联集 → LLM 选卡 → 适用性复析 → 声明采用 → 规划/生成 → 原验证器`

LLM 是语言模型；复析是模型结合具体卡片重新检查适用性；Joint 是同一份交付代码的功能与安全测试同时通过。

| 位置 | 当前实际行为 | 本研究含义 |
|---|---|---|
| `methods/cle_ablation/runner.py::run_one` | 默认 `max_experiences=3`，传给 `retriever.search` | 限制交给复析的卡数，不是把整个库缩成三张 |
| `methods/sct_trajectory/semantic_retrieval.py::semantic_select` | 有限参数被 `min(limit, 3)` 截断；`None` 才进入不限量分支 | 直接传 `6` 仍最多三张；实验必须核对实际返回 |
| `methods/sct_trajectory/memory_q.py::rank_candidates` | 有限参数仍截到三张；`None` 返回完整排序 | 不能把配置中的 K=6 当成已经实现六张 |
| `semantic_retrieval.py::semantic_value_select` | 数值直接选卡分支也截到三张 | 此分支不是本研究的原 CLE LLM 选卡主线 |
| `context_pipeline.py::adopt_experiences` | 根据已检索卡与模型采用 ID 过滤，没有另一条固定三张规则 | 复析可以拒绝卡；给三张不等于用三张 |
| `memory_q.py::update_adopted` | 对实际采用的唯一 ID 逐个更新，无前三张截断 | Q 更新没有独立的“三张名额”；上游不给卡才会限制更新机会 |

原方法说明中也明确写了“最多选三张”，见 [现行方法说明](CLE_Method_Complete_Description_20260924_Final.md)第 5、6 节。**方法中规定了三张，不等于这些规定已获得数量消融的支持。** 本次查阅的相关报告尚未给出隔离其他变量后的三张/不限量同题对照。

“不限量”仍受候选联集、合法状态、语言、卡片长度和上下文预算约束，最多来自当次 32 张候选的去重子集。它不表示把 1939 张卡全部塞给模型。

## 3. 三种待区分的解释

| 假设 | 通俗解释 | 必须看到的证据 |
|---|---|---|
| H1：信息不足 | 第四张以后包含前三张没有的必要建议，上限造成漏用 | 尾部卡建议被采用、正确实现，并对应稳定救回；只声明采用不算 |
| H2：额外干扰 | 多卡重复、冲突、携带别题前提或过度约束，反而使模型写错 | 错误具体对应尾部建议；同题去掉尾部后错误减少；不能只看上下文变长 |
| H3：瓶颈在别处 | 卡数改变了，但模型仍因接口、模板、实现或解析问题失败 | 同一错误跨组出现；相同采用卡下结果波动；卡数不是当次差异的主要解释 |

这些假设可以同时出现在不同题上。目标是找适用条件和实际取舍，不强行给整个卡库一个统一故事。

## 4. 第一条验证线：冻结卡库，隔离数量对解题的影响

操作类别为 A（固定库开发评价），之前的历史整理属于 R（复用分析）。本线不需要重新训练模型、重新提炼卡片或更新 Q。

### 4.1 核心三组

同一题先得到两份选卡结果：原选择器在“最多三张”提示下的有序列表 C，以及在“不限量”提示下的有序列表 U。U 的顺序沿用模型给出的“实际有用程度”顺序，不另按 Q 或相似度重排。

| 组别 | 怎么选 | 实际送入复析 | 回答的问题 |
|---|---|---|---|
| C3：原 CLE 三张 | 原选择器明确最多三张 | C，全体 0–3 张 | 真实原策略基线 |
| U3：不限量选、前三张输入 | 不限量选择器得到 U | `U[:3]`，0–3 张 | 固定不限量选卡结果，只保留前部信息 |
| Uall：不限量选、全部输入 | 与 U3 共用同一份 U | U，全体已选卡 | 第四张及以后有没有增量价值/干扰 |

两个主要比较：

- **Uall−C3**：取消上限后整个选卡策略的实际效果。
- **Uall−U3**：在相同选择结果和前三张前缀下，加入尾部卡的效果。

C3−U3 是解释性比较，用于识别“限制选卡提示后模型挑了不同三张”的影响，不作为第三项主要提分检验。U3 也不是“最优三张”，只是固定 U 的前缀。如果 Uall 优于 U3，却不优于 C3，说明尾部卡补足了这个前缀，仍不能据此要求取消原策略的上限。

先不增加无记忆组、纯相似度组、学习 Q 组或打乱 Q 组：它们不直接区分三张上限的问题。也不强制凑满三张；零张和少于三张都是合法结果。

### 4.2 样本与预算

1. 以既有固定 48 题 D_gate 清单为开发来源，先对全部 48 题完成零 API 公开契约预检并登记结果。
2. 预检同时核对公开签名/默认值、返回形态、已有全局对象、模板占位符、参考实现及夹具一致性。参考实现通过，不等于公开契约已经完整。
3. 若能从项目原始公开材料核实缺失信息，另存统一 context 覆盖；三组共用，原始数据不改。不能把隐藏测试里的常量或未公开要求转写为题面。
4. 无法澄清的契约缺陷题不进入新因果比较，保留缺陷清单和全部旧成绩。按原 48 题清单顺序，从预检合格者取前 8 个不同 family；不得按历史/新成绩、选卡数量或 Q 变化挑题。少于 8 个则停止真实测试并报告原因。
5. 在新选卡、标签和成绩产生前锁定这 8 题及排除理由。它们有历史开发暴露，不能称独立最终测试。
6. 每题三组，各做两次下游生成重复：**8×3×2=48 次 P7**。前两题的 12 次包含在预算内，先验证工程链路。

两次重复用于观察相同输入下的生成波动；统计单位仍是 8 个题族，不是 16 个独立任务。每题首次 C、U 各选一次，两个生成重复复用已锁定列表；本批不估计选择器多次随机输出的稳定性。

### 4.3 冻结条件与执行过程

- 固定 1939 卡正文、状态和语言资格。可读现有冻结库，但所有组都不读 Q 选卡、不向提示提供 Q/visits、不产生 Q 更新。
- 首次初析、检索查询、向量/词面候选、余弦与候选呈现顺序共享；采用原联集顺序 `candidate_order=None`，不增加门槛或 Q 重排。
- 保留当前旧检索字段规则。本线不顺手修改已知 `return/raise` 检索白名单遗漏；该局限三组一致，另列为未处理检索问题。生成模型仍得到完整公开契约。
- 使用共同的已有对象保留提示，沿用等 K 实验中 `IMPLEMENTATION_CONSTRAINTS` 的内容，三组一致。因此是新协议，不能直接用旧 Q0 生成成绩充当 Uall。
- `deepseek-v3.2`、thinking disabled、temperature=0、max_tokens=4096；`text-embedding-3-large`。输出上限一致，输入 Token 因卡数自然变化，按实计量。
- U3/Uall 必须从同一个 U 构造，前三张顺序和正文一致；C3 使用相同候选。模型二次复析仍可拒绝或适配，不能要求它强行采用。
- 保留原 P7：首次 Joint 通过早停，否则最多一次修复，交付实际末次代码，不取事后最好版本。
- 修复轮根据各臂代码和原许可反馈重新检索，继续执行本臂数量规则。查询已不同，不强行复用另一臂的候选/U，也不把修复轮当新独立题。查询相同时才允许复用选卡结果。
- 配对三组在相近时间运行，按预先固定种子轮换组别顺序；不按中途成绩改顺序、调参、换题或重跑失败。

首次尝试是最干净的同查询机制比较；最终 P7 成绩衡量完整策略的实际效果，包含各组随后走向不同修复路径的影响。

### 4.4 成本口径

硬规模上限是 48 次 P7；每次最多两个代码版本，不包括额外试到成功的重跑。共享首次初析和 C/U 选择只计一次，修复轮新调用按各组记账，原生格式重试计入实际用量。

作为规模参照，旧 Q0 的 48 次 P7 使用约 370 万 LLM Token；新三组会共享部分调用、输入卡数和修复次数也会变化，这只是历史参照，不是价格或用量保证。按阶段和组别记录请求、输入/输出 Token、Embedding、缺失 usage 与错误；无账单不填实付金额。零 API 整理和人工复核不冒充模型调用成本。

### 4.5 记录什么

| 层次 | 必存内容 | 能避免什么误解 |
|---|---|---|
| 输入 | 题目、family、共同初析/候选、C 与 U | 组名不同却输入其实一样 |
| 数量 | 候选数、选择器选中数、实际注入数、采用数、正文长度和 Token | 把选入、采用、实现混为一谈 |
| 卡片 | 前三张和尾部 ID、顺序、适用条件、重复/冲突/额外前提 | 把“更多”自动当“更好” |
| 代码 | 首次/修复/末次代码、公开接口是否保持、建议对应的实现位置 | 把声明采用当落实 |
| 结果 | 首次 Joint、最终 F/S/Joint、修复救回/损失、流程错误与缺测 | 把任一代码通过冒充交付通过 |
| 成本 | 选择、复析、规划、生成、修复和向量调用分开计量 | 忽略多卡导致的真实输入成本 |

报告所有题，同时单列 `len(U)>3` 的“上限实际生效子集”。该子集由选卡结果确定，只作机制诊断；主结果仍包含锁定的全部 8 题。如果 U≤3，U3/Uall 的输入应完全相同；结果仍不同时，是生成波动的直接线索。

对主要比较的每一道救回、损失，以及尾部卡新增采用的题逐一审阅。把“声明采用”“Agent 检查实现”“人工确认适用性”分开存，不伪造人工金标准。

### 4.6 怎样解释检索指标

先区分候选召回（最初找到哪些卡）和最终选择（最后给模型哪些卡）。本线首轮候选相同，因此**不会凭数量策略改善首轮候选召回率**；最终选卡的精确率、候选池内召回率可能改变。

如要报告正式四指标，三组共用同一完整候选池的人工标签，direct 为正类、其余已裁决标签为负类；未完成人工确认时只能称模型辅助估计。复用标签前须核对题面与卡片完全一致，否则旧标签不直接迁移。

优先同时报告：选入卡中直接适用比例、是否至少命中一张适用卡、尾部新增覆盖的契约义务、冲突率和冗余卡数。不限量选入更多卡会改变 Precision/Recall 的取舍，F1 更高不自动说明代码更正确。全库召回率保持“未测量”。本批生成比较不依赖标签调参；人工未完成不伪装成整个生成实验无法报告。

## 5. 第二条验证线：三张上限与 Q 反馈质量

先做 R 类零 API 分析，不立刻重跑 273 题。

1. 复用不限量 D_grow 的实际采用与有效更新事件，按**进入复析的卡序**标明每张实际采用卡来自第 1–3 位还是第 4 位及以后。
2. 分别统计两部分的唯一卡、仅尾部才获得反馈的卡、访问次数、独立 family 数、正负反馈与公开契约/流程资格屏蔽。
3. 对“尾部新增 Q”的卡抽查本题是否适用和代码是否落实；重点核对多张卡因同一份代码失败一起扣分的情况。
4. 可在统计副本中删去尾部更新事件后重放数值，必须标成**固定旧轨迹的反馈敏感性分析**；它不是三张策略重新解题得到的 Q。因为真删卡会改变采用、代码、测试结果和修复路径，不能拿旧代码奖励直接模拟真实三张学习效果。

Q 仍按原公式 `Q_new=0.7×Q_old+0.3×r` 更新实际采用卡，Joint 通过 r=+1，否则 r=−1。多卡共享一个代码结果是现有归因方式，卡数越多可能覆盖更多卡，也可能把无贡献卡一同奖励/惩罚；这是待检验问题，不预先写成结论。

**本线不增加一个“最多给三张卡记分”的人为规则。** 若冻结实验表明数量确实影响解题，而且反馈分析表明覆盖/归因值得继续，下一份 T 类协议才进行从同一 M0、Q=0 出发的两套匹配 D_grow 学习。两套必须使用相同题目、顺序、上下文和奖励资格，只改变选卡数量策略，然后在相同推理策略下比较两份冻结 Q。不能把历史 297 卡与 466 卡的两次不同运行替代这项对照。

多轮学习属于另外的干预；本轮不把增加外层轮数混入三张上限研究，也不把 D_gate 反馈用于学习。

## 6. 推进门槛、停止与结论用语

### 6.1 工程门

先完成前两题的 12 次预算内探针，确认 C3/U3≤3、Uall 无三张截断、共同候选和共享 U 正确、原 P7 验证/交付规则不变、Q 未写入、成本可读取。回调实现错误、候选复用错误或验证环境故障时暂停后续付费调用，修复后另记协议修订，不覆盖失败。

模型原生解析/规划降级照常保留、单列，本批不为拿到干净结果反复重跑。若关键救回只发生在流程异常或契约缺陷上，不把它作为卡数的作用证据。

### 6.2 8 题开发后的判定

设每题两次最终 Joint 的均值为该题得分。例如两次通过/失败分别记 1/0，两次一过一败则该题为 0.5；两组差在题族层面计算。

| 现象 | 处理 |
|---|---|
| Uall 在不足 4/8 题首次选入>3 | 数量干预不足；结束本批，不扩大样本凑差异，不判断三张普遍必要/无用 |
| Uall 相对 C3 和 U3 均净多至少 2/16 次最终 Joint、F 均不下降；至少一题两次均救回；有尾部卡实际落实的对应路径 | 有取消上限的开发信号，可提出扩展验证；阈值是工程推进线，不是显著性结论 |
| C3 相对 Uall 满足反向同等级稳定改善，且有尾部冲突/错适配的对应路径 | 有保留上限的开发信号，可提出扩展验证；还未证明三这个数最优 |
| Joint 没有稳定优势，但 C3 总 LLM Token 比 Uall 少至少 20% | 三张可作为节省成本的暂用默认；不能声称已证明准确率不受损 |
| 改了卡数/采用，但分数差主要来自接口缺失、共有卡不同实现或不稳定生成 | 记录“数量机制已介入，正确率作用未建立”，定位具体瓶颈后收口 |
| 核心链正确，但正反变化混杂或只有点估计差 | 记录“证据不足”，不为了证明必要性自动扩大 |

采用与实现证据应能说明具体建议和差异，不能用“新增卡被采用”这个计数代替。尾部卡还可能改变模型分析而未被声明采用；这类结果可记为上下文影响线索，不能冒充已核实的采用链。

### 6.3 统计与“正确”的标准

两项主要比较报告题族配对差、救回/损失、首次/最终 F/S/Joint 和 95% 配对重采样区间；以 8 个题族为单位，对两次重复先取均值，再做精确符号翻转检验，两项比较作 Holm 校正。不能把同一题的两次重复当独立题，也不能把低样本不显著解释为等效。

要写“三张在当前条件下更好”，须有正向效果、区间/检验支持和相应作用路径；要写“三张省钱且基本不损害正确率”，须另行预注册非劣效界值，例如最多允许损失 5 个百分点，并让 C3−Uall 的置信区间下界高于 −5 个百分点。**8 题通常不足以完成这种判断；没有达到就保留不确定，不偷换成“没有显著差异所以三张正确”。**

若开发信号清晰，可以再提交扩展方案，默认从同一 48 题来源预检合格、未参与本批调参的后续题族取 16 题，仅做已锁定的两种完整策略、各重复两次，即最多另加 64 次 P7；两个策略须分别说明选择和截断规则。本批 48 次加扩展最多 112 次。扩展名单和比较在新结果前锁定，且仍披露历史 CLE 暴露，不包装成独立最终测试。**本方案不自动启动扩展、全量学习或 Base/Plus。**

### 6.4 如果还要证明“为什么恰好三张”

核心三组只能比较既定策略和尾部信息。后续若确有必要，在共同 U 上增加一个中间点：

- Uall 明确更好：优先试 `U[:6]`，判断是否用六张就能保留收益和节省成本。
- C3 不差且成本更低：可以试 `U[:1]`，判断是否三张本身仍偏多。

新增点必须连同 U3 等既定对照，在新锁定任务上同批执行；不能只补跑一个点再拼旧成绩宣称最优。有限点比较仍只能说明本数据、模型、卡库下的取舍，不证明全局最优。实现六张时使用显式前缀回调，不直接传会被硬截成三张的 `limit=6`。
