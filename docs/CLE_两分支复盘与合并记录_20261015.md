## 2. 为什么仍缺原始pools和完整参数

检查覆盖两条源提交的完整文件树、新增路径、材料包、35个历史记录的JSON结构、导出脚本，以及对应PR正文中的附件链接。结果如下：

| 需要的对象 | 实际收到的对象 | 判定 |
|---|---|---|
| 原运行的完整`pools.json`逐题清单 | 历史summary中的source/replay/audit数量；303题来源索引 | 只有数量及来源子集，不能当作874题原始分池文件 |
| CLE原运行完整无密钥参数 | 24份run_metadata中的model、dataset、git_commit、时间和schema等摘要 | 24份均无args；不是完整参数 |
| 1939卡实际运行的原始元数据 | `source_materials.md`中的路径、数据哈希和部分paired273配置说明 | 可关联来源，但说明文本不等于原始run_metadata文件 |
| 30查询小实验配置 | `model_benchmark/preregistered.json`及配套结果 | 是该小实验的配置，不能替代CLE训练参数 |

缺失原因可以直接从分支源码定位：

- [导出文件白名单](https://github.com/smallrabbit490/sct-security-generation/blob/a6164b2fa833438ce5e395584f90fb194ea8d018/tools/export_cle_dashboard_history.py#L18)只有7类摘要文件，不含`pools.json`。
- [redact的字段过滤](https://github.com/smallrabbit490/sct-security-generation/blob/a6164b2fa833438ce5e395584f90fb194ea8d018/tools/export_cle_dashboard_history.py#L64)明确跳过`args`；它在源端导出时已被删除，不是本地解析遗漏。
- [列表裁剪](https://github.com/smallrabbit490/sct-security-generation/blob/a6164b2fa833438ce5e395584f90fb194ea8d018/tools/export_cle_dashboard_history.py#L69)只保留前100项，所以这类摘要即使出现长任务列表，也不能直接当作完整原件。

原运行的`output_schema`中出现字符串`pools.json`，仅表示预期输出文件名，不表示该文件已经随分支提交。当前35个运行目录中24个有元数据快照，不能写成“35份完整运行参数”。
