# 一道来源题精修的经验卡，能提高其他采用同一卡题目的 Joint 吗？

## 这次检验什么？

按用户11月3日授权，对5张卡逐卡处理：每张只用1道来源题形成精修版本，再在10道其他历史采用题上比较原卡和精修卡。50道留出题来自50个不同登记题族，全部排除5道来源题的题族。每个条件运行两次，最多修复一次，留出比较共200个代码单元。来源题另做20个单元，单独报告；来源题的新成绩不用于挑选版本或取消留出测试。

这次只回答卡片内容改动能否迁移。原卡由API提出修改、API作一次来源复核，再由Agent核对来源证据后冻结；这是有人审核的精修过程。自动修改提炼规则并稳定复现收益，属于后续独立问题，本批不派发。

## 精修具体改什么？

1. 每张卡只展示自身原文及一道来源题的公开题面、已有代码、分析、计划和允许反馈。精修模型不接触留出题代码、答案或成绩。
2. 只修正文中有依据的错误前提，保留正确操作、必要校验和合法行为；不按CWE整段换成同一份通用提醒，不填入来源题的函数名、测试常量或隐藏接口。
3. M1纠正重复占位符必须更换`str.replace`的错误解释；M2限定撤除网络检查的条件；M4限定角色配方并保留公开提供的允许名单；M5撤回无依据的固定数值示例。
4. M3没有找到来源证据支持的必要改动，保留原文并标为“无干预”。其同一重复的两个等同条件精确复用一次结果；两个重复各自独立。不会为凑满5个改动而修改正确建议。
5. 所有版本在任何新来源题和留出题成绩产生前冻结。每张来源题的初稿、复核稿、最终逐句补丁及审核理由全部保留。

## 原生CLE怎样接入？

固定每题原来检索得到的三卡组合及顺序，只替换其中被研究的一张卡。使用原生P7的复析、采用、规划、生成和至多一次修复；允许本轮模型重新采用或拒绝该卡，结果照实计入。其余卡不改，不更新Q或永久卡库，不调用Embedding。两条件共享同题同重复的首次初析，随后独立生成与修复；重复之间不共享一次返回。

模型为`deepseek-v4.1-flash`，thinking disabled、temperature 0、4096输出Token、单user消息、4 worker。验证器及任务夹具保持原样。旧成功返回只有在同模型、同提示、同重复和流程逐步一致时才复用；本批零API预检确认18份初析可复用，完整原卡代码单元可复用0份。

## 过什么门槛，可以说明什么？

|观察|预先固定的判断|
|---|---|
|来源题改善，其他题不改善|改动只在开发材料成立，尚无跨题迁移收益。|
|单卡有迁移信号|该卡20次留出比较净救回至少2次，救回分布于至少2个题族，两个重复的净增均不为负。M3等同条件不计作精修成功。|
|整体值得进入提炼规则验证|100个留出配对净救回至少5次，至少3张卡净增为正，精修组安全通过数不低于原卡。|
|门槛未过|结束本版精修扩样，保留具体收益与损失；不自动提炼或追加全量。|

同时报告功能、安全、Joint、首次与最终通过、配对救回及损失、每次重复波动、实际采用和代码落实。按题族计算区间与符号置换，逐卡五项探索采用Holm校正；工程门槛和统计检验分别报告。所有差异题回看实际题面、卡、计划、代码及验证，区分建议未采用、实施变化及其他随机生成变化，不凭Joint字段直接归因。

## 预算和执行顺序

结构上限为1660次物理请求、累计3000万Token；费用按真实返回累计，失败和未知用量占用原预算，不重置。构成为10次精修及复核、至多110份初析、220单元各至多7次原生P7请求。正确卡等同条件及18份已存初析的精确复用进一步减少实付。按此前同模型批次用量，主比较约需425万Token，具体以本批账本为准；没有核实货币单价，预算以请求与Token上限约束。

顺序为：来源精修及审核 → 零API冻结和复用检查 → 20个来源单元 → 200个留出单元 → 零API原生回放 → 配对统计 → 差异代码解读。低成绩不取消固定单元。只有核实为同类网络断流、无完整返回时，才先零API重放成功前缀、确认缺失边界，再在新段接续；认证、额度、解析或落盘错误不按网络重发。保留旧失败和未知费用。
