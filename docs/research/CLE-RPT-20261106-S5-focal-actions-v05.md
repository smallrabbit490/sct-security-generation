# 50例经验卡作用核对发现了哪些可修正错误？

**50例焦点动作已经逐一核对，19道已定位并复现的原失败题各有最小代码变体恢复Joint；10道原通过题接受纠错后均保持原Joint。** 最集中的问题是宿主配置被生成代码覆盖：11份相关代码中，10份原失败仅撤销顶层赋值就恢复Joint，另一份原通过代码恢复了合法字段的处理。它们分布在6个公开接口近邻组。

这些结果来自旧代码的零API诊断。原卡、移除焦点卡、只删除焦点动作的300个新生成单元已冻结，尚未运行；卡片是否诱发动作及新提炼方式的收益由该输入对照测量。

## 1. 本次完整检查了什么？

50例对应50个原推断题族ID、29个公开接口近邻组，其中D_grow和D_gate各25题。40例来自历史1017模型，10例来自不带1017的Flash。逐例阅读公开题面、全部144份实际可见卡片视图、复析、采用记录、计划、首次代码和已有验证证据，保存287项本地或模拟行为观测。其中67项与各自标明的公开要求、计划承诺或合成接口预期不符。多项观测来自同一道题，不能把287项当成独立题数。

1. 对照卡片原句，明确要检验的具体动作及其全部指令位置。
2. 查清公开题面和其他卡是否重复要求同一动作。
3. 分别记录正式采用、复析适配、计划承诺和代码实现。
4. 复现原成绩，并用标明依据的合成输入检查行为。
5. 对定位到的错误做最小代码改动，用原验证器回放，同时检查行为救回与损失。
6. 固定三路新输入、两次独立重复及留出排除，等待新批预算和完整运行器就绪。

46份原代码复现了已有原生结果。1409的夹具写绝对路径文件，1092会实际发HTTP，1105和1124会实际解析DNS，这4例保留旧原生记录，本轮只运行本地模拟。后三题也是本批未做原验证器最小修复回放的3道原失败题，未计入19道救回。

## 3. 救回和损失怎样统计？

|范围|数量|结果|
|---|---:|---|
|实际原代码诊断|31道旧题|19道原失败、12道原通过|
|纠错变体|35份|19道原失败各有至少一个变体恢复Joint；10道原通过接受纠错后无原Joint损失|
|不利方向反例|2份|验签前取回、限制新增成员必须预先注册均损坏对应行为，原Joint仍通过|
|全部代码变体|37份|全部使用原验证器测量；同题多变体不重复累计救回|
|新卡片输入因果对照|0／300|尚未生成，不计算新方法Joint差值|

163的前两份纠错变体修复了合法模板，却暴露原先被字段层级错误遮蔽的畸形模板放行；第三份补丁只检查原模板残留花括号，使7项登记行为全部匹配。中间变体及其行为损失完整保留，未因最终修复而删除。其他旧诊断中的残留问题同样保留在逐变体结果中。

宿主配置覆盖是这组旧失败中最直接、跨接口可重复定位的问题；采用标记、计划描述、代码落实和原测试Joint仍是四层不同证据。两个不利反例说明，原Joint通过也可能遗漏调用顺序或合法输入处理。

## 4. 现在能得出什么结论？

第一，正确的匹配或权限动作已经写进代码，仍会因宿主配置被覆盖而失败。只提醒“不修改对象内容”不够，还要核对代码是否把同名变量重新绑定到示例值。这一代码级机制在6个近邻组中得到实际回放支持。

第二，模型会拒绝卡片中的一部分指示，同时保留另一部分；采用了卡，也会在接口、对象层级、URL组件和替换顺序上偏离计划。因此应按具体动作归因，不能用整卡采用标记直接解释Joint。

第三，19道救回证明这些局部代码错误可修正。卡片删改是否使生成模型稳定避免错误，需要已冻结的三路新生成结果。现有代码诊断不替代该实验，不改写已冻结的S3／S4方法规则。

## 5. 接下来怎样接续？

来源、M50、H50三组各50题按用户批准的18／19／19近邻方案冻结，组间题目、原推断题族ID和近邻交叉均为0。统计按真实近邻组聚类。

S5这50例与正式H50也无题目、题族或近邻交叉。公开题面、实际卡文、焦点动作和三路材料已经冻结为300个唯一单元；两次重复分别使用新初析，共100份独立初析，组内三路共享同一初析。E0原卡，E1移除焦点卡，E2只删除焦点卡中指定动作，其他卡与顺序保持；各组只做首次生成，不修复、不再次检索、不更新卡或Q。
