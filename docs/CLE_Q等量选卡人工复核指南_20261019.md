# 本轮222个题卡对：人工复核怎么做

本轮评价的是“这张经验卡能否按公开题目直接使用”。不是判断这张卡能否独自解完整道题，也不是看最终代码通过没通过。

运行区：`translation_work/diagnostics/20261019/cle_memory_q/equal_k_v1/`。AI初标完成后生成`human_review.csv`；请另存一份副本进行审定，原表保留。表里不显示组别、Q值、排名或历史成绩，避免知道结果后倾向给某组好评。

## 每一行的操作

1. 阅读`task`里的题目、输入、返回和公开上下文。明确允许什么、禁止什么、哪些依赖已由调用方提供。
2. 阅读`card`完整正文，包括适用条件、排除条件、修法和禁忌；不能只看卡的标题或CWE类别。
3. 查看`ai_label`与`ai_reason`，把它当待核对建议。AI可能误解题目、卡片或额外前提。
4. 在`human_label`填下表中的一种；在`task_evidence`、`card_evidence`摘出对应依据，在`reason`用自己的话解释。
5. 真实填写`reviewer`和`confirmed_at`。Agent不会代填这两列。存在争议可以暂填`insufficient`，但正式指标需将争议裁决后才能导入。

| 标签 | 简单判断 | 常见误判 |
|---|---|---|
| direct | 卡的核心做法技术正确，在题目已给条件下就能用 | 不要求一张卡覆盖整道题所有安全义务 |
| conditional | 还需要题目没保证的前提，或必须实质改变卡的核心做法 | 变量改名、必要的普通接口适配通常不属于实质改变 |
| irrelevant | 处理的是别的问题，不能帮助当前机制 | 不能因同CWE或都有“校验”就判相关 |
| conflict | 卡有技术错误，或其做法违反题目明确要求 | 要指出具体冲突，不凭“感觉太复杂”判断 |
| insufficient | 信息不足，无法判断 | 不默认算负类，不为凑指标强选标签 |

例如：题目要求使用已有`BLOG_FORMAT`。如果卡建议HTML转义，且适用条件一致，它可以是direct；它没负责模板的所有细节，不自动成为conditional。如果卡要求替换题目已有模板、造成公开接口变化，则要具体检查是否conflict。不要仅因某次模型重定义了模板，就反推所有相关卡都有错。

例如：正则卡建议限制最大输入长度，而题目并未保证长度上限。要检查卡是否把新增长度限制作为必要做法，以及是否会拒绝题面允许的输入；仅仅同属正则安全不能直接确认direct。
