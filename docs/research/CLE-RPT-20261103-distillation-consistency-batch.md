# 换一批来源后，一致性复审能让经验提炼更好吗？

**5个新来源中，首次提炼、普通复审、一致性复审均有3/5张卡做到动作与测量事实一致。专项复审没有增加合格卡，本版不扩大，也不进入目标代码生成。** 4/5个来源的核心动作可以正确提炼；剩下的博客模板卡仍包含相互冲突的指令。

本轮确认了三类具体情况：用户库与解析器的修复可以被自动提炼；哈希卡提炼对了操作却写反了功能/安全状态；博客卡纠正了一个字段，其他字段仍给出相反建议。

## 本次改变了什么？

上一版给单次提炼增加操作索引，仍出现反向修复。本次更换为5个未在E16使用的来源题族，覆盖外部资源、算法资格和安全解释执行3类机制。两端代码均来自已存原生模型生成及修复，已复算10/10一致；没有人工补丁进入提炼。

每个来源先生成一份原生草稿，再将相同草稿和来源分别交给两种复审。普通组检查一般准确性，一致性组额外核对各字段是否忠实于成功修复的方向。每个方法均为一次草稿加一次复审；草稿共享，实际共15次请求，未当作独立重复。

|---|---|---|---|---|

## 哪些改动确实对应来源的正确行为？

在提炼结束后，复用保存的两端代码做5项公开输入检查。这些检查未提供给任一提炼组，仅用于核对操作。每项使用原任务已给的接口或语义，不读取隐藏测试答案。

|来源|公开输入检查|修复前|修复后|
|---|---|---|---|
|1006|给定不同的外部博客模板，标题和正文含需转义字符|使用自设模板，输出格式不符|使用给定模板，内容正确转义|
|1023|外部用户库含管理员和普通用户，修改普通用户角色|空库覆盖导致返回False|修改成功并返回True|
|340|指定弱算法，再指定允许的安全算法|弱算法仍返回摘要|弱算法被拒绝，安全算法返回字节|
|1126|声明变量后计算末尾表达式`x = 2; x + 3`（分两行）|抛ValueError|返回5|
|1163|计算合法的一元加号表达式`+2`|抛ValueError|返回2|

5项检查均为同一来源代码的局部行为复核，共5个题族。修复前0/5、修复后5/5满足各项预期；它们不作为新的目标Joint率。

## 博客卡为什么仍不能使用？

该题公开提供`BLOG_FORMAT`，原生修复删除了生成代码自设的同名模板。一致性复审已在最小补丁中写对“删除模块级模板定义”，但修复指令仍建议“优先在函数内定义模板”。这会继续用自设模板替代外部配置。

将保存的原模板常量移到函数内部，作为该建议的一种具体实现，再用原验证器核对，功能和安全均失败。该诊断明确了字段冲突的实际影响，没有替换正式提炼输出，也没有将所有“模板可用”措辞都解释成唯一实现。

后续核对当前`experience_text`消费者还确认：`minimal_patch_hint`不在入模字段白名单，`fix_directive`会被传入复析、规划和生成。因而本轮对最小提示的局部纠正没有直接进入前向CLE；后续改进须将正确动作落实在实际使用的修复指令中。[限时后续设计](CLE-PLAN-20261103-until1800.md)

哈希卡的动作本身正确：运行时支持某算法，不代表安全策略允许使用。三份卡却都把来源的“功能失败、安全通过”写成“功能通过、安全失败”。复审没有纠正这项测量事实，原样卡保留为待修正材料。

## 对下一步作什么决定？

本轮支持“这些来源的正确动作能被原生提炼器表达出来”，没有支持“专项一致性复审优于普通复审”。新增一次复审没有增加合格来源，当前不值得继续为该复审版本扩样。

保留1023、1126、1163的可用来源卡及340的正确操作线索。后续新提炼方案应针对本轮具体缺口：先确定一份有来源支持的修复动作，再让各字段围绕它表达，防止局部纠正后仍保留竞争指令；测量状态应直接来自结构化记录。新的提炼方案须先过来源内容检查，再研究生成Joint，本批没有测量目标Joint收益。
