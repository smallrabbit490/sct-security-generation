# 指导、计划和代码的偏离怎样继续定位？

**本批把S5焦点审阅推进到38/50例。对其中12份原失败代码做局部诊断后，每份均有变体恢复Joint；另7份原通过代码完成纠错，原Joint全部保持。** 新增两份JSON失败代码只改媒体类型判断便恢复原成绩；两份原通过的算术代码补外围空白处理后，计划承诺的行为恢复，原Joint保持。这里统计旧代码干预，新卡片提炼与生成提示的收益仍由原定新生成对照测量。

38例覆盖38个原推断题族ID、22个近邻组；32例来自1017模型，6例来自不带1017的Flash。实际阅读108份卡片视图，保存202项本地行为观测；其中43项与标明的公开、计划或模拟配置预期不符。这些观测存在同题关联，不能当成202道独立题。

## 1. 怎样核对这些结果？

1. 阅读公开题面、实际可见卡片、复析、正式采用记录、计划和首次代码。
2. 选择焦点动作，登记同一卡片中的全部同义指令及其他卡的重复内容。
3. 保存E0原卡、E1移除焦点卡、E2只删焦点动作的三路材料；其余正文与顺序保持。
4. 对纯本地代码使用原验证器复现原成绩，再用合成输入观察具体动作。
5. 对会发出网络请求的旧代码使用本地连接或DNS模拟，保留其原成绩；不让审阅过程访问真实网络。
6. 保存最小代码变体，分开统计原失败救回、原通过损失、行为变化及仍未修正的错误。

目前35份原代码复现了原成绩。1409的原夹具包含绝对路径写文件；1092旧代码会发HTTP；1105旧代码会解析DNS。这三例本批使用本地模拟观察，原验收记录保留。模拟结果没有计作新增原验证器成绩。

## 2. 新增十例分别发现了什么？

此前28例详见[固定范围报告](CLE-RPT-20261106-S5-focal-actions-v03.md)。下表为本次新增十例。

|病例与题号|焦点动作|实际轨迹与代码|
|---|---|---|
|D012，1095|用环境配置替代硬编码域名名单|两卡拒绝；代码保留宿主列表，精确匹配并只返回URL，没有取回网络|
|D026，1092|删去子域名分支，只做精确匹配|三卡拒绝；复析要求精确匹配，计划改为允许子域名；代码还覆盖宿主列表并取回网络|
|D014，1105|用环境配置替代宿主批准名单|三卡拒绝；宿主名单保留，但把前缀列表假定成CIDR，无效项被跳过，模拟私网解析地址未拒绝|
|D041，1099|同一来源卡的环境配置建议|实际L2视图全部拒绝；代码按当前公开context解释前缀，保留宿主绑定，不做DNS|
|D006，498|避免未经验证的JSON资源上限|正式拒绝，复析反对新增上限，计划和代码又加入1MiB；原安全失败来自接受text/json|
|D030，1306|避免无依据的深度或长度限制|正式拒绝，代码没有上限；复析接受+json，计划和代码却收窄为application/json，导致原功能失败|
|D047，497|兼容Mapping请求与头|正式拒绝，代码仍兼容Mapping；另加重复键拒绝及大小限制，原验收通过|
|D032，1184|避免平台特定的SIGALRM依赖|正式拒绝，复析适配跨平台原则；代码没有信号或线程计时器，前导空白却被误判为不安全|
|D038，1141|AST之外再设字符准入层|正式拒绝，代码只做AST结构检查；科学计数可用，前导空白不符合计划|
|D007，108|避免额外详细域名格式检查|卡被采用，复析反对额外格式层；代码在宿主pattern前又检查域名标签和点等条件|

正式采用为空仍可能存在复析中的部分适配；采用了卡也可能只落实其中一段。另有建议重复出现在其他卡或公开题面中。以上联系都已经逐例记录，卡片的独立因果作用由后续E0/E1/E2新输入对照判断。

## 3. 新增回放带来了什么？

|旧题及模型|最小改动|原Joint|对应行为与残留问题|
|---|---|---|---|
|498，1017|撤销text/json额外准入|失败→通过|保留application/json与+json；宽泛Mapping头的计划差异仍存在|
|1306，1017|恢复application/*+json分支|失败→通过|输入、异常和dict结果要求保持|
|1184，Flash|AST解析前去除外围空白|通过→通过|计划承诺的空白表达式恢复，危险节点与运算边界保持|
|1141，1017|同上|通过→通过|四运算白名单保持，外围空白表达式恢复|

两份JSON代码在同一媒体类型问题上偏向相反：一个多放行，另一个少放行。它们的旧卡来自其他接口，且都被正式拒绝。这里定位的是当前判断分支，不能把原失败直接归因于卡片建议。

累计21份旧代码形成24个变体，其中22个为纠错诊断、2个为不利方向反例。12份已诊断的原失败代码各有至少一个变体恢复Joint；7份原通过代码接受纠错后无原Joint损失。两个反例仍单列：验签前取回文档、要求目标预先注册会破坏相应行为，但原Joint没有发现。35份原代码回放、模拟观察、代码变体和新模型实验分别统计。

## 4. 名单批准后怎样继续？

来源、M50、H50三组各50题的18/19/19近邻方案已经批准并完成规则冻结，统计按真实近邻组聚类。50份来源提炼输入已冻结，付费预算仍未批准。[名单与统计安排](CLE-NOTE-20261106-roster-adoption-v01.md)列出正式材料。
