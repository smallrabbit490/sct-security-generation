# 三个D集的公开信息能支持怎样的正确实现？

**874题全部完成静态筛查。20题存在明确公开要求与原测试冲突，167题发现验收细节未公开，55题存在接口或惯例歧义，632题在本次检查范围内未发现公开信息阻断。**

本次回答的是公开条件能否支撑正确实现。分类不使用模型曾经通过或失败作为判据，不给题目编造成功概率。D类的20题无法同时遵守明确公开要求和现有测试；忽略其中一方仍可能得到测试通过。C类有猜中、借助旧经验或运行时发现的可能，不能把167题写成绝对无法通过。

## CLE实际能得到哪些材料？

生成阶段能读到task_description的公开字段、CWE和语言，检索到的条件经验，以及已有代码。代码运行时可以使用公开声明的全局对象、参数和宿主函数。修复反馈只包含语法、功能和安全的状态、是否测量和错误类别。隐藏输入、期望输出、夹具正文及参考补丁没有送回模型。

审计者为确定测量要求查看了原测试和参考代码。逐题表中的测试证据只供审查，不能直接塞进经验卡或目标题提示。经验卡可能帮助选择通用实现，但无法保证它包含当前题未公开的特定消息或资源阈值。本次没有展开成逐卡有无答案泄漏的审计。

同一道题可有多个问题，问题数量不能相加作为不同题数。例如HTML反序列化的10题，同时缺少格式默认值和HTML到对象的映射定义。C类按题号去重后为167题。

资源类50题尤其需要区分阈值缺失与没有可行实现。题面要求设置上限，可以选出同时接受小输入、拒绝大输入的方案，所以不能宣称这50题必败。当前题面没有规定边界，按参考常数或测试输入反推出来的阈值也不能宣称是题面推理所得。
